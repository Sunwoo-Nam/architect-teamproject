# 01. TC 스키마 — 복합 의제 협상 방식 PoC

> 본 문서는 `scenarios/*.yaml`의 스키마 정본이다. TC는 **구조**(축·의존성·충돌 성격·판정 기준)만 정의하고,
> 크기(축별 값 수·축 수)와 주입(오류·강제 중단)은 실행 계획(하니스)이 파라미터로 적용한다 — QA별 전용 TC를 만들지 않기 위한 원칙.
> QA 기준: [`docs/changbae/23-핵심-QA-최종-확정.md`](../../docs/changbae/23-핵심-QA-최종-확정.md) (측정 정의는 23이 위임한 21).

## 스키마

```yaml
meta:
  id: S01                      # TC 식별자
  name: 기준 — 2인 영화+저녁
  conflict_level: mid          # low / mid / high / extreme — 라벨 (validator가 실측 확인)
  conflict_rho: 0.0            # 정답 ufun 상관 목표 (low +0.7 / mid 0.0 / high -0.7)
  expected: agreement          # agreement | no_agreement (S08: 정상 결렬이 정답)

axes:                          # 순서 있는 목록. 값은 나열이 아니라 생성기 + 개수 (c 스윕은 count만 조절)
  - {name: date,   generator: date_slots,  base_count: 7}
  - {name: time,   generator: time_slots,  base_count: 6}
  - {name: region, generator: regions,     base_count: 5}
  - {name: movie,  generator: movies,      base_count: 8}

dependencies:                  # 축 간 의존성 (프리픽스 안전 — S11처럼 축을 잘라 쓸 때 범위 밖 규칙은 비활성)
  - {type: hard, rule: availability, subject: movie, over: region, coverage: 0.75}
      # 상영표형: subject 값별로 over 값의 일부만 허용 (시드 결정론 생성)
  - {type: hard, rule: availability_explicit, subject: movie, subject_value: mv6,
     allowed: {date: [fri, sat], time: ["21:00"]}}
      # 명시형: 특정 값의 허용 조합을 직접 지정 (S06 역방향 의존)
  - {type: hard, rule: membership, subject: restaurant, region_axis: region}
      # 소속형: subject 값의 region 속성이 region 축 값과 일치해야 함
  - {type: soft, rule: conditional_home, if_axis: time, if_values: ["21:00"],
     then_axis: region, penalty: 0.3}
      # 조건 선호형(soft): 조건 성립 시 then_axis가 참여자 home_region이 아니면 감점
  - {type: soft, rule: conditional_pref, if_axis: budget, if_values: [low],
     then_axis: menu, preferred: [korean, chinese], penalty: 0.15}
  - {type: soft, rule: same_region, a: region, b: cafe, penalty: 0.15}
      # b 값의 region 속성이 a 축 값과 다르면 감점

participants:
  count: 2                     # 본 PoC는 2인 고정 (참여자 확장 b는 dp2-nparty 소관)
  profile_seed: 1201           # 정답 프로파일 결정론 생성 시드 (validator 통과값으로 고정)
  styles: [default, default]   # default | focused(가중치 집중) | indifferent(약한 선호)
  constraints:                 # 참여자별 하드 제약 (TC 본질이라 시드와 무관하게 고정)
    - {participant: 0, axis: date, values: [sat]}                     # 값 이름 나열형
    - {participant: 0, axis: date, attr_equals: {weekend: true}}      # 속성 기반형 — count 확대에도 의도 유지 (예: 주말 = sat, sun, sat2, sun2 …)
    - {participant: 1, pairs: {axes: [date, time], values: [[sat, "17:00"], [sun, "19:00"]]}}

agent_view:                    # 에이전트에 주는 부분 정보의 파생 규칙 (21.3-1 순환 판정 차단)
  weights: quantized3          # 가중치 3단계 양자화
  score_dropout: 0.3           # 값 점수의 30%를 중립(0.5)으로 마스킹
  constraints: pass_hard       # 하드 제약은 그대로 전달

judge:                         # FC 판정 기준 (이 TC의 "정답" 정의 — 판정기 전용)
  floor_quantile: [0.7, 0.7]   # 수용선 = 자기 정답 효용 분포의 분위수 (상위 30% 안이면 수정 불요)
  expected: agreement
```

## 판정 규칙 (judge)

"수정 불요" = 다음 셋을 모두 만족:
1. **의도 부합** — 유효한 완성 합의(모든 축 값·하드 제약 통과). `expected: no_agreement`인 TC는 정상 결렬이 정답이며, 억지 합의는 실패로 집계한다.
2. **제약 충족** — 정답 프로파일의 하드 제약 100%.
3. **선호 수용선** — 정답 ufun 효용 ≥ 자기 분포의 `floor_quantile` 분위수(기본 0.7 = 상위 30%).

정답 프로파일은 판정기(oracle/judge)만 읽는다. 에이전트는 `agent_view` 파생 정보만 받는다.

## 봉인·검증

- `scripts/validate_scenarios.py`: 전 TC에 대해 (a) 로드·결정론, (b) oracle(기본 크기 전수)로 합의 가능해 존재(S08은 부재),
  (c) 충돌 라벨 vs 실측 상관 일치, (d) Pareto frontier 크기 보고. 실패 시 시드 교체 후 재검증.
- 통과한 `profile_seed`만 yaml에 고정 커밋한다.
