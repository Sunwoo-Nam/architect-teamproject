# 벤치마크 셋 자리 — 별도 담당자 작업 예정

이 폴더에 utility function·벤치마크 케이스 데이터가 들어온다.

## 케이스 규격 (제안 — 담당자와 협의해 확정)

케이스 1건에 필요한 것 (`src/dp2_nparty/benchmark.py`의 `BenchmarkCase` 대응):

- `case_id` — 케이스 식별자
- `candidates` — 후보 목록 (예: 시간 슬롯, 또는 K×L×M×P 조합)
- 참여자별 프로파일:
  - `utilities` — 후보별 utility (0-1)
  - `initial_threshold` — 수락 바닥선 (0-1)
- `meta` (선택) — 난이도 표기, **정답이 결렬인지**(전원 threshold 이상 후보 없음) 여부 등

## 표본 구성 요구 (측정 정의에서 오는 것)

- [24 §24.5] "정답이 결렬인" 케이스를 일정 비율 포함할 것
- [25 §25.5] 참여자 수 스윕용: 공통 feasible 후보 k개를 N과 무관하게 고정하는
  **역방향 샘플링** 케이스 (난이도 교락 통제)
- [21 §21.3-5] 의제 수 스윕용: 조합 수를 로그 등간격 6단계로 키운 케이스

포맷(JSON/CSV 등)은 자유 — 확정되면 `benchmark.py`의 로더를 함께 구현한다.
