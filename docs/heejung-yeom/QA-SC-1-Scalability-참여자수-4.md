# QA-SC-1 — Scalability (참여자 수)

> **지위**: 다자간 협상 구조 결정([`31 제안 토폴로지`](31-제안-토폴로지.md) / [`DP-02`](DP-02-negmas-nparty.md))의 **유일 판별 축**
> **ISO/IEC 25010:2023 매핑**: Flexibility > Scalability
> **관련 축과의 경계**: 절대 시간은 QA-TB-1, 절대 메모리는 QA-RU-1, 의제 조합 확장은 QA-SC-2 소관 — 본 축은 **참여자 수에 대한 증가 추세**만 판정한다

---

## 1. 품질 속성 정의

협상 세션의 참여자 수 N이 증가할 때, 합의 도달에 드는 **시간·메시지·단말별 부하**의 증가가 N에 대해 선형을 초과하지 않고, 동시에 **합의 완결 품질이 저하되지 않는** 정도.

| 구분 | 내용 |
|---|---|
| **포함** | 시간 증가 추세 · 메시지 증가 추세 · 부하 분포의 편중 추세 · 완결률 불변성 |
| **제외** | 절대 시간 상한(QA-TB-1) · 절대 메모리 수준(QA-RU-1) · 의제 조합 확장(QA-SC-2) |

**"완결 품질 저하 없음"을 정의에 넣은 이유**: 이것이 없으면 *N이 커질수록 빨리 실패해서 시간 지수가 좋아지는* 역설이 성립한다. 상세는 §4.1.

---

## 2. SQuaRE 표준 매핑 — 한계 명시

| 계층 | 매핑 |
|---|---|
| ISO/IEC 25010:2023 | **Flexibility > Scalability** |
| ISO/IEC 25023:2016 | **직접 대응 measure 없음** — 25023은 25010:2011 기준이라 Scalability 부특성 자체가 없던 판 |
| 차용 대상 | Performance efficiency > Capacity 계열(*User access capacity* 등)의 **서술 형식**(measure ID / QME / 측정 함수 / 해석 / 판정) |

Capacity 계열은 "몇 명까지 되는가"(용량 상한)를 재는 형태로, 본 축이 필요로 하는 "N에 대한 증가 형태"(추세)와 결이 다르다. 따라서 **측정 대상은 자체 정의하되 서술 형식만 표준에서 차용**한다.

> 표준 원문의 measure ID·판 번호는 인용 전 확인 필요.

## 3. QAS (품질 속성 시나리오)

```
Source        N-party 협상 세션 개시 요청

Stimulus      세션 참여자 수가 3 → 4 → 5 → 6 → 8 → 10 으로 증가함
              (feasible slot 개수는 N과 무관하게 고정 — 난이도 교락 통제, §5.3)

Artifact      DP-02의 협상 진행 구조
              C1: SequentialSaoOrchestrator + CumulativeState + All-ACK Barrier
              C2: SyncEngine + ReadyGate + ConsensusEngine + AckCollector

Environment   ENV-A(결정적 시뮬레이션): 라운드 수 분포 수집
              ENV-B(온디바이스 실기기): 라운드 1회 실측
              → 대안별 합성식(§5.2)으로 시간 산출

Response      참여자 증가에 대해 합의 시간과 메시지 수가 선형 이내로 증가하며,
              합의 완결률이 저하되지 않는다

Response      [유효 조건] SC-N-G  완결률이 N 증가에 따라 유의하게 저하되지 않을 것
Measure       [판정 1]    SC-N-1  합의 시간 확장 지수 b     — 95% CI 하한 ≤ 1
              [판정 2]    SC-N-2  메시지 확장 지수 b_msg   — 95% CI 하한 ≤ 1
              [기록]      SC-N-3  부하 집중 지수 κ         — 판정은 QA-RU-1로 이관
              [병기]      R² · 각 N의 절대 시간·메시지 수 · M04-1 deadline 대비 여유
```

## 4. Measure 명세

### 4.1 SC-N-G — 완결률 불변성 (유효 조건)

| 항목 | 내용 |
|---|---|
| QME | A_N = 참여자 수 N에서 AGREED로 종결한 세션의 비율 |
| 판정 함수 | A_N이 N 증가에 따라 유의하게 저하되지 않을 것 (N=3 대비 N=10, 비율 차 검정) |
| 미충족 시 | SC-N-1·SC-N-2 **무효** — 저하 사실을 결함으로 보고하고 지수 판정 보류 |

**근거 — 구조적 게이밍 경로 차단.** C1은 CumulativeState가 세션마다 좁아지는 구조라, N이 커질수록 후반 세션에서 교집합이 비어 `NO_DEAL`로 조기 종결될 확률이 올라간다(DP-02 C1-S2). 조기 종결 세션은 시간이 짧으므로, 걸러내지 않으면 **"N이 커질수록 빨리 실패해서 b가 좋아지는"** 역설이 생긴다.

이는 21번 문서가 Fault Tolerance 지표에서 이미 경계한 위험(*"오류를 만나면 즉시 결렬해버리는 퇴화 전략"*)이 Scalability 축에 나타난 형태다. FT가 합의/결렬 **구성비**로 막았듯 동일 방식으로 막는다.

### 4.2 SC-N-1 — 합의 시간 확장 지수 b (판정)

| 항목 | 내용 |
|---|---|
| QME | T_N = 참여자 수 N에서 AGREED로 종결한 세션의 합의 도달 시간(중앙값) |
| 측정 함수 | log T_N = a + b·log N 최소제곱 회귀의 기울기 b와 95% 신뢰구간 |
| 해석 | 낮을수록 좋음. 참조점: 선형 = 1(수학적 기준선), 전원-전원 직접 통신 이론값 ≈ 2 |
| 판정 | b의 95% 신뢰구간 **하한 ≤ 1** |
| 유효 조건 | SC-N-G 통과 시에만 유효 |

### 4.3 SC-N-2 — 메시지 확장 지수 b_msg (판정)

| 항목 | 내용 |
|---|---|
| QME | M_N = 참여자 수 N에서 세션 1회에 오간 A2A 메시지 총수(중앙값) |
| 측정 함수 | log M_N = a + b_msg·log N 회귀의 기울기와 95% 신뢰구간 |
| 해석 | 낮을수록 좋음. C1 Sequential 이론값 ≈ 1, C2 multilateral 이론값 ≈ 2 |
| 판정 | b_msg의 95% 신뢰구간 **하한 ≤ 1** |

**판정으로 승격한 근거**: 시간 지수만으로는 C2의 병렬 이득이 메시지 비용을 가린다. 온디바이스에서 메시지는 배터리·라디오 점유로 환산되므로 별도 판정축이 필요하다. (기존 §21.5-4는 메시지를 보조 관측으로 두었으나, DP-02의 C1↔C2 비교에서는 결정적 판별축이므로 변경 제안 — 팀 합의 필요)

### 4.4 SC-N-3 — 부하 집중 지수 κ (기록)

| 항목 | 내용 |
|---|---|
| QME | 노드별 협상 관여 처리 시간(또는 처리 메시지 건수) |
| 측정 함수 | κ_N = (최대 부하 노드의 처리량) ÷ (전체 노드 평균 처리량) |
| 해석 | 1에 가까울수록 대칭. 구조적 참조값 — C1 Central: κ ≈ (N−1)/2 로 **N에 비례 증가**, C2: κ ≈ 1 |
| 지위 | **판정하지 않고 기록** — 집중된 부하의 감당 가능 여부는 앱 가용 예산 대비 절대 수준 문제이므로 QA-RU-1 소관. 본 지표는 *집중이 N과 함께 자라는지*만 노출한다 |

**RU로 넘긴 근거**: 21번 §21.3-8의 *"같은 관측값을 두 QA에 이중 계상하지 않는다"* 원칙. 다만 §7-4의 사각 위험을 함께 볼 것.

## 5. 측정 방법

### 5.1 N 수준 — 로그 등간격 6단계

```
N ∈ {3, 4, 5, 6, 8, 10}
log N ≈ 1.10, 1.39, 1.61, 1.79, 2.08, 2.30
```

| 근거 | 내용 |
|---|---|
| **6단계 이상** | 3단계는 회귀 자유도 1이라 신뢰구간이 극단적으로 넓어져 "하한 ≤ 1"이 무조건 통과된다 — 판정이 형해화. 21번 §21.5-5가 SC-의제조합에 이미 요구한 기준(*"로그 등간격 6단계 이상"*)과 동일하게 맞춘다 |
| **로그 등간격** | log-log 회귀이므로 산술 등간격은 작은 N에 점이 몰려 회귀 지렛대가 큰 N에 쏠린다 |
| **N=10 포함 필수** | 정책 상한이 10이면 회귀 범위에 10이 들어가야 한다 — N=7까지 측정하고 N=10을 보장할 수 없다(외삽 금지). DP-02의 "N=10 exploratory"를 **판정 범위로 승격** |

### 5.2 시간 합성식 — 대안별 분리

```
C1 Central Sequential:
  T_N = Σ(i=1..N-1) [ rounds_i × t_round(i) ] + T_ack
        ↑ 세션별 라운드 수가 다름 (CumulativeState 축소 효과)
        ↑ 세션 위치 i에 따른 t_round 변화도 확인해 보고

C2 Distributed:
  T_N = T_hard_sync + rounds × t_round(N) + T_ack
        ↑ 단일 다자 세션 (또는 vote 라운드)
        ↑ t_round가 N에 의존 (수신 처리 건수 증가)
```

기존 §21.5-4의 단일 합성식(`라운드 수 × 라운드 1회 시간`)은 C1에 성립하지 않는다 — C1은 세션이 N−1개이고 세션마다 라운드 수가 다르기 때문이다. 하니스에 **대안별 어댑터**를 둔다(§21.5-7 Recoverability 측정이 쓴 방식과 동일 구조).

### 5.3 난이도 교락 통제 — 가장 중요한 통제

참여자를 늘리면서 Hard 프로파일을 매번 무작위 생성하면 **N이 커질수록 feasible 교집합이 자연히 좁아진다.** 그러면 라운드 수·실패율이 올라가는데, 이는 *아키텍처의 확장성*이 아니라 *문제 난이도*가 올라간 결과다. 두 효과가 섞이면 b는 아키텍처를 측정하지 못한다.

**통제 방법**: feasible slot 개수를 N과 무관하게 고정한다 — 먼저 공통 슬롯 k개(예: 3개)를 정하고, 각 참여자의 Hard를 그 k개를 포함하도록 역방향 샘플링. 실패 시나리오는 SC-N-G 게이트용 별도 프로파일로 분리 측정한다.

### 5.4 실행 절차

1. N 수준별 프로파일 생성 (5.3 통제 적용, 동일 seed 고정)
2. 각 N에서 **30회** 실행 — AGREED / NO_DEAL 종결 유형 기록
3. **SC-N-G 먼저 판정** — 완결률 저하 시 중단하고 결함 보고
4. AGREED 세션만으로 T_N, M_N 집계 (중앙값)
5. log-log 회귀 → b, b_msg와 95% CI, R² 산출
6. 노드별 처리량에서 κ_N 산출·기록 → QA-RU-1로 연결
7. 절대 deadline 교차 확인 — DP-02 M04-1의 deadline 게이트와 나란히 보고 (판정은 중복하지 않음)

### 5.5 실기기 제약 시 보완

ENV-B로 10대 확보가 어려운 경우:
- ENV-A(시뮬레이션)는 6단계 전부 측정
- ENV-B(실기기)는 3~4단계만 실측하고 라운드 1회 시간의 N 의존성을 회귀로 보간
- **보간 구간임을 보고서에 명시** (실측값과 보간값 구분 표기)

## 6. 판정 기준의 근거

### 6.1 왜 "하한 ≤ 1"인가 — 판정 방향

b는 추정값이므로 구간으로 나온다. **하한**은 그 구간의 최저값이다.

```
b 구간 = [0.82, 1.48]  하한 0.82 ≤ 1  → 통과 (1을 넘는다고 단정 못 함)
b 구간 = [1.12, 1.68]  하한 1.12 > 1  → 탈락 (1을 넘는 게 확실)
```

즉 **"선형보다 나쁘다"가 통계적으로 확인될 때만 탈락**시키는 무죄 추정 방식이다. 애매하면 통과.

SC-의제조합(c)이 *상한 < 1*(유죄 추정)인 것과 방향이 반대인데, 이는 c의 판정 목적이 *전체 열거 구조의 명시적 기각*이라 입증 책임이 반대편에 있기 때문이다.

**주의**: 판정 대상은 절대 시간이 아니라 **증가 기울기**다. 참여자 2배에 시간 2배면 선형(통과), 4배면 제곱(탈락). 절대 시간이 아무리 길어도 기울기가 선형 이내면 본 축은 통과하며, 절대 상한은 QA-TB-1·M04-1 소관이다.

### 6.2 왜 95%인가 — 정직한 근거

**표준 문서에 규정된 값이 아니다.** ISO/IEC 25010·25023 어디에도 신뢰수준 지정은 없으며, 95%는 Fisher 이래의 관습이다. 98%·90%·99% 모두 사용 가능하다.

따라서 근거는 다음 두 가지로 한정해 기록한다:

**① 1종/2종 오류 비용이 대칭에 가깝다 → 극단값 배제**

| 신뢰수준 | 구간 | 판정 경향 | 위험 |
|---|---|---|---|
| 낮춤(90%) | 좁아짐 | 탈락 쉬워짐 | 멀쩡한 토폴로지를 잘못 버림 |
| 높임(99%) | 넓어짐 | 통과 쉬워짐 | 제곱 증가 구조를 놓침 |

잘못 탈락시키면 대안 재검토 비용(회복 가능), 잘못 통과시키면 실사용에서 뒤늦게 발견(역시 회복 가능). **어느 쪽도 파국적이지 않아** 극단을 고를 이유가 없다. 안전 필수 시스템이라면 2종 오류 비용이 커서 신뢰수준을 올려야 하지만 본 시스템은 해당하지 않는다.

**② 문서 내 일관성**

21번 문서의 SC-의제조합(c)·Confidentiality가 이미 95%를 쓴다. 새 지표만 98%로 하면 *"왜 이것만 다른가"* 라는 임의성이 새로 생겨, 문서가 견지하는 **"임의 상수를 넣지 않는다"** 원칙과 충돌한다.

> 95%와 98% 중 하나를 수학적으로 유도할 방법은 없다. 문서에는 *"분야 표준이므로"* 가 아니라 위 ①②를 근거로 기록한다.

### 6.3 모형 적합성 — 미해결

신뢰구간은 **멱함수 모형(T ∝ N^b)이 맞다는 가정** 위에 있다. C1 Sequential의 `T = Σ(session_i) + ack` 구조는 사실 *선형+상수항* 모형이 더 자연스러워, log-log 회귀로 억지로 맞추면 b 추정이 왜곡될 수 있다.

R² 병기가 이를 부분적으로 막지만 **R²가 낮을 때의 처리 규칙이 정해져 있지 않다.** §7-5 참조.

## 7. 후보 판별력 검증 — 이 정의가 C1/C2를 가르는가

| Measure | C1 Central Sequential | C2 Distributed |
|---|---|---|
| SC-N-1 (시간 b) | ≈ 1 — 통과하되 여유 없음 | < 1 가능(병렬) — 통과 |
| SC-N-2 (메시지 b_msg) | ≈ 1 — 통과 | **≈ 2 — 위반 위험** |
| SC-N-3 (κ, N=10) | **≈ 4.5 — 심각한 편중** | ≈ 1 — 평탄 |
| SC-N-G (완결률) | **N↑ 시 저하 위험**(누적 제약) | 상대적 안정 |

**네 지표가 서로 다른 방향으로 갈린다 — 측정 정의가 제 역할을 한다는 신호다.** 시간 지수 하나만으로는 두 후보가 모두 통과해 판별이 되지 않았을 것이다. DP-02 §5의 *"동등 비교 후 측정으로 ADR 확정"* 이 요구하는 측정이 바로 이 네 축이다.

N=7까지만 보면 차이가 애매하고, **N=10에서 비로소 선명하게 갈린다** — N_max=10 설정의 실질적 의미가 여기 있다.

## 8. 남는 결정 사항

1. **feasible slot 고정 개수 k** — 3개가 적절한지, k가 b에 미치는 영향은 사전 실험 필요.
2. **SC-N-2 판정 승격 여부** — 21번 문서가 메시지를 보조 관측으로 둔 원판단을 뒤집는 제안이므로 팀 합의 필요.
3. **SC-N-G 저하 판정의 검정 방법·유의수준** — 비율 차 검정의 구체 절차 미정.
4. **κ의 RU 이관 형식 — 사각 위험** ⚠ 
   현재 QA-RU-1은 *기준 시나리오(3인)의 절대 수준*만 측정한다. **N=10의 Central 단말**이 RU 측정 범위에 들어가지 않으면, C1의 부하 집중이 SC에서는 "기록만"·RU에서는 "범위 밖"이 되어 **어느 QA에서도 판정되지 않는 사각**이 생긴다. RU 측정 설계(§21.5-8)의 기준 시나리오에 *N=N_max의 최대 부하 노드*를 추가할 것을 권고한다.
5. **R² 임계값** — 낮을 때 멱 모형을 재검토할 기준선(예: 0.9)을 정할지, 미해결로 둘지.
