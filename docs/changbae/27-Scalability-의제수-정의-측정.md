# 27. Scalability — 의제 수 · 정의 · 측정 방법 · 측정 목표

> 배경: 핵심 QA 4위인 Scalability-의제 수(확장성)의 측정 정의다. PL이 직접 지목한 문제 — "의제가 4개이고 후보가 K·L·M·P개면 조합은 곱이 되어, 전부 만들어 놓고 협상하면 메모리가 터진다" — 를 재는 축이며, 복합의제(multi-issue) 해석은 PL 확인을 거쳤다 (2026-08-11).
> 지위: **본 QA의 정의·지표·목표는 본 문서가 정본**이다. [`21`](21-핵심-QA-측정-정의.md) §21.3-5의 측정 정의를 별점 척도로 정제해 대체한다.
> 측정 수행 시 단일 참조: [`29-1 QA 측정 핸드북`](29-1-QA-측정-핸드북.md) — 본 문서는 지표·척도의 정의와 도출 근거를 담는다.

---

## 27.1 정의 (한 문장)

> **Scalability-의제 수 = 의제가 늘어나 후보 조합이 곱으로 커질 때, 협상에 드는 메모리가 조합 수에 정비례하지 않고 훨씬 완만하게 자라는가.**

의제(issue)는 협상에서 정해야 할 항목이다 — 영화 약속이면 날짜·영화·영화관·시간의 4개. 의제 수 d가 하나 늘 때마다 전체 후보 조합 수 S는 **곱셈으로** 폭발한다(의제별 후보 8개면 d=4에서 4,096개, d=5에서 32,768개). 조합을 전부 만들어 놓는 구조(전체 열거)는 메모리가 S에 정비례해서, 의제 몇 개만 늘어도 단말에서 터진다. 이 축은 "그 구조를 피했는가"를 잰다.

## 27.2 용어

| 용어 | 뜻 |
|---|---|
| **의제 (issue)** | 정해야 할 항목 1개 (날짜, 영화, …). 의제 수 = d |
| **복합의제 후보** | 의제 값들의 튜플 — 예: (토요일, 영화A, 강남점, 19시). "후보군"(한 의제의 값 목록)과 다르다 |
| **조합 수 S** | 의제별 후보 수의 곱 (K×L×M×P) — 전체 후보 공간의 크기 |
| **전체 열거** | S개의 조합을 전부 생성·보관하는 구조 — 메모리 ∝ S (탄력성 1) |
| **탄력성 c** | 피크 메모리가 S의 몇 제곱으로 자라는가 — 메모리 ∝ S^c 의 지수. 전체 열거면 1, 완전한 순차 좁히기면 이론상 1/d 수준 |

## 27.3 핵심 지표 — 조합-메모리 탄력성 c와 별점 척도

> **c**: 조합 수 S를 바꿔가며 협상 1회의 피크 메모리를 재고, log(메모리)를 log(S)에 대해 회귀했을 때의 기울기. 95% 신뢰구간과 함께 추정한다.
> **평가: c를 별점 0-5점으로 변환한다** — 등급 경계는 두 수학적 참조점, **전체 열거(c = 1)**와 **순차 좁히기의 이론 이상값(c ≈ 1/d — 기준 시나리오 d=4면 0.25)** 사이를 5등분한 폭 0.15의 구간이다.

| 별점 | c 범위 | 뜻 |
|---|---|---|
| **5점** | 0.40 이하 | 이론 이상에 근접 — 조합이 4배 될 때 메모리 1.7배 이하 |
| **4점** | 0.40 초과 - 0.55 이하 | 강한 축소 구조 |
| **3점** | 0.55 초과 - 0.70 이하 | 축소가 작동하나 여지 큼 |
| **2점** | 0.70 초과 - 0.85 이하 | 전체 열거에 근접 |
| **1점** | 0.85 초과 - 1.00 이하 | 사실상 전체 열거 |
| **0점** | 1.00 초과 | 전체 열거 이상 — 조합 폭발을 흡수하지 못함 |

(기준 시나리오의 의제 수 d가 바뀌면 하계 1/d와 구간 폭을 갱신한다 — 분석자 제안.)

**통계 처리**: 별점은 c 점추정으로 정하고 95% 신뢰구간을 병기한다. 구간이 3개 이상 등급에 걸치면 측정 단계(S 수준)를 늘려 재측정한다.

## 27.4 유효 조건 — 완결률이 떨어지면 지수는 무효

S가 커질수록 협상이 빨리 결렬해 버리면 깊은 라운드에 도달하지 않아 메모리가 적게 나온다 — "많이 실패해서 탄력성이 좋아지는" 왜곡이다. [`25`](25-Scalability-참여자수-정의-측정.md) §25.4와 같은 게이트를 둔다:

> **유효 조건**: 정상 완결률이 S 증가에 따라 유의하게 저하되지 않아야 한다 (최소 S vs 최대 S, 비율 차 검정 95%). 저하 확인 시 c 값과 무관하게 **0점 처리하고 결함으로 보고**한다.

## 27.5 측정 방법

- **후보 공간**: 복합의제 튜플의 곱집합으로 구성한다. **조합 수 S를 로그 등간격 6단계**로 확장하되, 의제 수 d 자체도 함께 늘린다(예: d=2/S=100 → d=5/S=32,768) — 의제 수 증가가 이 축의 본질이기 때문이다.
- **utility**: 의제별 점수의 가중합(벤치마크 규격 확정 전에는 개발용 임시 — NegMAS LinearAdditive와 동형).
- **측정량**: 협상 1회의 피크 메모리에서 협상 시작 전을 뺀 증가분. **관찰 로그 등 하니스 부가 할당은 제외**한다 (측정 오염 방지).
- **환경**: 정본은 실기기(ENV-B) 프로파일러다. 개발 단계에서는 ENV-A에서 프로세스 할당 추적(tracemalloc)으로 대체 측정하고, 대체임을 보고서에 명시한다.
- **절차**: ① S 수준별 프로파일 생성(시드 고정) ② 각 수준 5회 이상 실행, 피크 메모리 중앙값 ③ 유효 조건 판정 ④ log-log 회귀 → c·95% CI·R² (R² < 0.9면 멱 모형 재검토) ⑤ 별점 산정. 대안 비교는 동일 하니스·시드에서 구조만 교체.

## 27.6 측정 목표

- **시스템 목표: 별점 3점 이상** (c ≤ 0.70), 이상적으로는 5점. 0-1점은 사실상 전체 열거이므로 구조 재설계 대상이다.
- **등급 경계의 근거**: 임의 상수가 없다 — 상계 1은 전체 열거의 수학적 성질이고, 하계 1/d는 의제를 하나씩 확정하며 좁히면 메모리가 곱이 아니라 합 규모가 된다는 이론값이다. 그 사이를 별점 단계 수로 등분했다.

## 27.7 경계 — 이 축이 재지 않는 것

| 재지 않는 것 | 소관 |
|---|---|
| 기준 시나리오에서의 절대 메모리 수준 (Peak/Average RSS) | Resource Utilization-메모리 ([`26`](26-Resource-Utilization-정의-측정.md)) |
| 참여자 수 증가에 대한 추세 | Scalability-참여자 수 ([`25`](25-Scalability-참여자수-정의-측정.md)) |

같은 관측값의 이중 계상 금지 원칙에 따라 본 축은 **조합 수에 대한 메모리의 증가 추세(지수)** 만 판정한다 — 26이 절대 수준을, 본 축이 기울기를 맡는 분업이다.
