# 9. 핵심 Quality Attributes 중요도·난이도 평가 (빈도 상위 11종)

> 대상: [`03-QA-카테고리-정리.md`](03-QA-카테고리-정리.md) §3.2의 **빈도 4 이상 하위특성 11종**.
> 여러 stakeholder가 독립적으로 요구한 교차 관심사이므로, 전수 평가([`04`](04-QA-중요도-난이도-평가.md))에서
> 분리해 **아키텍처 논의의 1차 대상**으로 별도 평가한다. 등급은 전수 평가와 동일 척도(04 §4.1)이며 일관된 값을 유지한다.
>
> **포커스 반영** (사용자 지시, 2026-08-04): 과제 주제는 **다자간 협상** — NegMAS 기반 2자 프로토콜
> (효용 점수화 → 최고점 제안 → threshold 수락/역제안)의 N-party 확장. 각 QA에 "다자 확장에서의 함의"를 병기한다.

| 4 | Performance Efficiency — **Time Behaviour** | 4 | S1 S4 S8 S10 | **H** | **H** | 가설③ 직결 + 핵심 사용자 가치가 "시간 회수". 온디바이스 추론 지연이 협상 시간의 지배 항 | 교대 제안이 순차 진행되면 소요 시간이 **참여자 수에 비례 이상으로 증가** — 라운드 병렬화·제안 동시 수집 등 프로토콜 차원의 시간 설계 필요 |

## 9.2 분포 요약

| | 난이도 H | 난이도 M |
|---|---|---|
| **중요도 H** | Functional Correctness · Fault Tolerance · Time Behaviour · Resource Utilization · Recoverability · Confidentiality · Testability · Scalability · Operational Constraint **(9)** | Analysability · Accountability **(2)** |

- 11종 전원이 중요도 H — **빈도 상위(여러 역할의 교차 요구)와 과제 결정성(중요도)이 일치**함을 확인. 전수 평가의 (H,H) 12종 중 9종이 여기에 포함된다.
- 전수 평가 (H,H)이면서 빈도 상위가 아닌 3종: Co-existence(빈도 2) · Operability(빈도 2) · Safe Integration(빈도 1) — **빈도가 낮다고 덜 중요한 것이 아님**을 보여주는 반례다. 소수 역할(MX·End User·개발자)만 요구하지만 미충족 시 시스템 존립이 무너지는 속성이므로, 아키텍처 논의에서는 본 11종에 이 3종을 더한 집합을 다루는 것을 권고한다 (분석자 판단).

## 9.3 다자간 협상 설계가 우선 답해야 할 질문 (분석자 도출)

위 평가에서 다자 확장 시 질적으로 변하는 QA(1·2·4·6·7·9·10·11)를 종합하면, 다자 프로토콜 설계는 최소 다음을 결정해야 한다:

1. **제안 토폴로지** — 전원 브로드캐스트 vs 중재자(Coordinator) 집계 vs 순차 릴레이 (시나리오 2의 "중재자 또는 분산 락"): Scalability·Time Behaviour의 증가 함수를 결정
2. **수락 판정 규칙** — 전원 threshold 초과 vs 정족수 — Functional Correctness(L2: 전원 제약 만족)와 직결
3. **양보(concession) 전략** — 라운드 경과에 따른 threshold 완화 규칙: 무한 루프 방지(Fault Tolerance·Scalability)와 결과 품질(L3)의 트레이드오프
4. **이탈·무응답 처리** — 부분 진행 허용 여부: Fault Tolerance·Recoverability
5. **정보 공개 수준** — 제안·수락 패턴에서의 선호 역추론 방어: Confidentiality
6. **개입 시점 모델** — 진행 중 사용자 개입이 어느 라운드 경계에서 반영되는가: Operability(빈도 외 추가 3종 중 하나)
7. **합의 확정 커밋** — 전원 확인 후 실행(원자성): Functional Correctness L4·Accountability
