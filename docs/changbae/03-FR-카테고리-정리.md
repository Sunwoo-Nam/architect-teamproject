# 3. Functional Requirements 카테고리별 정리 — 다자간 협상 범위

> 입력: [`02-Stakeholder별-FR-도출.md`](02-Stakeholder별-FR-도출.md)의 100개 항목 (10명 × 10개)
> 여러 stakeholder가 같은 기능을 요구한 경우 **통합 FR(CFR)** 로 묶고 출처를 병기한다.
> 통합 결과: 100개 항목 → **64개 CFR**. 평가는 [`04`](04-FR-중요도-난이도-평가.md)에서 CFR 단위로 수행한다.
> 카테고리 체계(A~J)는 분석자 정의.

## 3.1 카테고리 체계와 분포

| 카테고리 | 기능 축 | 항목 수 | CFR 수 |
|---|---|---|---|
| A | 의도 감지·해석 (Intent Detection) | 2 | 2 |
| B | **다자 협상·합의 (N-party Negotiation & Consensus)** | 15 | 12 |
| C | 권한 위임·통제 (Delegation & Control) | 4 | 3 |
| D | 사용자 상호작용 (User Interaction) | 8 | 6 |
| E | 선호·효용 구성 (Preference & Utility) | 2 | 2 |

| G | 보안·프라이버시 (Security & Privacy) | 8 | 6 |
| H | 이력·감사 (History & Audit) | 5 | 4 |
| I | 플랫폼·자원·운영 (Platform & Operations) | 31 | 18 |
| J | **검증·측정 (Verification & Measurement)** | 24 | 10 |
| **계** | | **100** ✓ | **64** |

관찰 (분석자 판단): 항목 수 최다는 **I(플랫폼·자원·운영, 31건)** 로, 기술 stakeholder 5인의 공통 기반 요구가 모이는 곳이다. 다만 과제의 성격을 드러내는 것은 **B(다자 협상, 15건)와 J(검증, 24건)의 비중**이다 — "다자 프로토콜을 만들고, 그것을 실기기 없이 검증한다"는 포커스가 분포에 그대로 나타난다. 실행·외부 연동(F)이 1건에 그치는 것은 B2C 예약을 확장 단계로 분류한 범위 설정의 반영이다.

## 3.2 카테고리별 통합 FR (CFR)

### A. 의도 감지·해석

| CFR | 통합 Functional Requirement | 출처 |
|---|---|---|
| CFR-A1 | 시스템은 그룹 대화·맥락에서 다자 조율 의도(참여자·의제·기한)를 감지·분류하여 선제 제안하는 기능을 제공해야 한다 | S1-F01 |
| CFR-A2 | 시스템은 명시적 지시로부터 그룹 협상을 시작하는 기능을 제공해야 한다 | S1-F02 |

### B. 다자 협상·합의 (포커스 코어)

> NegMAS 기반 2자 프로토콜(효용 점수화 → 최고점 제안 → threshold 수락/역제안)의 다자 확장.

| CFR | 통합 Functional Requirement | 출처 |
|---|---|---|
| CFR-B1 | 시스템은 참여자 초대·세션 구성과 협상 역할(중재자/참여자) 설정 기능을 제공해야 한다 | S1-F03 · S4-F04 |
| CFR-B2 | 시스템은 라운드 단위의 다자 협상 실행(제안 수집·배포·라운드 타임아웃)을 수행하는 기능을 제공해야 한다 | S1-F06 · S5-F02 |
| CFR-B3 | 시스템은 협상 메시지를 N명에게 브로드캐스트·라우팅하는 기능을 제공해야 한다 | S5-F01 |
| CFR-B4 | 시스템은 전 참여자가 동일한 협상 상태를 갖도록 동기화하는 기능을 제공해야 한다 | S5-F03 |
| CFR-B5 | 시스템은 의제로부터 옵션 공간(OutcomeSpace)을 의제 간 종속 관계와 함께 계층적으로 정의·생성하는 기능을 제공해야 한다 | S6-F01 |
| CFR-B6 | 시스템은 옵션을 효용으로 점수화하고 제안 후보 순위를 산출하는 기능을 제공해야 한다 | S6-F03 |
| CFR-B7 | 시스템은 수신 제안의 효용을 threshold 기준으로 수락·거절 판정하는 기능을 제공해야 한다 | S6-F04 · S2-F04 |
| CFR-B8 | 시스템은 라운드 경과에 따른 양보(concession) 전략(threshold 조정)을 실행하는 기능을 제공해야 한다 | S6-F06 |
| CFR-B9 | 시스템은 N명의 수락·거절을 시나리오별로 구성된 완결 규칙(전원 합의·정족수·다수결·승인자 부분 완결)에 따라 집계하여 합의 성립을 판정하는 기능을 제공해야 한다 | S6-F07 (완결 규칙 다양성은 PL 지시, 2026-08-05) |
| CFR-B10 | 시스템은 수렴 불가 시 결렬을 판정하고 종결하는 기능을 제공해야 한다 | S6-F08 |
| CFR-B11 | 시스템은 참여자의 중도 이탈·재참여를 처리하는 기능을 제공해야 한다 | S2-F08 |
| CFR-B12 | 시스템은 확정된 의제 값을 제약으로 전파하여 미확정 의제의 후보군을 축소(가지치기)하고, 옵션 조합을 전체 열거 없이 지연 생성하는 기능을 제공해야 한다 | S6-F05 |
