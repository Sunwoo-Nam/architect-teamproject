# 6. Stakeholder별 Functional Requirements 도출 (10명 × 10개)

> **FR 기술 형식**: FR은 QA와 달리 정도가 아니라 기능이므로, 모든 항목을
> *"시스템은 ~하는 기능을 제공해야 한다"* 형태로 기술한다.
>
> **독립 도출 원칙**: 기존 요구사항 문서(`docs/04-FR.md` 등)를 참고하지 않고,
> **stakeholder VOC([`docs/03-Stakeholder.md`](../03-Stakeholder.md) · [`annex/Stakeholder-원본표.md`](../../annex/Stakeholder-원본표.md))와
> 과제 설명([`docs/01`](../01-과제-배경-및-목적.md) · [`docs/02`](../02-과제-개요.md) ·
> [`annex/상호작용-시나리오-9종.md`](../../annex/상호작용-시나리오-9종.md))만을 근거**로 도출했다.
>
> 순위(1~10)는 해당 역할 관점의 상대적 중요도(분석자 판단).
> 카테고리 약자(A~J)는 [`07-FR-카테고리-정리.md`](07-FR-카테고리-정리.md)의 기능 카테고리 체계를 가리킨다.
