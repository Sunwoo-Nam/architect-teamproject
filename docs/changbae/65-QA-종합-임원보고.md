## 슬라이드 3 — ② QA 상세 1/5: 기능 정확성 (QA-FC-1)

- **정의**: 협상이 도달한 결과가, 도달할 수 있었던 **최적 합의안 효용의 몇 %인가 — 달성률**.
- **왜 중요한가**: 협상 시스템의 존재 이유 — 빨라도, 덜 새도, 나쁜 합의안이면 무의미 (서열 1위).
- **측정 방식**: 선호를 봉인 생성 → 채점기만 전체를 보고 최적 x\* 산출 → 달성률 = U(도달) ÷ U(x\*). **결렬이 정답인 판에서 정확히 결렬하면 만점**.
- **별점**: ≥0.95 ★5 / ≥0.90 ★4 / ≥0.85 ★3 / ≥0.80 ★2 / ≥0.70 ★1 / 미만 ★0 (만점 1.0부터 5%p 계단, ★1만 0.70-0.80).
- **과대평가 방어**: 무작위 선택 평균(R̄)을 병기하고, **무작위 평균 이하면 별점과 무관하게 즉시 결함**.
- 그림: 61-2 달성률 눈금 개념 (별점 대역 + 결렬/무작위/도달/만점 위치).

## 슬라이드 4 — ② QA 상세 2/5: 자원-메모리 (QA-RU-1)

- **정의**: 협상 중 **가장 무거운 단말의 순간 피크**가 협상 몫(128MB)의 몇 %인가 — 사용률 r.
- **왜 중요한가**: 온디바이스 전제 — 초과하면 앱이 죽는다(OOM). "더 사면 된다"가 없다.
- **측정 방식**: 프로토콜 상태를 라운드마다 실측, 최대 부하 단말 1대 기준(죽는 것은 합이 아니라 한 대) + 방안 무관 공통 기저 1인분. **판정 = 케이스 P95** (OOM은 꼬리 사건).
- **별점**: 로그 사다리 — ≤1% ★5 / ≤3.2% ★4 / ≤10% ★3 / ≤32% ★2 / ≤100% ★1 / 초과 결함. ★5 = 실사용 최대 규모(≈10축)까지 성장(약 100배)해도 한도 내, 1칸 = √10 ≈ 3.2배 (지수 성장 도메인이라 로그 등분).
- **한도 유도**: 앱 힙 256MB × 75%(GC 여유 25% 차감) − 64MB(앱 기본) = 128MB.
- 그림: 61-3 한도 유도 개념.

## 슬라이드 5 — ② QA 상세 3/5: 기밀성 (QA-CF-2)

- **정의**: 협상이 끝난 뒤에도 **내 선호(전체 후보 서열)가 얼마나 비밀로 남는가 — 잔여 비밀률**.
- **왜 중요한가**: 메시지는 암호화돼도 제안·수락의 **패턴**이 선호를 흘린다 — 일정·취향은 개인정보.
- **측정 방식**: 나를 가장 많이 알게 된 관찰자가 내 후보 몇 개를 지목·확인했는지 센다. 분모는 전체 후보(거부 후보의 서열도 비밀). **집계는 합의 완료 세션만**(결렬은 전 목록 소진이 본성), 참여자 평균.
- **별점**: >80% ★5 / >60% ★4 / >40% ★3 / >20% ★2 / >0% ★1 / 0% ★0 (무노출-전량 공개 20%p 등분).
- **해석 앵커**: 1:1 협상의 실측 잔여 ≈ 71% → "★4 이상 = 일반 2인 협상 수준으로 지킨다".
- 그림: 61-4 순위표 공개/비밀 개념.

## 슬라이드 6 — ② QA 상세 4/5: 시간 성능 (QA-TB-1)

- **정의**: 가장 단순한 기본 방식(naive — 전 후보를 1명씩 차례로 제안) 대비 협상 시간을 얼마나 줄이는가 — **시간 비율 ρ = T_설계 ÷ T_naive의 P95**.
- **왜 중요한가**: "약속 잡아줘" 뒤에 사용자가 기다리는 시간 — 합의가 느리면 사람이 직접 하는 게 빠르다.
- **측정 방식**: 합성 시간 모델(통신 단계 × 75ms + 평가÷N × 1.4µs + 전송 ÷ 20Mbps — 재현 가능)로 같은 케이스를 설계안과 naive 양쪽으로 계산해 비율. **판정 = P95** — 시간 품질은 "평소 빠른가"가 아니라 "느린 꼬리에서도 보장되는가" (서비스 SLO의 p95/p99 관행).
- **별점**: ≤0.2 ★5 / ≤0.4 ★4 / ≤0.6 ★3 / ≤0.8 ★2 / ≤1.0 ★1 / ρ>1 ★0 — naive만도 못함, 즉시 결함.
- 그림: 61-1 P95 판정 개념 (누적 곡선과 느린 5%의 경계).

## 슬라이드 7 — ② QA 상세 5/5: 확장성-의제 (QA-SC-2)

- **정의**: 메모리 한도 안에서 협상을 정상 완결할 수 있는 **최대 의제(축) 수**.
- **왜 중요한가**: 후보 조합은 축 수에 지수적 — 날짜×시간×장소×… 20축이면 조합 수천억 개로 "펼쳐놓고 고르기" 자체가 불가능. 견디는 한계 = 제품이 다룰 협상의 복잡도.
- **측정 방식**: 의제 수를 4축부터 늘려가며(스윕) 128MB 한도 안에서 정상 완결하는 최대 축 수 (결렬 실행은 수용의 증거로 세지 않는다).
- **별점**: ≥12축 ★5 / 9-11 ★4 / 7-8 ★3 / 5-6 ★2 / 4 ★1 / 미만 결함. 하한 4축 = 기준 시나리오 요구, 상한 12축 = 실사용 최대(여행급 협의 포화 + 인지 한계 7±2 + ANAC 실세계 도메인 규모) — 사이는 로그 등분.
- 그림: 61-5 조합 폭발 개념.

## 슬라이드 9 — ④ DP1 상세 1/2: 격차는 어디서 오나

**헤드라인: 방안 2는 인원이 늘어도 평평, 1-A는 단조 하락 — N=30부터 전패.**

| N (참여자) | 1-A 달성률 | 방안 2 달성률 |
|---|---|---|
| 3 | 0.938 ★4 | 0.954 ★5 |
| 10 | 0.871 ★3 | 0.955 ★5 |
| 30 | 0.842 ★2 | 0.944 ★4 |
| 50 | 0.835 ★2 | 0.949 ★4 |

- **기능 정확성**: 1-A는 "정답을 못 찾는" 게 아니라 "더 좋은 답을 기다리지 못하는" 방안 — 격차는 전부 미끼 3유형(합계 288건)에서 나고 그중 방안 2가 259건(약 9할) 승. 정답이 유일한 판은 만점 동률.
- **기밀성**: 1-A는 전 구간 1:1 협상 수준(71%) 근방을 지키고, 방안 2는 합의 후보가 깊은 판에서 30%까지 하락.
- **시간**: 절대 시간은 둘 다 50인 협상 3초 이내(naive 64초) — 변별은 소인원 느린 꼬리 (N=3에서 방안 2 P95 0.87 vs 1-A 0.61).

*공정성: 방안 2를 겨냥한 함정 변형도 미끼 2유형 표본의 44%(84건)에 포함 — 그 판에서는 방안 2도 ★1 (한쪽 편 데이터가 아님).*

## 슬라이드 10 — ④ DP1 상세 2/2: 방안 2의 약점은 보완 가능한가 — "방안 2+"

**헤드라인: 택틱 3종으로 열세 2축(기밀·시간)을 모두 역전 — 방안 2+ = 전 축 ★4-5.**

| 전달 기억 | 바퀴마다 같은 후보를 재전송하던 낭비 제거 | 시간 개선 (무손실) |
| 적응 배치 | 라운드당 제출을 1→2→4→8개로 가속 | 라운드 약 40% 감소 (N=50, 방안 2+ 기준) — 느린 꼬리 정조준 |

## 슬라이드 11 — ③ 설계 문제(DP) 2 결과 요약: 복합 의제

**결론 헤드라인: 종합 우위는 pool — 메모리 결함(16축 조건의 근거)은 보완 택틱으로 해소 실측 완료 (슬라이드 13).**

측정 판: 정본 500건 전수 — 의제 4-20축, 조합 최대 약 6×10^11 (경로 함정\* 53 · 현실 모사 302 · 결렬 정답 45 · 규모 스트레스 100).
비교: **seq2** (의제를 한 축씩 순차 확정 — 경로 의존) vs **pool** (조합 풀로 한 판에 협상 — 풀이 지수 성장). *이하 약칭 seq2·pool (각각 방안 1·방안 2).*

| QA | seq2 | pool | 우세 |
|---|---|---|---|
| 기능 정확성 (달성률) | 0.880 ★3 | **0.941 ★4** | pool — 승 186 : 패 143 (무 71) |
| 자원-메모리 (r P95) | **0.30% ★5** | 48.2% ★1 (한도 초과 11건) | seq2 |
| 시간 (ρ P95) | 4.24 ★0 (결함 152건) | **0.633 ★2** | pool |

"품질·시간의 pool vs 메모리의 seq2" — 서열 1위(기능 정확성)·4위(시간)가 pool 우세.
바닥 요건 완벽: 결렬 정답 45건 전건 정확 결렬 · FR 위반 0 · 무작위 이하 없음.
*\*경로 함정 = 앞 축의 인기값이 뒤 축의 좋은 값을 막는 판 — 축별 확정의 경로 의존 검증 장치. 데이터셋: FIN.*

## 슬라이드 12 — ④ DP2 상세 1/2: 격차는 어디서 오나 — 경로 의존

**헤드라인: 격차의 출처는 경로 함정 — seq2는 53건 중 43건 결렬, pool은 53/53 합의.**
