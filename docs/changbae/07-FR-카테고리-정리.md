## 7.2 카테고리별 통합 FR (CFR)

### A. 의도 감지·해석

| CFR | 통합 Functional Requirement | 출처 |
|---|---|---|
| CFR-A1 | 시스템은 사용자의 명시적 지시로부터 의도를 해석하여 작업을 시작하는 기능을 제공해야 한다 | S1-F01 |
| CFR-A2 | 시스템은 기기 사용 맥락에서 잠재 의도를 감지하여 선제적으로 작업을 제안하는 기능을 제공해야 한다 | S1-F02 |
| CFR-A3 | 시스템은 Intent를 분류하고 confidence를 산출하며, confidence가 낮으면 사용자에게 확인 질문을 하는 기능을 제공해야 한다 | S8-F02 · S8-F03 |

### B. 협상·합의

> 포커스 반영: 협상 알고리즘은 **NegMAS 기반** — 각 참여자가 자기 옵션 공간(OutcomeSpace)을 효용 함수(Ufun)로 점수화하여 최고점 후보를 제안하고, 수신자는 자기 효용이 threshold 이상이면 수락·미만이면 거절 후 역제안하는 교대 제안 방식. **본 과제는 이 2자 프로토콜의 다자간(N-party) 확장 설계에 포커싱한다** (사용자 지시, 2026-08-04).

| CFR | 통합 Functional Requirement | 출처 |
|---|---|---|
| CFR-B1 | 시스템은 사용자를 대신해 상대 Agent와 1:1 자율 협상(효용 기반 제안 → threshold 평가 → 수락/역제안 사이클)을 수행하는 기능을 제공해야 한다 | S1-F04 |
| **CFR-B2** | 시스템은 3인 이상이 참여하는 **다자간(N-party) 그룹 합의**를 수행하는 기능을 제공해야 한다 — 2자 교대 제안 프로토콜의 다자 확장 | S4-F07 |
| CFR-B3 | 시스템은 예약 가능 여부·조건 조회 요청에 응답하고 조건을 협상하는 기능을 제공해야 한다 | S3-F03 |
| CFR-B4 | 시스템은 진행 중인 협상에 정책·조건 변경을 반영하고 참여자에게 통지하는 기능을 제공해야 한다 | S3-F08 |
| CFR-B5 | 시스템은 확정된 합의의 변경·취소를 상대측과 재협상하는 기능을 제공해야 한다 | S2-F10 |
| CFR-B6 | 시스템은 협상 프로토콜의 버전을 식별하고 상호 호환 버전을 협상하는 기능을 제공해야 한다 | S5-F06 |
| CFR-B7 | 시스템은 Agent 간 표준화된 형식의 협상 메시지를 송수신하는 기능을 제공해야 한다 | S6-F05 |
