# 51-3. 메시지 페이로드 결합 구조 검토 — 방안 1-A / 방안 2

> 목적: [`51-2`](51-2-라운드상호작용-구조-검토.md)가 "언제 메시지가 오가는가"를 다뤘다면, 본 문서는 "그 메시지 하나에 무엇이 실리는가"를 다룬다 — 필드 결합 여부가 유실 시 영향 범위를 결정하기 때문이다.

## 1. 원문의 경고

51 §3-1: "대가: O/X와 다음 후보가 한 메시지에 묶여 1건 유실이 둘을 함께 잃는다(방안 1에서는 별개 사건)." 이 문장이 실제로 무엇을 의미하는지, 코드의 payload 구조로 확인한다.

## 2. 방안 1-A 회신 메시지 — 실제 필드 구성

코드(`protocol_styles.py` `Plan1aSao._exchange`):

```python
bundle = {c: a.vote(c, sweep) for c in candidates}   # 이번 라운드 배포된 후보 전부에 대한 O/X
nxt = a.peek(sweep)                                   # 자기 다음 순위 후보
...
bb.counter.add("reply", 1, {
    "votes": {str(c): v for c, v in bundle.items()},
    "next": str(nxt) if nxt is not None else None,
})
```

회신 메시지 1건 = `{votes: {candidate: O/X, ...(그 라운드 배포분 전체)}, next: 다음 순위 후보}`. 원문의 "O/X"는 단일 불리언이 아니라 **그 라운드에 배포된 후보 전체에 대한 O/X 묶음**(votes dict)이고, 여기에 다음 순위 후보(next)가 같은 메시지에 더 묶인다 — "판정 정보 + 다음 제안"이 하나의 전송 단위다.

이 메시지 1건이 유실되면(`injector.lost()` 분기, `continue`로 처리): 그 라운드 배포분 전체에 대한 O/X 판정과 다음 순위 후보 제출이 동시에 사라진다. 포인터(`a.ptr`)가 전진하지 않으므로 다음 라운드에 같은 후보가 재시도되지만, 그 사이 담당자는 이 참여자의 판정 자체를 이번 라운드 판정에서 빼고 진행한다(`unanimous` 계산의 `len(votes) == self.n` 조건 — 미도착 시 애초에 만장일치 후보가 없다고 판정).

## 3. 방안 2 제출 메시지 — 단일 필드

코드(`protocol.py` `_BasePlan._one_round`):

```python
bb.submit(a.p.pid, i == 0, {"candidate": str(c)})
```

제출 메시지 1건 = `{candidate: 이번 순위 후보}` 뿐이다. 판정을 위한 별도 필드가 없다 — 51 §4 특성 그대로 "투표 없음, 제출이 곧 수락 의사". 유실되면 그 후보 하나의 제출만 사라지고(포인터 유지, 다음 라운드 재시도), 다른 정보와 결합돼 함께 사라지는 것이 없다.

## 4. 대비 표

| | 방안 1-A 회신 메시지 | 방안 2 제출 메시지 |
|---|---|---|
| 필드 | `votes`(그 라운드 후보 전체 O/X) + `next`(다음 후보) | `candidate`(이번 후보) 1개 |
| 유실 시 잃는 정보 | 판정(votes) + 제안(next) 동시 | 제안(candidate) 하나만 |
| 결합 원인 | 배포↔회신 2-phase 왕복을 유지하면서 정보를 병합 (51 §3-1) | 애초에 판정 필드 자체가 없음(투표 없는 구조) |

## 5. 51-1과의 연결 — Recoverability에 미치는 영향

51-1 §2.5는 Final Notifier의 "성립 시에만 통지" 구조가 확정 신뢰성 문제라고 지적했다. 이 문서가 추가로 보여주는 것은 그보다 이전 단계 — **라운드 진행 중의 회신 유실도 방안 1-A에서는 이중 손실**이라는 점이다. 두 문서 모두 Recoverability(복구 성공률 ≥95%, [`10-핵심-QA-측정-계획.md`](../10-핵심-QA-측정-계획.md) 48행) 목표와 관련이 있지만, 51-1은 프로세스 종료 시점의 저장소 유실을, 이 문서는 진행 중 메시지 유실 시의 결합 손실을 다룬다는 점에서 서로 다른 실패 지점을 보완적으로 짚는다.

## 6. 다음 그림에 반영할 요소

1. 방안 1-A 회신 메시지 박스 내부를 `votes`/`next` 두 필드로 나눠 표시 — 유실 시 둘 다 사라짐을 하나의 봉투로 시각화한다.
2. 방안 2 제출 메시지는 `candidate` 단일 필드로 단순하게 표시해 대비를 강조한다.
3. 유실 지점에 결합 손실(1-A) vs 단일 손실(방안 2) 차이를 화살표/아이콘으로 표시한다.
4. 51-1 §2.5(세션 종료 시 통지 유실)와의 범위 차이 — 이 문서는 라운드 진행 중 유실이라는 점을 각주로 명시한다.
