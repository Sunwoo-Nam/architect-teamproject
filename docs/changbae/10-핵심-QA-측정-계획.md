# 10. 핵심 QA 측정 계획 — 지표·목표 수준·테스트 환경·방법

> 대상: [`08`](08-핵심-QA-중요도-난이도-평가.md) §8.3에서 확정한 **최우선 QA — QA ID 기준 15개 항목** + 별개 QA 항목 **QA-FC-2 효용 분배 균형** + 기반 QA 2개 항목.
> 각 항목에 대해 ① 무엇을 재는가(지표·산식), ② 어떤 수준을 만족해야 하는가(목표), ③ 어디서 어떻게 재는가(환경·방법)를 정의한다.
> **정본 안내 (2026-08-06)**: [`20`](20-핵심-QA-확정.md)에서 확정된 핵심 QA 10개의 **핵심 지표·목표 수준은 [`21`](21-핵심-QA-측정-정의.md)이 정본**이다 — 본 문서의 해당 항목 목표값과 다르면 21을 따른다. 본 문서는 전체 QA ID의 측정 항목 목록과 테스트 환경(ENV-A/B/C)·실험 방법의 참조로 유지된다.
> 모든 지표·목표는 **분석자 제안**이며 팀 합의·베이스라인 실측을 거쳐 확정한다. QAS(품질 속성 시나리오) 작성 시 본 계획의 각 행이 "자극 → 환경 → 응답 측정"의 원천이 된다.
> **측정 단위 원칙**: 하나의 QA 항목(ID)은 하나의 자극 부류·하나의 판정 유형만 갖는다 — 판정 주체·측정 층위·판정 방식(결정적/통계적)이 다른 요구는 같은 ISO 하위특성이라도 별개 QA ID로 분리하고, 같은 지표를 두 항목에서 이중 계상하지 않는다.

---

## 10.1 목표 수준의 두 유형

| 유형 | 의미 | 표기 |
|---|---|---|
| **절대 기준** | 결정적으로 검증 가능한 요구 — 실측으로 조정하는 값이 아니라 위반 자체가 결함 | **0건 / 100%** |
| **파일럿 목표** | 통계적 요구 — 베이스라인 실측 전의 잠정 목표. 1차 실측 후 확정치로 대체 | *(제안)* 표기 |

## 10.2 테스트 환경 정의

| 환경 | 구성 | 담당 CFR | 용도 |
|---|---|---|---|
| **ENV-A: Mock 다자 시뮬레이션** | Mock 참여자 N명(스크립트된 선호·threshold·응답 지연) + 기록·재생 하니스(입력·난수·LLM 응답 고정) + 장애 주입기(이탈·단절·타임아웃·메시지 손실) | CFR-J2·J8·J3 | 프로토콜 로직·신뢰성·정확성 계층의 대량 반복 실험 — **다자 검증의 기본 환경** |
| **ENV-B: 실기기** | Galaxy 단말 1~3대 + Android 프로파일러(메모리·CPU·배터리)·adb(Doze 강제 진입·저메모리 시뮬레이션) + 온디바이스 LLM 실추론 | CFR-I13·J4 | 시간·자원·OS 공존 등 단말 물리 특성이 지배하는 QA — 시뮬레이션으로 대체 불가한 항목 |
| **ENV-C: 사용자 평가** | 소수 실사용자 또는 페르소나 기반 Mock 판정기(선호 프로파일로 승인/수정/거부를 판정) | CFR-J4·J9 | 통계 계층(의도 정확성 L1·선호 정합 L3)의 수용성 판정 — 최종 판정 주체가 사용자인 항목 |

> 원칙: **로직은 ENV-A에서 대량으로, 물리는 ENV-B에서 소수 정밀하게, 수용성은 ENV-C에서** 잰다. 시간 예산처럼 둘이 결합되는 항목은 "ENV-A의 라운드 수 × ENV-B의 실측 추론 시간"으로 합성한다 (분석자 제안).

## 10.3 최우선 QA 측정표 (QA ID 기준 15개 항목)

### QA-FC-1: Functional Correctness (기능 정확성, 개인 관점) — 4계층별로 분리 측정 ([`09`](09-Functional-Correctness-정의.md))

| 계층 | 측정 지표 (산식) | 목표 수준 | 환경 | 테스트 방법 (자극 → 측정) |
|---|---|---|---|---|
| 의도 정확성 (L1) | 분류 정확도 = 올바르게 감지된 의도 / 라벨된 전체 케이스, 오탐률 = 의도 없는 대화에서 협상 개시된 비율 | 정확도 ≥ 90%, 오탐률 ≤ 5% *(제안 — 베이스라인 실측 후 확정)* | ENV-A + 라벨 데이터셋 | 그룹 대화 스크립트(의도 있음/없음 라벨) N건 주입 → 감지 결과를 라벨과 대조 |
| 제약 준수 (L2) | 합의안·발신 제안의 제약 위반 건수 (참여자별 위임 범위·캘린더 충돌·예산·공유 금지 대조) | **위반 0건 (절대)** | ENV-A | 무작위 선호·제약 조합으로 협상 M회 실행 → 전 제안·합의안을 규칙 검사기로 전수 대조. **경계값 케이스**(예산 상한 ±1, threshold 경계의 위임 밖 후보) 필수 포함 |
| 선호 정합 (L3) | 무수정 승인율 = 제시안을 수정 없이 승인한 비율, 수정률·거부율·재협상 요구율 | 무수정 승인율 ≥ 70% *(제안 — 1차 실측을 베이스라인으로 확정)* | ENV-C | 페르소나 선호 프로파일로 협상 실행 → Mock 판정기/실사용자의 승인·수정·거부 기록. 선호 입력 누락 오류를 의도 주입한 대조군으로 지표 민감도 확인 |
| 합의 종결 정합 (L4) | 종결 시점 확정 당사자 간 합의 레코드 불일치 건수 | **불일치 0건 (절대)** — 미승인자에 대한 효력 차단의 판정은 QA-OC-1로 단일 귀속 | ENV-A | 커밋 단계(ACK 수집 중)에 단절·이탈을 주입한 협상 M회 → 종료 후 확정 당사자 전원의 최종 레코드를 기계 대조 |

### QA-FT-1 ~ QA-AD-1: 나머지 14개 항목

| QA ID · 항목명 (ISO 하위특성) | 측정 지표 (산식) | 목표 수준 | 환경 | 테스트 방법 (자극 → 측정) |
|---|---|---|---|---|
| **QA-FT-1** 일시 결함 투명 처리 (Fault Tolerance) | 일시 오류(메시지 손실·지연·LLM 타임아웃) 주입 케이스 중 사용자 인지 없이 정상 완결(합의 또는 정상 결렬)된 비율 | 완결률 ≥ 95% *(제안)* | ENV-A | 라운드 진행 중 무작위 시점에 일시 오류 유형별 주입 → 세션 최종 상태 분류. 불확정 상태 발견 = Fail Safe 결함으로 별도 기록 |
| **QA-FT-2** 참여자 상실 하 협상 지속 (Fault Tolerance) | 참여자 이탈·장기 무응답 시, 완결 규칙상 지속 가능한 케이스에서 잔여 그룹이 협상을 지속·정상 완결한 비율 | **100% (절대)** — 지속 불가 케이스(정족수 미달 등)는 정상 결렬로 종결되어야 하며 불확정 상태 0건 | ENV-A | 임의 라운드에서 참여자 이탈·무응답 주입 → 완결 규칙 재적용과 잔여 그룹의 진행·종결 상태 확인 |
| **QA-SC-1** 참여자 확장성 (Scalability) | N ∈ {3, 5, 7}에서의 합의 시간·라운드 수·메시지 수·메모리 — N에 대한 증가 함수의 회귀 적합 | 선형 이내 증가 *(제안 — 초선형이면 프로토콜 재설계 신호)* | ENV-A (로직) + ENV-B (자원 확인) | 동일 시나리오를 N만 바꿔 반복(각 N에서 M회) → 지표를 N에 대해 회귀 분석 |
| **QA-SC-2** 의제 조합 확장성 (Scalability) | 의제 수(2~4)·의제별 후보 수 증가에 따른 탐색 비용(생성·평가된 후보 수)·합의 시간·메모리의 증가 함수, 가지치기(CFR-B12) on/off 대비 축소율 | 전체 열거 대비 유의미한 탐색 공간 축소 입증 + 증가 함수 통제 *(제안)* — 메모리 절대 예산의 판정은 QA-RU-1 소관 (역할 구분: SC-2는 증가 추세, RU-1은 예산 준수) | ENV-A + ENV-B | 의제 수·후보 수 스윕 + B12 on/off 대조 실험 → 증가 함수 비교 |
| **QA-TB-1** 그룹 합의 시간 (Time Behaviour) | 합의 도달 총 시간 = 라운드 수(ENV-A) × 라운드당 실측 시간(ENV-B: 온디바이스 추론+통신), 의도 인지 알림 시간 | 3인 일정 합의 기준 총 5분 이내 *(제안 — 실기기 추론 시간 실측 후 라운드 예산으로 환산·확정)* — 개입 반영 지연은 QA-OP-1 소관 | ENV-A × ENV-B 합성 | 시뮬레이션으로 라운드 수 분포 수집 + 실기기에서 라운드 1회의 추론·전파 시간 실측 → 곱으로 총 시간 추정, 대표 케이스는 실기기 E2E로 검증 |
| **QA-RE-1** 세션 복구 (Recoverability) | 세션 복구 성공률 = 중단 후 재개 성공 / 복구 시도, 복구 후 상태 불일치 건수, 재동기화 시간 | 복구 성공률 ≥ 95% *(제안)*, 복구 후 상태 불일치 **0건 (절대)** | ENV-A (+ ENV-B에서 OS 강제 종료 케이스) | 임의 라운드에서 프로세스 kill·네트워크 완전 단절 → 재시작 후 세션 재개 여부·전 참여자 상태 일치·소요 시간 측정 |
| **QA-TE-1** 시험 용이성 (Testability) | Mock 재현 커버리지 = 정의된 시나리오·이상 카탈로그 중 ENV-A에서 재현 가능한 비율, 재생 재현율 = 동일 기록 재생 시 동일 결과 비율 | 커버리지 **100% (절대)**, 재생 재현율 **100% (절대)** | ENV-A 자체 검증 | 시나리오·이상 카탈로그 전 항목을 Mock으로 실행 시도 → 불가 항목 목록화(=구조 결함). 기록된 세션을 2회 재생 → 결과 diff |
| **QA-RU-1** 자원 효율성 (Resource Utilization) | 피크 메모리(옵션 공간 표현 포함)·참여자당 메모리 증가분·협상 1회당 배터리 소모 | 단말 프로파일별 메모리 예산 내 · OOM **0건 (절대)** · 참여자당 증가분 선형 *(제안 — 예산 절대값은 단말 사양 실측 후 확정)* | ENV-B | N·의제 수 스윕하며 프로파일러로 계측 — 예산 준수(절대 판정) 관점. 증가 추세 분석은 QA-SC-1·2 소관 |
| **QA-CF-1** 정책 기반 비공개 보호 (Confidentiality) | 공유 금지 정보의 그룹 노출 건수, 참여자별 차등 공개 정책 위반 건수 | **0건 (절대)** | ENV-A + 메시지 검사기 | 협상 전 메시지 로그를 공개 정책 스캐너로 전수 검사 — 결정적 판정 |
| **QA-CF-2** 선호 역추론 내성 (Confidentiality) | 역추론 성공률 = 공격자 모델이 메시지 로그만으로 타 참여자의 선호 순위를 복원하는 정확도 | 무작위 추측 수준으로 **최소화** *(제안 — 공격자 모델 정의 후 확정)* | ENV-A + 공격자 모델 | 완료된 협상 로그에 역추론 공격자 모델 실행 → 복원 정확도 측정. 노출 최소화 전략(CFR-G5) on/off 대조 — 통계적 판정, 협상 효율과의 트레이드오프 함께 기록 |
| **QA-OC-1** 운용 제약 준수 (Operational Constraint) | 위임 범위 초과 행동 건수(수락·집계·확정·인계 전 경로) + 미승인자 확정 효력 발생 건수 | **초과 0건 + 미승인자 효력 0건 (절대)** | ENV-A (적대적 케이스) | threshold는 넘지만 위임 범위 밖인 고효용 후보를 의도적으로 생성·주입 → 이중 검사(CFR-C2)의 차단 여부 확인. 완결 규칙별(전원/다수결/부분)로 미승인자 효력 검사 반복 |
| **QA-CX-1** 공존성 (Co-existence) | Doze 진입 중 세션 생존율, OS 강제 종료 빈도, 포그라운드 앱 성능 저하(프레임 드랍) | Doze 통과 세션 생존율 ≥ 95% *(제안)* — 강제 종료된 세션의 복구는 QA-RE-1로 이관 측정 | ENV-B | 협상 진행 중 adb로 Doze 강제 진입·저메모리 상황 유발·포그라운드 부하 앱 실행 → 세션 상태·OS 이벤트 로그·프레임 지표 수집 |
| **QA-OP-1** 운용성/사용자 통제 (Operability) | 개입 반영 지연 = 개입 명령 시점 → 협상 상태 반영 시점, 개입 반영 후 전 참여자 상태 일관성 | 개입 반영 ≤ 1라운드 경계 *(제안 — 설계 질문 6의 개입 시점 모델 확정과 연동)*, 개입 반영 후 상태 불일치 **0건 (절대)** — 무승인 확정의 판정은 QA-OC-1 소관 | ENV-A | 임의 라운드에 스크립트된 개입(중단·조건 변경·거절) 주입 → 반영 시점·전 참여자 상태 일관성 확인 |
| **QA-AD-1** 적응성 — 시나리오 가변성 수용 (Adaptability) | 신규 협상 시나리오 수용 시 코드 변경량(변경 파일·라인 수)과 수용 소요 시간 — 프로세스 템플릿·설정 정의만으로 실행 가능한지 | 사전에 정의하지 않았던 대표 신규 시나리오 2종 이상을 **코드 변경 0으로** 템플릿·설정만으로 수용 *(제안 — 시나리오 표본은 팀 선정)* | ENV-A | 설계 시 참조하지 않은 신규 시나리오(예: 라운드별 주제 전환형, 승인자 부분 완결형)를 프로세스 템플릿(CFR-I3)으로 작성 → 실행 성공 여부와 코드 diff 확인 |

### 기반 QA (1차 드라이버의 실현 기반 — [`08`](08-핵심-QA-중요도-난이도-평가.md) §8.3)

## 10.4 QA-FC-2 — 효용 분배 균형 (Utility Distribution Balance, Functional Correctness 매핑)

| 항목 | 내용 |
|---|---|
| 측정 지표 | 단일 협상: 확정 합의안의 참여자별 효용 분포(최소 효용·분산). 반복 협상: 동일 그룹 반복 실행에서 참여자별 누적 효용·1순위 채택률의 편향 추세 |
| 목표 수준 | 특정 참여자의 체계적 우위가 통계적으로 유의하지 않을 것 *(제안 — 구체 지표·유의 기준은 팀 결정, [`09`](09-Functional-Correctness-정의.md) §9.7)* |
| 환경·방법 | ENV-A — 동일 선호 구성을 역할만 바꿔(개시자 로테이션) 반복 실행 → 역할·양보 속도에 따른 효용 편향을 대조. 완결 규칙(전원/다수결/부분)별로 비교해 CFR-B9 설계 입력으로 사용 |

## 10.5 운용 원칙·미결정

1. **측정의 전제**: 본 계획의 전 항목은 ENV-A(Mock·기록 재생)의 성립을 전제한다 — 시험 용이성(QA-TE-1)이 자체 절대 기준(커버리지·재현율 100%)을 갖는 이유다.
2. **QAS 연계**: QAS 작성 시 각 QA ID를 "자극(주입 이벤트) → 환경(ENV-A/B/C) → 응답 측정(지표·목표)"으로 전개한다 — QA ID가 QAS ID의 상위 키가 된다.
3. **미결정** (팀 논의): ① *(제안)* 표기 목표치의 확정(베이스라인 실측 후), ② 역추론 공격자 모델(QA-CF-2)의 정의, ③ 효용 분배 균형(QA-FC-2)의 구체 지표, ④ L1 라벨 데이터셋의 구축 주체·규모.
