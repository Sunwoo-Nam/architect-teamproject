# 53. FR 재도출 — 협상 범위 한정, VoC 매핑

> **배경**: [`52`](52-Stakeholder-재편-VoC.md)의 재편 Stakeholder·VoC로부터 FR을 재도출한다 (사용자 지시, 2026-08-13).
> **작성 원칙**:
> ① **협상 내용과 관련된 기능만** 포함한다 (과제 관리·개발 지원·학습 루프는 52 §52.3 보류).
> ② **해법 중립** — "설계를 다르게 골랐다면 무효가 되는 문장"은 FR이 아니다. 요구는 결과(무엇이 보장되어야 하는가)로 쓰고, 방법(어떻게)은 DP로 내려보낸다. 이 원칙으로 배제·재작성한 내역은 §53.2.
> ③ 각 FR은 근거 VoC 인덱스를 표기한다 (1:1일 필요 없음).
> **기존 문서와의 관계**: [`../04-FR.md`](../04-FR.md)(FR-IDS/FR-MAF 체계)·[`02`](02-Stakeholder별-FR-도출.md)(구 Stakeholder 100건)와 별개의 신규 도출이다. 정제 완료 후 정본 관계를 정리한다.

## 53.1 FR 목록 — 17건 (협상 라이프사이클 순, 결번 10건은 §53.1.1)

> FR-26·27은 2026-08-14 추가분으로 단계 순 배치를 위해 ID가 오름차순과 어긋난다 (리넘버링 추후).

| ID | 단계 | Functional Requirement | VoC 매핑 |

| FR-02 | 개시 | 시스템은 초대를 수신하고 참여를 수락·거절하는 기능을 제공해야 한다 | EU-V2, EU-V4 |
| FR-03 | 개시 | 시스템은 위임 범위·수락 바닥선·정보 공개 범위를 사전 설정하는 기능을 제공해야 한다 | EU-V2, EU-V3, SP-V1 |
| FR-04 | 선호 | 시스템은 사용자 선호·제약을 수집해 협상에 반영하는 기능을 제공해야 한다 | PD-V2 |

| FR-10 | 수행 | 시스템은 의제 도메인에 필요한 조회·실행 능력을 동적으로 구성하는 기능을 제공해야 한다 *(동적 Agent·Tool 생성 — 과제 제약·검증 가설 연계, [`../02-과제-개요.md`](../02-과제-개요.md) §2.7)* | SA-V2 |

| FR-13 | 관찰·개입 | 시스템은 진행 중 사용자 개입(중단·조건 변경·거절)을 받아 협상에 반영해야 한다 *(반영 지연 상한은 [`54`](54-QAS-재도출.md) QAS-11 소관)* | EU-V2, EU-V4 |

### 53.1.1 결번 — 병합·QAS 이동 내역 (2026-08-14, 리넘버링은 추후)

중복 정제 병합 4건 + FR 재검토에 따른 QAS 이동 6건. 이동 기준: **시스템이 제공하는 기능이 아니라 지켜야 할 품질·속성("~하지 않아야 한다", "~이내여야 한다")이면 QAS 소관.**

| 결번 ID | 병합처 | 사유 |
|---|---|---|
| FR-06 | FR-05 | "확인·교정"과 "열람·수정·삭제"는 동일 행위 — 선호 데이터 통제권 1건으로 통합 |
| FR-15 | FR-11 | 확정 효력 조건은 완결 규칙 판정의 일부 — "합의 확정" 규정 1건으로 통합 |
| FR-16 | FR-12 | 진행 중/사후 조회는 시점만 다른 같은 기능. 판단 근거의 열람은 FR-12, 기록 생성은 FR-22로 일원화 |
| FR-18 | FR-17 | 이상 상황 완결과 장애 후 재개는 모두 "비정상 상황에서의 보장" — 1건으로 통합 |
| FR-08 | [`54`](54-QAS-재도출.md) QAS-03 | 품질 요구(자동 수락 차단) — QAS-03과 VoC(EU-V2·SP-V1)·보장 내용 동일. 바닥선 문구는 QAS-03 시나리오에 병합 |
| FR-09 | [`54`](54-QAS-재도출.md) QAS-01 | 실현 가능성은 FC의 L2 계층([`09`](09-Functional-Correctness-정의.md)) — QAS-02가 L4를 흡수한 방식과 동일. SA-V1은 QAS-01 매핑으로 이관 |
| FR-17 | [`54`](54-QAS-재도출.md) QAS-09·10 | Reliability 속성 — 이상 상황 완결은 QAS-10, 복구·재개는 QAS-09와 VoC 중복. SD-V1은 QAS-10 매핑으로 이관 |
| FR-19 | [`54`](54-QAS-재도출.md) QAS-12·15 | Confidentiality 속성 — VoC(EU-V3·V8, SP-V4, PD-V4)가 QAS-12·15와 완전 중복 |
| FR-20 | [`54`](54-QAS-재도출.md) QAS-16 (신설) | Security 속성 — 권한 초과 접근 차단은 접근 통제 품질 |
| FR-21 | [`54`](54-QAS-재도출.md) QAS-17 (신설) | Security 속성 — 상호 인증·암호화는 메커니즘, 보장할 품질은 위장·변조의 감지·차단 |

## 53.2 해법 중립 원칙의 적용 내역

요구가 설계 후보를 죽이는 사고를 막기 위해 배제·재작성한 내역. 판정 기준: **"설계를 다르게 골랐다면 이 문장이 무효가 되는가."**

| 항목 | 처리 | 사유 |
|---|---|---|
| "제안 생성→수락/거절→역제안" (교대 제안 사이클) | FR-07로 재작성 | 교대 제안은 특정 프로토콜. dp2-nparty 실측에서 FC 최고(★5)인 방안 3-A(일괄 순위·중앙 선별)는 역제안 사이클이 없다 — 원안대로면 최고 성능 설계가 요구 위반이 됨 |
| "라운드 경과에 따른 양보 전략 실행" | [`54`](54-QAS-재도출.md) QAS-03으로 대체 | 양보 곡선은 수렴 메커니즘(설계). 요구의 본질은 "바닥선 미만 자동 수락 금지" — 품질 요구로서 QAS-03에 병합 (구 FR-08) |
| "전 참여자 협상 상태 동기화" | 삭제 (FR-11·FR-17·QAS-02로 커버) | 상시 동기화는 수단. 보장할 결과는 종결 시 전원 동일 + 중단 후 유효 재개 |
| "모델 출력 검증 후 반영" | 삭제 → [`54`](54-QAS-재도출.md) QAS-14로 이동 | "검증 계층"은 해법. 요구의 본질은 "모델 오류가 정확성을 훼손하지 않는다"는 품질 요구 |
| "Ufun 입력으로 정규화·공급" 등 해법 어휘 | FR-04·07 및 [`54`](54-QAS-재도출.md) QAS-03에서 중립 표현으로 재작성 | Ufun·threshold는 NegMAS(선택한 해법)의 내부 개념 — 설계 문서·DP에서 등장할 어휘 |
| Sub-Agent 계층·동적 생성·A2A·서버 Orchestrator | FR에서 지우지 않고 제약으로 연결 | 우리가 고른 설계가 아니라 **과제 설명서가 부여한 제약** ([`../02-과제-개요.md`](../02-과제-개요.md) §2.3·§2.7) — [`../06-Constraints.md`](../06-Constraints.md) 소관 |

## 53.3 커버리지 점검

- 보류 8건([`52`](52-Stakeholder-재편-VoC.md) §52.3)을 제외한 VoC 46건 중 FR 또는 QAS([`54`](54-QAS-재도출.md))에 매핑되지 않은 항목: **0건**
- 구현 대응 참고(추적성): FR-04 → Ufun 구성 · FR-07 → 협상 프로토콜(DP01 계열) · QAS-03([`54`](54-QAS-재도출.md)) → threshold 판정 · FR-11 → 완결 규칙([`32`](32-완결-규칙-실행-구조.md)) — 해법 어휘는 설계 문서에서만 사용한다
