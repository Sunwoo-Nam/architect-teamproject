# 29-1. QA 측정 핸드북 — 전 측정 항목 통합 참조

> 지위: **측정을 수행할 때 보는 단일 참조 정본**이다. [`24`](24-Functional-Correctness-정의-측정.md)-[`29`](29-Confidentiality-정의-측정.md)의 측정 정의를 하나로 통합하고, 미문서화 항목(Time Behaviour · Message 전송 횟수 · Message 전송 크기 · Analysability)을 같은 형태로 추가했다. 각 항목의 도출 과정·근거 논증은 원 문서(24-29)에 있다 — 본 문서와 원 문서가 어긋나면 본 문서를 따르고 어긋남을 결함으로 보고한다.
> 공통 원칙: 별점은 점추정으로 정하고 95% 신뢰구간 병기, CI가 3개 이상 등급에 걸치면 표본 확대. 게이트(유효 조건) 위반 시 0점 + 결함 보고. 대안 비교는 동일 하니스·동일 시드·동일 프로파일에서 대안만 교체. 측정값은 이 문서가 아니라 `poc/*/results/`에 기록한다.

## A. 핵심 QA (23번 우선순위 순)

### A1. Functional Correctness (기능 정확성) — 핵심 1위 · 원 문서 [`24`](24-Functional-Correctness-정의-측정.md)

- **정의**: 협상이 도달한 결과(합의 또는 결렬)가, 도달할 수 있었던 가장 좋은 결과에 얼마나 가까운가.
- **핵심 지표**: **Total Utility 달성률** = U(r) ÷ U(x\*). x\* = 결렬 포함 전 후보 중 [전원 utility ≥ initial threshold]를 만족하는 후보 중 total utility 최대. 결렬 후보의 utility = 각자의 initial threshold.
- **별점**: 개선 비율 s = (달성률 − R̄) ÷ (1 − R̄). R̄ = 유효 후보 중 무작위 선택 전략의 평균 달성률(같은 표본에서 산출).

| 별점 | s | | 별점 | s |
|---|---|---|---|---|
| 5점 | 0.8 초과 | | 2점 | 0.2 초과 - 0.4 이하 |
| 4점 | 0.6 초과 - 0.8 이하 | | 1점 | 0 초과 - 0.2 이하 |
| 3점 | 0.4 초과 - 0.6 이하 | | 0점 | 0 이하 — 무작위만도 못함, 즉시 결함 |

- **측정 방법**: ENV-A. 정답 프로파일(선호·initial threshold) 봉인 — 채점기만 전체를 본다(순환 차단). 기준 3인 100회 + 5·7인 보조. 표본에 "정답이 결렬인" 케이스 일정 비율 포함. 같은 표본에서 무작위 베이스라인 동시 실행.
- **경계**: initial threshold 미만 수락·제약 위반·레코드 불일치는 FR 합격 조건(달성률과 무관하게 판정). revised threshold는 채점 기준이 아니라 채점 대상.

### A2. Resource Utilization-메모리 (자원 효율성) — 핵심 2위 · 원 문서 [`26`](26-Resource-Utilization-정의-측정.md)

- **정의**: 온디바이스 LLM과 협상을 함께 실행할 때 앱 프로세스가 사용하는 Peak RSS와 Average RSS.
- **핵심 지표**: **Peak RSS** (프로세스 한도 준수 판단) · **Average RSS** (설계 대안의 지속 효율 비교). 비LLM 몫 = (LLM+협상 측정값) − (LLM-only 측정값), 동일 모델·prompt·조건에서.
- **목표**: Peak RSS < L_state (단말에서 실측한 프로세스 한도 — `adb shell am memory-limiter status`). Average RSS는 낮은 대안 우수 — **별점 척도 미확정** (근거 없는 고정 비율을 쓰지 않는다는 26의 방침), 상대 비교로 판정.
- **측정 방법**: ENV-B 실기기 (주: Galaxy S25 FE 8GB, Not-visible 상태). LLM-only → LLM+협상 각 5회, Peak는 최댓값·Average는 평균. 최대 정상 협상(최대 참여자·의제·후보) 조건 고정. 개발 단계 대체: ENV-A tracemalloc(관찰 로그 제외) — 상대 비교만.
- **경계**: 증가 추세는 A3·A4 소관. OOM 강제 종료 금지는 FR.

### A3. Scalability-참여자 수 (확장성) — 핵심 3위 · 원 문서 [`25`](25-Scalability-참여자수-정의-측정.md)

- **정의**: 참여자 수 N이 늘 때 협상 1회의 통신량이 N에 비례하는 수준을 넘지 않는가.
- **핵심 지표**: **메시지 확장 지수 b_msg** — M_N(세션 1회 물리 전송 총 건수의 중앙값, B1 규약) ∝ N^b_msg 의 log-log 회귀 기울기.
- **별점** (선형 1 - 제곱 2 를 5등분):

| 별점 | b_msg | | 별점 | b_msg |
|---|---|---|---|---|
| 5점 | 1.0 이하 | | 2점 | 1.4 초과 - 1.6 이하 |
| 4점 | 1.0 초과 - 1.2 이하 | | 1점 | 1.6 초과 - 1.8 이하 |
| 3점 | 1.2 초과 - 1.4 이하 | | 0점 | 1.8 초과 — 사실상 제곱 |

- **게이트**: 완결률이 N 증가에 유의 저하(N 최소 vs 최대, 비율 차 검정 95%)하면 0점 + 결함 — "빨리 실패해서 지수가 좋아지는" 왜곡 차단.
- **측정 방법**: ENV-A. N ∈ {3, 4, 5, 6, 8, 10} 각 30회 이상(상한 10은 정책 상한 — 외삽 금지). **난이도 교락 통제 필수**: 공통 feasible 후보 k개를 N과 무관하게 고정(역방향 프로파일 생성). 정상 완결 세션만 집계. R² < 0.9면 멱 모형 재검토.
- **경계**: 절대 시간은 B1, 절대 메모리는 A2, 의제 추세는 A4.

### A4. Scalability-의제 수 (확장성) — 핵심 4위 · 원 문서 [`27`](27-Scalability-의제수-정의-측정.md)

- **정의**: 의제가 늘어 후보 조합 S(의제별 후보 수의 곱)가 커질 때, 메모리가 S에 정비례하지 않고 완만하게 자라는가.
- **핵심 지표**: **조합-메모리 탄력성 c** — 피크 메모리 ∝ S^c 의 log-log 회귀 기울기.
- **별점** (전체 열거 1 - 이론 이상 1/d 를 5등분, 기준 d=4):

| 별점 | c | | 별점 | c |
|---|---|---|---|---|
| 5점 | 0.40 이하 | | 2점 | 0.70 초과 - 0.85 이하 |
| 4점 | 0.40 초과 - 0.55 이하 | | 1점 | 0.85 초과 - 1.00 이하 |
| 3점 | 0.55 초과 - 0.70 이하 | | 0점 | 1.00 초과 — 전체 열거 이상 |

- **게이트**: A3과 동일한 완결률 게이트 (S 최소 vs 최대).
- **측정 방법**: 후보 = **복합의제(multi-issue) 튜플의 곱집합** (단일 의제의 후보 수 확장이 아님). S 로그 등간격 6단계, 의제 수 d 2-5 동반 확장. 피크 메모리는 협상 시작 전 대비 증가분, 하니스 부가 할당(관찰 로그) 제외. 정본 ENV-B, 개발 대체 ENV-A(tracemalloc). 수준당 5회 이상 중앙값.
- **경계**: 절대 수준은 A2 소관 — 본 축은 기울기만.

### A5. Fault Tolerance & Recoverability (신뢰성) — 핵심 5위 · 원 문서 [`28`](28-Fault-Tolerance-Recoverability-정의-측정.md)

관리 항목 1개, 측정 하위 축 2개(자극이 다름). **통합 별점 = 두 하위 축 중 낮은 값** (약한 고리).

**A5-1. FT — 내성 여유 배수**: 주입 강도 스윕에서 완결 분포(합의/정상 결렬 구성비)가 무주입 베이스라인 대비 유의 저하되기 시작하는 임계 강도 ÷ 실환경 실측 오류율.

| 별점 | 배수 | | 별점 | 배수 |
|---|---|---|---|---|
| 5점 | 10배 이상 | | 2점 | 1.8 - 3.2배 |
| 4점 | 5.6 - 10배 | | 1점 | 1 - 1.8배 |
| 3점 | 3.2 - 5.6배 | | 0점 | 1배 미만 — 실환경에서 이미 저하 |

- 방법: ENV-B에서 실환경 오류율 실측(앵커) → ENV-A 무주입 100회 → 강도 1×-50× 각 50회 주입(오류 카탈로그 구성비 고정) → 임계 강도 판정(95% CI 분리). 구성비 판정이라 "즉시 결렬" 퇴화 전략이 걸러진다.

**A5-2. REC — 복구 시간 비율**: 강제 중단 후 복구 소요 ÷ 정상 라운드 1회 시간. 복구 성공·전원 상태 일치는 FR(실패 = 결함, 집계 제외) — QA는 성공한 복구의 비용만 잰다.

| 별점 | 비율 (R = 정상 세션 총 라운드 수 중앙값 = 재시작 비용) |
|---|---|
| 5점 | 1 이하 (한 라운드 이내) |
| 4점 - 1점 | 1 - R 구간의 로그 4등분 (경계: R^(1/4), R^(1/2), R^(3/4), R) |
| 0점 | R 초과 — 재시작보다 비쌈 |

- 방법: ENV-A. 중단 유형 {프로세스 강제 종료, 네트워크 단절} × 시점 {라운드 중, 승인 수집 중, 확정 절차 중} 그리드 각 10회. "처음부터 재시작"으로 살아난 것은 FR 실패 — 재는 것은 재개(resume)다.

## B. 비핵심 QA · 보조 관측 (측정은 유지 — 판정 아닌 감시·비교용)

### B1. Time Behaviour (시간 효율성) — 비핵심 6위 · 원 정의 [`21`](21-핵심-QA-측정-정의.md) §21.3-6

- **정의**: 합의 도달까지의 총 시간이 짧은가.
- **정본 지표 (ENV-B)**: **프로토콜 오버헤드 비율** = 실측 합의 시간 ÷ 필수 추론 시간 합(같은 세션 로그에서 동시 수집). 참고 기준 ≤ 2 ("프로토콜이 얹는 시간이 본질 작업 이하"). 추론 호출 횟수 병기(분모 부풀리기 검출).
- **ENV-A 대체 지표**: **직렬 통신 단계(phase) 수** — "앞 단계 메시지가 도착해야 다음으로 넘어가는 단계" 1회. 같은 단계의 병렬 메시지는 1단계다(제출 N-1건 동시 = 1 phase). 체감 시간 ≈ phase 수 × 왕복 지연이므로, 라운드 수보다 시간에 가깝다 — **라운드 수 비교는 방안별 라운드 구성이 달라 왜곡되므로 쓰지 않는다**. 세션당 총 phase 수의 중앙값으로 상대 비교.
- **별점**: 미확정 — 비핵심이므로 상대 비교(낮은 쪽 우수)로 운용.

### B2. Confidentiality (기밀성 — 역추론 방지) — 비핵심 7위 · 원 문서 [`29`](29-Confidentiality-정의-측정.md)

- **정의**: 협상 관찰만으로 다른 참여자의 1순위를 알아낼 수 없는가.
- **핵심 지표**: **정규화 노출률** = 역추론 이득 ÷ 최대 이득(1 − 1/M). 공격자 = frequency 상대 모델(규칙 고정·봉인 — `poc/dp2-nparty/src/dp2_nparty/measures/confidentiality.py`).
- **별점**: 유계 [0, 1]을 6등분 — 5점 ≤ 1/6 … 0점 > 5/6. 관점 2개: **일반 참여자 관찰자(판정)** / Blackboard 담당자(병기 — 노출 집중 감시).
- **측정 방법**: ENV-A 100회, 관점별 가시 이벤트만 공격자 입력(각자 정당하게 보이는 것). 신호 없으면 무작위 기대 정확도(1/M)로 계산.
- **목표의 지위**: 감시선 — 미달해도 설계 기각 아님, 리스크로 보고 ([`23`](23-핵심-QA-최종-확정.md) §23.3).

### B3. Analysability (분석 용이성) — 비핵심 8위 · 원 정의 [`21`](21-핵심-QA-측정-정의.md) §21.3-3

- **정의**: 기록만으로 협상의 인과를 재구성할 수 있는가.
- **핵심 지표**: **인과 재구성 성공률** (건당 30분 한도) — 표본 40건 = 정상 세션 20(과제: 합의를 성립시킨 결정 요인과 각자의 효용 근거) + 결함 주입 세션 20(과제: 원인 3요소 — 어느 라운드·어느 참여자·어느 처리 단계). 결렬 세션에서는 "어느 참여자가 어떤 후보를 막았나"의 특정을 과제에 포함한다.
- **참고 기준**: ≥ 95% (표본 40건 중 실패 2건 이내 — 초과 시 기록 체계의 구조적 사각 신호). 별점 척도 미확정 — 비핵심이므로 상대 비교로 운용.
- **측정 방법**: ENV-A. 주입자·진단자 분리(블라인드), 진단자에게 로그만 제공(코드·내부 접근 금지). 정답은 시뮬레이션 내부 기록으로 봉인. 부분 정답은 실패로 세되 보조 기록.
- **전제(FR)**: 결정 지점 기록 완전성(입력·utility·threshold·적용 규칙) — CFR-H2.

## C. 관측량 (QA 지표의 원자료 — 자체 별점 없음)

### C1. Message 전송 횟수

- **정의**: 세션 시작-종결 사이에 발생한 A2A 메시지의 **물리 전송 건수**. 브로드캐스트 1회 = 수신 단말 수만큼(N-1건). Blackboard 담당자 자신의 제출·투표는 로컬 = 0건.
- **집계 범위**: 제안·응답뿐 아니라 라운드 제어·판정 배포·ACK·동기화까지 **세션 중 전체** — 대안별 제어 오버헤드 차이를 잡기 위해.
- **측정 방법**: ENV-A에서 하니스가 프로토콜 경계에서 센다(대안 내부 비의존). 대안별 전송 매핑 표를 실험 설계서에 고정한다 (예: `poc/dp2-nparty/README.md`의 매핑 v1).
- **용도**: A3(b_msg)의 원자료 + 절대 통신량 비교(온디바이스 라디오·배터리 비용의 대리). 노드별 처리 건수의 최대÷평균(부하 편중 추세)도 함께 기록.

### C2. Message 전송 크기 (신설 — 분석자 제안, PL 확정 전 잠정)

- **정의**: 세션 중 전송된 **총 페이로드 바이트** = Σ(전송 건수 × 건당 직렬화 크기). 직렬화 규약(JSON 등)을 실험 설계서에 고정해야 대안 간 비교가 성립한다.
- **왜 필요한가**: 건수 지표(C1)의 사각 — 라운드 반복 없이 목록을 한 번에 보내는 구조(일괄 제출형)는 건수는 적지만 건당 크기가 후보 수에 비례한다. 건수만 보면 이런 대안이 부당하게 유리해진다.
- **측정 방법**: ENV-A에서 메시지 직렬화 시점에 바이트 수를 계상(결정적). 세션당 총 바이트의 중앙값으로 비교하고, 필요시 N·S에 대한 확장 추세(log-log 회귀)를 보조 산출.
- **용도**: C1과 쌍으로 통신 비용의 두 얼굴(횟수 = 라디오 기동, 크기 = 대역·전력)을 재는 원자료.

### C3. 직렬 통신 단계(phase) 수

- B1의 ENV-A 대체 지표와 동일 항목 — 정의·셈법은 B1 참조. C1(건수)·C2(크기)와 함께 통신 비용의 세 축(횟수·크기·직렬 깊이)을 이룬다: 건수 = 배터리, 크기 = 대역, phase = 체감 시간.
