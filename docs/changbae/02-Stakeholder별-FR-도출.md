# 2. Stakeholder별 Functional Requirements 도출 (10명 × 10개) — 다자간 협상 범위

> **FR 기술 형식**: *"시스템은 ~하는 기능을 제공해야 한다"* 형태로 기술한다 (QA와 달리 기능).
> **범위**: 다자간 협상 — NegMAS 기반 효용·threshold 교대 제안 프로토콜의 N-party 확장 ([`01`](01-Stakeholder-도출.md)).
> **독립 도출 원칙**: 기존 요구사항 문서를 참고하지 않고 VOC(03·annex 원본표)와 과제 설명(01·02·annex 시나리오)만을 근거로 한다.
> 순위(1~10)는 해당 역할 관점의 상대적 중요도(분석자 판단). 분류(A~J)는 [`03`](03-FR-카테고리-정리.md)의 기능 카테고리.
