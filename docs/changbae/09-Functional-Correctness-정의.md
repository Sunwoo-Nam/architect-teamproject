# 9. Functional Correctness의 정의 — 다자간 협상 범위

> 배경: PL 지시 ① (2026-08-04) — *"Functional Correctness가 가장 중요한 QA이며, 이를 어떻게 정의할 것인지도 함께 고민할 것."*
> PL 지시 ② (2026-08-05) — *"1차적 정의는 '내 선호를 잘 반영했는가'. 2차적으로 'N명의 선호가 잘 반영되었는가'는 공정성 문제인데, 이를 Functional Correctness로 분류할지 다른 QA로 분류할지 판단이 필요함. 둘을 하나로 묶을 수는 없음."*
> PL 지시 ③ (2026-08-05) — *"Ufun(효용 함수)은 잘 만들어져 있다고 가정한다. 이런 알고리즘은 우리가 만드는 것이 아니다."*
> PL 지시 ④ (2026-08-05) — *"시나리오에 따라 다수결·전원 승인·승인자만 추려 완결 등 완결 규칙이 다양하며, 이를 모두 수용해야 한다."*
> PL 지시 ⑤ (2026-08-05) — *"결정된 사항의 실행은 과제 범위 밖(외부 앱 연동 기능). L4는 '모두가 동일한 결과로 협상이 종료되었는가'의 측면이라면 중요하며, 그렇다면 이름이 바뀌어야 한다."*
> PL 지시 ⑥ (2026-08-05) — *"모든 QA는 ISO/IEC 25010 QA로 매핑할 것. 임의의 비표준 QA를 만들지 말 것. 같은 Functional Correctness로 정의하더라도 별개의 QA ID로 배정할 수 있다."*
> 범위: 다자간 협상 — NegMAS 기반 효용·threshold 교대 제안 프로토콜의 N-party 확장.
> 본 문서는 위 지시에 대한 **확정 제안**이며(결론: §9.6), 팀 합의로 채택된다.

## 9.1 왜 별도의 정의가 필요한가

**ISO/IEC 25010:2023의 Functional Correctness**는 대략 *"제품이 필요한 정밀도로 정확한 결과를 제공하는 능력"* 이다(개념 수준 요약). 이 정의는 "정답이 존재하고 비교 가능하다"를 전제하는데, 다자 협상 시스템에서는 그 전제가 다섯 가지 이유로 성립하지 않는다.

| # | 어려움 | 내용 |
|---|---|---|
| 1 | **LLM 비결정성** | 같은 입력에도 다른 출력. "출력 = 기대값" 비교 판정 불가 |
| 2 | **정답의 복수성** | 그룹 합의는 단일 정답이 없음 — 전원 threshold를 넘는 합의안이 여럿 존재 가능 |
| 3 | **판정 주체의 주관성·다수성** | '맞았는지'는 참여자 각자의 의도·선호로만 판정 가능하며, **판정 주체가 N명** |
| 4 | **공정성과의 경계** | 전원이 threshold를 넘겼어도 효용 분배가 특정 참여자에게 체계적으로 유리하면 나머지는 "불공평하다"고 인식 — 이것이 정확성(개인 관점)의 문제인지 별도 품질의 문제인지 경계를 정해야 함 (→ §9.2에서 분리 결론) |
| 5 | **전원 종결 정합** | 협상이 종료될 때 확정 당사자 모두가 **동일한 합의 결과**를 갖고 있어야 함 — 1명이라도 다른 결과를 갖고 종료되면 이후 각자의 실행이 실세계에서 충돌 (시나리오 6 "이중 확인" 문제의 일반형). 합의의 실행 자체(캘린더 등록 등 외부 앱 연동)는 과제 범위 밖 (PL 지시 ⑤) |

또한 "크래시 없이 끝났다"(기술적 성공 — Reliability의 몫)와 "의도에 맞는 결과"(내용적 정확성)는 별개의 축이므로, Functional Correctness는 후자만 겨냥해야 측정이 겹치지 않는다.

## 9.2 정의의 구조 — 1차(개인 관점)와 2차(그룹 관점)의 분리

PL 지시 ②에 따라 두 관점을 분리하고, 각각의 귀속을 다음과 같이 **판단·확정**한다.

| 관점 | 질문 | 판정 주체·단위 | 분류 판단 |
|---|---|---|---|
| **1차 — 개인 정확성** | 시스템이 **나의** 의도·제약·선호를 맞게 반영해 협상·종결했는가 | 참여자 **개인별** — 단일 협상 1건으로 판정 가능 | **Functional Correctness로 확정** (§9.3의 4계층) |
| **2차 — 그룹 공정성** | **N명의** 선호가 서로 **고르게** 반영되었는가 (분배의 문제) | **그룹 단위** — 단일 협상으로 판정 곤란, 반복 협상의 분배 추세로 판정 | **같은 하위특성(Functional Suitability — Functional Correctness)에 매핑하되, 별개 QA 항목 QA-FC-2 "효용 분배 균형(Utility Distribution Balance)"** 으로 분리 (§9.4). 하나의 QA 항목으로 합산하지 않는다 (PL 지시 ②·⑥) |

**분리 근거 (분석자 판단)** — 두 관점은 하나의 지표로 묶을 수 없다:

1. **판정 주체가 다르다.** 1차는 참여자 각자가 자기 기준으로 판정하지만("내 주말 선호가 반영됐나"), 2차는 개인이 판정할 수 없고 그룹 전체의 효용 분포를 관찰해야 판정된다.
2. **측정 층위가 다르다.** 1차는 협상 1건에서 측정 가능하지만, 2차의 "체계적 편향"은 반복 협상에 걸친 추세로만 드러난다 (한 번은 누군가 양보하는 것이 정상이다).
3. **서로 트레이드오프 관계다.** 전원이 개인 기준(threshold)을 만족해도 분배는 편향될 수 있고, 반대로 공정성을 높이는 집계 규칙이 특정 개인의 효용을 낮출 수 있다. 한 지표로 합산하면 두 실패 모드가 서로를 상쇄해 측정이 무의미해진다.
4. **분류 방식.** 모든 QA는 ISO/IEC 25010 체계에 매핑한다 (PL 지시 ⑥). 공정성은 "합의 결과가 그룹 관점에서도 맞는가"의 문제이므로 하위특성 수준에서는 **Functional Suitability — Functional Correctness에 귀속**하되, 위 1-3의 이유로 하나의 QA 항목으로 합산하지 않고 **별개 QA ID — QA-FC-1(개인 관점) / QA-FC-2(그룹 분배 관점)** — 로 분리 관리한다.

## 9.3 1차 정의 — QA-FC-1: Functional Correctness의 4계층 (확정 제안)

**"정확함"을 하나의 수치로 정의하지 않고, 의도 감지 → 효용 구성 → 다자 협상 → 합의 종결 파이프라인의 계층마다 "무엇이 틀릴 수 있는가"로 분해**하여, 계층별 성격에 맞는 판정 방식을 부여한다.

> Functional Correctness = **의도 정확성(L1) ∧ 제약 준수(L2) ∧ 선호 정합(L3) ∧ 합의 종결 정합(L4)**
> — 각 참여자 개인 관점에서 판정하며, 어느 한 계층이라도 틀리면 그 참여자는 "Agent가 틀렸다"고 인식한다.

### L1. 의도 정확성 (Intent Correctness) — 그룹 조율 의도를 맞게 읽었는가

| 항목 | 내용 |
|---|---|
| 정의 | 시스템이 감지한 그룹 조율 의도(누구와·무엇을·언제까지 합의해야 하는가)가 사용자의 실제 의도와 일치한다 |
| 오류 예 | "우리 언제 볼까?" 단톡 대화에서 참여자 구성을 잘못 식별 / 의도 없는 잡담에서 협상을 개시(오탐) |
| 판정 방식 | **통계적** — 정답 라벨 기준 분류 정확도·오탐률 + 실사용 프록시(선제 제안 수락률·무시율) |
| 근거 | 02 §2.6 1단계 (Intent 감지), 협상 알고리즘 담당 VOC "Intent 품질이 떨어지면 전부 헛수고" |

### L2. 제약 준수 (Constraint Correctness) — 전원의 경계를 지켰는가

| 항목 | 내용 |
|---|---|
| 정의 | 협상 과정과 합의안이 **N명 각각의 결정적으로 검증 가능한 경계(hard constraint)** 를 위반하지 않는다: 각자의 위임 정책 범위·캘린더 물리 충돌·예산 상한·공유 금지 데이터·프로토콜 규칙. **threshold를 넘는 후보라도 위임 범위 밖이면 수락 불가** (이중 검사) |
| 오류 예 | 참여자 B의 위임 예산을 넘는 금액 합의 / C의 확정 일정과 겹치는 시간 합의 / 공유 금지 정보가 포함된 제안 브로드캐스트 |
| 판정 방식 | **결정적** — 규칙 엔진으로 참여자별 기계 검증. 목표는 **전 참여자 기준 위반 0건** |
| 근거 | 개시 사용자 VOC "마음대로 결정이 제일 무서움", 보안·프라이버시 VOC "단 한 건의 초과도 불가" |

### L3. 선호 정합 (Preference Correctness) — 나에게 좋은 선택이었는가

| 항목 | 내용 |
|---|---|
| 정의 | 합의안이 (a) 기제공 Ufun에 내 선호·제약이 올바르게 입력·통합된 상태에서, (b) 내 threshold를 넘는 — 즉 **내가 받아들일 만한** — 선택이다. (그룹 간 분배의 문제는 여기 포함하지 않는다 → §9.4 효용 분배 균형) |
| 오류 예 | 선호 입력·통합 오류로 사용자의 "주말 선호"가 Ufun에 전달되지 않아 평일이 고득점 처리됨 / threshold 계산 오류로 수용 불가 안을 자동 수락 |
| 판정 방식 | **통계적 + 사용자 판정** — 수용성 중심: **무수정 승인율**·수정률·거부율·재협상 요구율. Ufun 구성 알고리즘 자체는 기제공·품질 확보 가정(PL 지시 ③)이므로 알고리즘 내부의 정합 검증은 범위 외 — 단, 선호 입력→Ufun 통합 경로의 오류는 무수정 승인율 하락으로 드러나므로 수용성 지표가 통합 오류의 검출 수단을 겸한다 |
| 근거 | 원본표 "결과 만족도", 01 §1.4.1 "결정 품질" — (a)(b) 분해는 분석자 도출 |
| NegMAS 대응 | (a) = 선호 데이터의 Ufun 입력·통합 (알고리즘은 기제공), (b) = threshold(aspiration/reservation 수준) 판정 |

### L4. 합의 종결 정합 (Agreement Closure Consistency) — 전원이 동일한 결과로 협상이 종료되었는가

| 항목 | 내용 |
|---|---|
| 정의 | 협상이 종료되는 시점에 **확정 당사자 전원이 동일한 최종 합의 레코드를 보유·확인(ACK)** 하고 있으며, 승인하지 않은 참여자에게는 확정 레코드가 효력을 갖지 않는다. "확정 당사자"는 시나리오의 완결 규칙(전원 승인·다수결·승인자 부분 완결 — PL 지시 ④)에 따라 확정에 참여한 참여자들이다 |
| 범위 주석 | **합의의 실행(캘린더 등록·예약 등 외부 앱 연동)은 과제 범위 밖이다** (PL 지시 ⑤ — 별도 연동 기능에서 담당). 본 시스템의 책임은 "전원 동일한 합의 레코드로 종결하고 실행 계층에 인계"까지이며, 여기가 틀리면 이후 실행이 아무리 정확해도 실세계 충돌이 발생하므로 종결 정합 자체는 핵심 계층으로 유지한다 |
| 오류 예 | 종료 시점에 개시자는 "토요일 18시", 참여자 한 명은 "토요일 17시"를 최종 합의로 보유 / 서로 다른 장소가 각자의 합의 레코드에 기록됨 / 승인하지 않은 참여자에게 확정 레코드가 전파되어 효력 발생 |
| 판정 방식 | **결정적** — 종결 시점에 확정 당사자 전원의 합의 레코드를 기계 대조. 목표 **확정 당사자 간 불일치 0건**. 미승인자에 대한 효력 차단은 정의의 일부이나, 그 판정·측정은 운용 제약 준수(QA-OC-1)로 단일 귀속한다 (이중 계상 방지) |
| 근거 | 시나리오 6 "확정 정보를 N명에게 전파하고 승인을 얻는 이중 확인(Double Confirm)" — 범위 재정의는 PL 지시 ⑤ |

### 판정 방식의 이원화 원칙

| 계층 | 성격 | 기준 유형 | 초기 제안 방향 |
|---|---|---|---|
| 제약 준수(L2) · 합의 종결 정합(L4) | 결정적으로 검증 가능 | **절대 기준 (위반 0건)** | 전 참여자 기준 위임 위반 0건 · 종결 시 합의 레코드 불일치 0건 |
| 의도 정확성(L1) · 선호 정합(L3) | 비결정적·주관적 | **통계 기준 + 사용자 안전판** | 정확도·무수정 승인율은 **베이스라인 실측 후 목표치 설정** (사전 임의값 지양) |

비결정 계층의 오류가 실세계 피해로 이어지지 않게 막는 최종 안전판은 **전 참여자의 승인(Operability)** 이다 — *"Agent는 틀릴 수 있으나, 틀린 채로 실행되지는 않는다"* 가 N명 각각에게 성립해야 한다.

## 9.4 2차 — QA-FC-2 "효용 분배 균형(Utility Distribution Balance)" (정의 스케치)

| 항목 | 내용 |
|---|---|
| 정의 (정량 방향) | 반복되는 그룹 협상에 걸쳐, 합의안의 효용 분배가 특정 참여자에게 체계적으로 유리·불리하게 편향되는 정도를 **최소화**해야 한다 |
| 오류 예 | 전원 threshold는 매번 넘지만, 집계 규칙 특성상 매번 개시자의 1순위만 채택됨 / 양보 전략이 느린(고집 센) Agent가 항상 이득을 봄 |
| 판정 방식 | **통계적 (그룹 단위)** — 단일 협상: 참여자 간 효용 분포 지표, 반복 협상: 참여자별 누적 효용·1순위 채택률의 편향 추세. 구체 지표 선택은 미결정 (§9.7) — 협상 이론의 후생 개념(최소 효용 최대화, 효용 곱 등)을 후보로 검토하되 원문 근거가 없으므로 팀 결정 사항 |
| ISO 매핑·QA ID | **Functional Suitability — Functional Correctness**에 매핑, QA ID는 **QA-FC-2** — 1차 정의(QA-FC-1, §9.3)와 지표·판정을 합산하지 않는 별개 QA 항목 (PL 지시 ⑥) |
| 주 설계 지점 | **CFR-B9 (합의 완결 규칙 실행)** — 집계 규칙의 성질이 공정성을 좌우. CFR-B8(양보 전략)도 부차 영향 |
| 검증 | CFR-J2(Mock 다자)·J4(지표) 위에서 반복 협상 시뮬레이션으로 편향 추세 측정 |

## 9.5 아키텍처 함의 (07 문서에서 난이도 H로 평가한 근거)

1. **생성-검증 분리 (Generate–Validate)**: LLM·Ufun이 만드는 제안(비결정)은 참여자별 **결정적 검증기(L2 규칙 엔진)** 를 통과한 뒤에만 발신·수락·확정된다. 검증기는 제안 생성→평가→집계→확정·인계의 전 경로에 삽입된다 (Safety — Operational Constraint와 공유 구조).
2. **합의의 원자적 커밋**: 합의 종결 정합(L4)의 "전원 동일 종결"은 전원 확인(ACK) 후에만 합의를 확정하고 실행 계층에 인계하는 커밋 프로토콜을 요구한다 (시나리오 6 Double Confirm의 일반화). 인계 이후의 실행은 과제 범위 밖이다.
3. **판정 가능성의 기록·재현**: L1·L3의 통계 측정과 공정성(§9.4)의 추세 분석은 참여자별 제안·수락의 완전한 이력(Accountability)과 Mock 다자 재현 하니스(Testability)를 전제한다.
4. **선호 확인 루프**: 선호 정합(L3)의 "내 선호가 올바르게 입력·통합됨"은 협상 전 사용자가 반영된 선호 구성(우선순위)을 확인·수정할 수 있는 상호작용(CFR-E1 선호 확인·수정)과 결합될 때 검증 가능해진다 — Ufun 알고리즘 기제공 가정(PL 지시 ③) 하에서도 입력 경로의 확인은 사용자 신뢰 요소로 유지된다.
5. **제약 모델의 이중 활용**: 제약 준수(L2)의 hard constraint(위임 범위·캘린더 충돌·예산 상한)는 검증만이 아니라 **탐색 공간 축소(제약 전파·가지치기, CFR-B12)의 입력**이기도 하다. "확정된 의제가 미확정 의제의 후보군을 좁힌다"(PL 구두 시나리오)는 구조와 하드 제약 검증을 **동일한 제약 표현 위에서** 동작시키면, 위반 후보는 애초에 생성·제안되지 않으므로 L2 위반 0건과 메모리 통제를 한 구조로 달성할 수 있다.

## 9.6 결론

1. **Functional Correctness의 1차 정의는 QA-FC-1(개인 관점)로 확정한다**: 각 참여자 관점에서 *의도 정확성(L1) ∧ 제약 준수(L2) ∧ 선호 정합(L3) ∧ 합의 종결 정합(L4)*. — PL 지시 ①·②의 "내 선호를 잘 반영했는가"에 대한 답.
2. **판정은 이원화한다**: 결정 계층(제약 준수 L2·합의 종결 정합 L4)은 위반 0건의 절대 기준, 비결정 계층(의도 정확성 L1·선호 정합 L3)은 통계 지표 + 사용자 승인 안전판. 완결 규칙(전원·다수결·부분 완결)이 무엇이든 **승인하지 않은 참여자에게는 확정 효력이 미치지 않으므로** 안전판은 유지된다. 목표치는 베이스라인 실측 후 설정.
3. **2차(N명의 선호 반영 = 공정성)는 같은 Functional Correctness 하위특성에 매핑하되, 별개 QA 항목 QA-FC-2 "효용 분배 균형"으로 분리한다** (§9.2 분리 근거 — 판정 주체·측정 층위·트레이드오프가 달라 하나의 QA 항목으로 합산 불가, ISO 매핑은 PL 지시 ⑥). QA-FC-2는 CFR-B9(완결 규칙) 설계의 평가 기준으로 사용한다.
4. **본 정의의 용처**: QAS(품질 속성 시나리오) 도출 시 Functional Correctness 시나리오의 자극-응답 측정 기준, 그리고 정확성 판정 하니스(CFR-J9)의 판정 규칙으로 사용한다.

## 9.7 미결정 사항 (팀 논의 필요)

1. L1 정확도·L3 무수정 승인율의 목표치 — 베이스라인 실측 전 미설정을 제안.
2. L2 검증기의 규칙 표현 — 위임 정책과 하드 제약의 통합 스키마.
3. 효용 분배 균형(§9.4)의 구체 지표 선택.
4. 본 결론(§9.6)의 팀 채택 여부.
