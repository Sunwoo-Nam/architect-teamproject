# 34. 설계 문제 — 의제 분해·어젠다 구조 (Multi-issue Agenda)

> 문제 정의·의존: [`30`](30-설계-문제-총괄.md) §30.1 · 평가 축: [`20`](20-핵심-QA-확정.md)의 확정 QA 10개
> 관련 CFR: B5 계층적 옵션 공간 · B12 제약 전파·지연 생성

---

## 1. 문제 정의

영화 약속 하나에도 정할 것이 여러 개다 — 날짜, 영화, 영화관, 시간. 의제가 4개이고 각 의제의 후보가 K·L·M·P개면 조합은 K×L×M×P개가 되어, 전부 만들어 놓고 협상하면 메모리가 터진다(PL 지목 문제). 반대로 의제를 하나씩 순서대로 확정하면 공간은 작아지지만 "날짜를 먼저 정했더니 정작 보고 싶은 영화가 그날 상영을 안 한다"처럼 **먼저 정한 것이 나중 선택지를 망치는 경로 의존**이 생긴다.

알고리즘 차원에서는 패키지 일괄 협상, 의제별 순차 협상, 둘의 혼합 등 여러 방식이 가능하다. 본 문제가 정하는 것은 그 알고리즘이 아니라 **그런 방식들을 담아서 돌릴 세션 구조** — 협상 세션을 몇 개, 어떤 관계로 두는가 — 이다.

## 2. 전제와 제약 (모든 대안에 공통)

- 확정된 의제 값을 제약으로 전파해 미확정 의제의 후보를 좁히는 가지치기(CFR-B12)와 옵션의 지연 생성은 **어느 대안에서든 각 단말 내부에서 동작**한다 — 대안이 바꾸는 것은 세션의 개수와 관계다.
- 의제 간 종속 관계(날짜를 정하면 영화·영화관 후보가 좁아진다)는 옵션 공간 정의(CFR-B5)에 명세되어 있다고 전제한다.
- 각 세션 내부의 라운드 진행은 [`31`](31-제안-토폴로지.md)의 결정을 따른다.

## 3. 대안

### 대안 A — 단일 세션 복합 공간형 (Single Session, Composite Space)

**도식**: [`drawio/34-A-단일-세션-복합-공간형.drawio`](drawio/34-A-단일-세션-복합-공간형.drawio)

**구조.** 협상 세션은 **1개**다. 제안 하나가 (날짜, 영화, 영화관, 시간) **패키지 전체**이고, 전 의제를 통합한 OutcomeSpace 위에서 협상한다. 조합 폭발은 Constraint Propagator(가지치기)와 지연 생성으로 막는다.

| Component | 위치 | 역할 |
|---|---|---|
| Composite Outcome Manager | 각 참여자 단말 | 전 의제를 묶은 통합 옵션 공간을 관리하고 패키지 후보를 지연 생성한다 |
| Constraint Propagator | 각 참여자 단말 | 잠정 확정·거절된 값을 제약으로 전파해 후보 공간을 좁힌다 |

**정상 동작:** 패키지 제안 ↔ 패키지 평가의 라운드 반복 — 한 세션에서 합의가 나면 전 의제가 한 번에 끝난다. **오류 상황:** 세션이 1개라 오류 처리·복구 흐름도 하나다.

### 대안 B — 의제별 순차 파이프라인형 (Sequential Per-issue Sessions)

**도식**: [`drawio/34-B-의제별-순차-파이프라인형.drawio`](drawio/34-B-의제별-순차-파이프라인형.drawio)

**구조.** 의제마다 **독립된 하위 세션**을 열고 순서대로 진행한다. **Agenda Orchestrator**가 순서를 관리하며, 앞 세션의 확정 결과(날짜)를 뒤 세션(영화관)의 제약으로 주입한다.

| Component | 위치 | 역할 |
|---|---|---|
| Agenda Orchestrator | 개시자 단말 | 의제 순서를 관리하고, 의제 k의 확정 결과를 의제 k+1 세션의 제약으로 주입한다 |
| Per-issue Session Runner | 각 참여자 단말 | 지정된 의제 하나만의 작은 옵션 공간으로 하위 협상을 실행한다 |

**정상 동작:** 의제 1 세션(합의) → 결과를 제약으로 의제 2 세션 → … 마지막 의제 합의로 종료. **오류 상황:** 뒤 의제에서 수용 가능한 후보가 하나도 없으면(날짜를 잘못 골라 영화가 전멸) 앞 의제로 되돌아가는 역추적(backtrack) 절차가 필요하다.

### 대안 C — 마스터-서브 병렬형 (Master with Parallel Sub-sessions)

**도식**: [`drawio/34-C-마스터-서브-병렬형.drawio`](drawio/34-C-마스터-서브-병렬형.drawio)

**구조.** **마스터 세션**이 전체 패키지의 골격 — 각 의제의 잠정 구간("주말 저녁, 시내 쪽") — 을 잡고, **의제별 서브 세션들이 병렬로** 그 구간 안에서 세부를 좁힌다. Sync Bus가 골격과 세부를 양방향으로 동기화한다(서브에서 좁혀진 결과가 골격을 갱신하고, 골격 변경이 서브에 전파).

| Component | 위치 | 역할 |
|---|---|---|
| Master Session | 개시자 단말 | 패키지 골격(의제별 잠정 구간)을 관리한다 |
| Sub-session Runner | 각 참여자 단말 | 의제별 서브 협상을 병렬로 실행한다 |
| Sync Bus | 전 단말 | 골격 ↔ 서브 세션 간 갱신을 양방향 전파한다 |

**정상 동작:** 골격 합의 → 서브 세션들 병렬 진행 → 전 서브 완료 시 패키지 확정. **오류 상황:** 동기화가 늦으면 서브들이 서로 모순된 방향(영화 서브는 심야 영화, 시간 서브는 저녁 6시)으로 진행될 수 있어 Sync Bus의 충돌 감지·조정이 필요하다.

## 4. QA Trade-off 평가표

(SC-참여자 축은 세 대안 모두 (0) — 세션 구조는 참여자 수 확장과 직교하고, 참여자 축은 31의 결정이 지배한다.)

| QA | A. 단일 세션 복합 공간형 | B. 의제별 순차 파이프라인형 | C. 마스터-서브 병렬형 |
|---|---|---|---|
| Functional Correctness | (+)<br>패키지 전체를 놓고 판단하므로 의제 간 연관(늦은 시간이면 집 근처 영화관)을 반영한 좋은 조합을 찾을 수 있다 | (−)<br>앞 의제의 확정이 뒤 의제의 선택지를 잘라버린다 — 전체로 보면 더 좋았을 조합을 구조적으로 놓친다 (경로 의존) | (0)<br>골격이 연관을 어느 정도 반영하지만, 동기화가 늦으면 서브들이 모순된 부분 합의를 만들 위험이 있다 |
| Fault Tolerance | (0)<br>세션이 1개라 오류 처리 흐름이 단일하다 — 특별히 유리하지도 불리하지도 않다 | (+)<br>세션이 의제 단위로 독립적이라 하나의 실패가 그 의제에 갇힌다 — 재시도 단위가 작다 | (−)<br>병렬 세션 + 동기화 조합이라 실패 지점이 많고, 부분 실패 시 어디까지 유효한지 정리가 복잡하다 |
| Analysability | (−)<br>패키지 제안 하나에 전 의제의 판단이 뒤섞여 "왜 이 조합인가"의 재구성이 복잡하다 | (+)<br>의제별로 이력이 깨끗이 분리된다 — "날짜는 왜 토요일이 됐나"를 그 세션 이력만 보면 안다 | (−)<br>병렬 이력이 교차하고 동기화 이벤트까지 얽혀 재구성이 가장 어렵다 |
| Scalability (참여자 수) | (0)<br>31의 결정이 지배 | (0)<br>동일 | (0)<br>동일 |
| Scalability (의제 조합) | (−)<br>통합 공간이라 가지치기를 해도 다뤄야 하는 조합의 상한이 가장 크다 | (+)<br>공간이 의제 단위로 잘려 한 번에 다루는 후보 수가 최소다 — 조합 폭발에 가장 강하다 | (0)<br>골격이 구간을 좁혀 주지만 서브 공간들을 동시에 유지한다 |
| Time Behaviour | (−)<br>큰 공간을 탐색하느라 수렴까지의 라운드 수가 가장 많다 | (0)<br>세션마다는 빠르지만 순차로 이어져 총 시간은 중간 — 역추적이 나면 더 길어진다 | (+)<br>서브 세션들이 병렬로 돌아 총 시간이 가장 짧다 |
| Recoverability | (0)<br>복원할 세션이 1개 — 상태는 크지만 단일하다 | (+)<br>확정된 앞 의제들은 이미 저장 완료 — 중단 시 진행 중이던 의제 세션 하나만 복원하면 된다 | (−)<br>마스터+서브 여러 세션과 동기화 상태를 함께 복원해야 한다 |
| Resource Utilization | (−)<br>통합 공간의 후보·상태 메모리가 가장 크다 | (+)<br>한 번에 한 의제의 작은 공간만 메모리에 있다 | (−)<br>병렬 서브 세션들의 공간을 동시에 유지한다 |
| Confidentiality | (−)<br>패키지 제안 하나가 전 의제에 걸친 선호를 한꺼번에 노출한다 | (0)<br>노출이 의제별·시점별로 분산되어 결합 추론이 상대적으로 어렵다 | (0)<br>골격(대략 구간)과 세부가 분리 노출된다 — 중간 수준 |
| Adaptability | (0)<br>의제 추가 = 공간 확장 — 구조는 그대로나 공간이 커진다 | (+)<br>의제 추가 = 파이프라인에 단계 하나 추가 — 가장 자연스러운 확장 | (−)<br>의제를 더할 때마다 골격 표현과 동기화 규칙을 함께 늘려야 한다 |

## 5. 배타성 확인

세 대안은 "세션이 몇 개이고 서로 어떤 관계인가"가 다르다 — 1개(A) / 순차 여러 개(B) / 병렬 여러 개+마스터(C). 같은 협상에서 이 구조는 하나만 성립한다: 패키지 전체를 한 세션에서 다루면서 동시에 의제별 세션을 따로 돌리면 같은 의제가 두 곳에서 다른 값으로 합의될 수 있어 구조 자체가 모순된다. "일부 의제는 묶고 일부는 순차"같은 혼합은 B의 파이프라인 단계 하나에 묶음 의제를 넣는 것으로 B의 변형이지 별개 구조가 아니다.

## 6. 비지배 확인

- A는 SC-의제·TB·Rec·RU·Analy·Conf에서 진다 (우위: FC) ✓
- B는 FC·TB에서 진다 (우위: SC-의제·Analy·Rec·RU·AD·FT) ✓
- C는 FC·FT·Analy·Rec·RU·AD에서 진다 (우위: TB) ✓

## 7. 다른 문제와의 결정 의존

- **[`38`](38-협상-시나리오-가변성-구조.md)**: 어젠다(의제 순서·묶음 방식)의 표현이 프로세스 정의의 일부가 되어야 한다 — B·C를 고르면 세션 오케스트레이션 규칙까지 시나리오 정의에 포함되어야 하므로 38의 표현력 요구가 커진다.
- **[`31`](31-제안-토폴로지.md)**: B·C는 세션이 여러 개라 세션마다 토폴로지 인스턴스가 반복 생성된다 — 세션 수립 비용이 토폴로지 선택에 따라 달라진다.
- **[`36`](36-개입-시점-모델.md)**: 사용자 개입의 반영 단위가 A는 패키지 라운드, B는 의제 세션 경계, C는 골격/서브 중 어느 층인지 — 세션 구조에 따라 개입 지점의 의미가 달라진다.
