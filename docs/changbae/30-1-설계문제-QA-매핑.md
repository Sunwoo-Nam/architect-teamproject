# 30-1. 설계 문제별 QA 매핑 — 각 설계 문서가 만족시키려는 품질

> 목적: 설계 문제 8건([`31`](31-제안-토폴로지.md)~[`38`](38-협상-시나리오-가변성-구조.md))이 각각 **어떤 품질 속성(QA)을 만족시키기 위한 결정인지**를 한 문서로 정리한다 (PL 지시, 2026-08-09).
> 근거: 각 설계 문서의 §1 문제 정의와 §4 QA Trade-off 평가표를 전수 재검토했다 — §6 비지배 선언과 §4 표의 정합, 직교 선언의 정합을 기계 검산으로 확인했고(위반 0건), [`21`](21-핵심-QA-측정-정의.md) 지표 재정의와 어긋난 표현 1건(33의 FC 판정 근거)을 정정한 상태다.

---

## 30-1.1 평가 축 — 핵심 QA 10개

[`20`](20-핵심-QA-확정.md)에서 확정한 핵심 QA 10개가 모든 설계 문서의 공통 평가 축이다. 본 문서만 읽어도 되도록 각 QA의 뜻과 핵심 지표([`21`](21-핵심-QA-측정-정의.md))를 요약한다. 괄호의 순위는 QAW([`22`](22-QAW-QA-우선순위-선정.md))에서 stakeholder 10개 역할이 채점한 우선순위다.

| QA (QAW 순위) | 뜻 | 핵심 지표 ([`21`](21-핵심-QA-측정-정의.md)) |
|---|---|---|
| **Functional Correctness (기능 정확성)** (1위) | 합의가 각 참여자의 의도·제약·선호에 비추어 올바르고, 종결 시 전원이 동일한 합의 레코드를 갖는다 | 정합 판정률 ≥ 70% |
| **Confidentiality (기밀성 — 역추론 방지)** (2위) | 협상 메시지 관찰만으로는 참여자의 선호 순위를 복원할 수 없다 | 역추론 이득 ≤ +10%p |
| **Scalability — 참여자 수 (확장성)** (3위) | 참여자가 늘어도 합의 시간·메시지가 선형 이내로 증가한다 | 확장 지수 b — 95% 신뢰구간 하한 ≤ 1 |
| **Fault Tolerance (결함 감내)** (4위) | 일시 오류(유실·지연·무응답·일시 이탈)를 흡수하고 중단 없이 정상 완결한다 | 내성 여유 배수 ≥ 10배 |
| **Recoverability (복구 가능성)** (5위) | 세션이 죽은 뒤에도 중단 지점에서 재개되고 전 참여자 상태가 일치한다 | 복구 시간 비율 ≤ 1 (한 라운드 이내) |
| **Time Behaviour (시간 효율성)** (6위) | 합의 도달까지의 총 시간이 짧다 — 사람 직접 조율보다 확실히 빨라야 한다 | 프로토콜 오버헤드 비율 ≤ 2 |
| **Analysability (분석 용이성)** (7위) | 기록만으로 협상의 인과(성공 요인·결함 원인)를 재구성할 수 있다 | 인과 재구성 성공률 ≥ 95% |
| **Scalability — 의제 조합 (확장성)** (8위) | 의제 조합(K×L×M×P)을 전체 열거하지 않고 협상한다 | 조합-메모리 탄력성 c — 95% 신뢰구간 상한 < 1 |
| **Resource Utilization (자원 효율성)** (9위) | 협상 1회가 단말 자원(메모리 중심)을 적게 쓴다 | 피크 추가 메모리 ≤ 앱 가용 예산의 50% |
| **Adaptability (적응성)** (10위) | 아직 정의되지 않은 신규 협상 시나리오를 코드 변경 없이 수용한다 | 신규 시나리오 수용 공수 평균 ≤ 8시간 |

## 30-1.3 정방향 매핑 — 각 설계 문제는 어떤 QA를 위한 결정인가

읽는 법:
- **주 목적 QA** — 그 문제가 존재하는 이유. 각 문서 §1 문제 정의가 명시한 품질이다. 이 QA를 포기하면 그 설계 문제 자체가 필요 없어진다.
- **판별 축** — 대안 A/B/C의 선택이 실제로 (+)/(−)로 갈리는 QA (§4 평가표 기준). 주 목적은 아니지만 이 결정에서 얻거나 잃는 품질이다.
- **직교 축** — 세 대안 모두 (0)인 QA. 이 문제의 결정이 그 품질에 영향을 주지 않는다.

| 설계 문제 | 주 목적 QA | 문제 정의의 근거 문장 | 그 외 판별 축 | 직교 축 |
|---|---|---|---|---|
| **31 제안 토폴로지** | **Scalability — 참여자 수 (확장성)** (+ Fault Tolerance (결함 감내)) | "참여자가 늘 때 메시지가 폭증하거나, 한 단말의 고장이 협상 전체를 멈추거나" — 경로 구조가 이 둘을 정한다 | 기능 정확성 · 분석 용이성 · 시간 효율성 · 복구 가능성 · 자원 효율성 · 기밀성 · 적응성 | 확장성-의제 조합 |
| **32 완결 규칙 실행 구조** | **Functional Correctness (기능 정확성)** — 판정 정합 + **Adaptability (적응성)** — 미정의 규칙 수용 | "참여자마다 성립 여부를 다르게 판단해 갈리거나(정확성), 새 규칙이 올 때마다 코드를 고쳐야 한다(적응성)" | 결함 감내 · 분석 용이성 · 확장성-참여자 · 시간 효율성 · 복구 가능성 · 자원 효율성 · 기밀성 | 확장성-의제 조합 |
| **33 정보 공개 구조** | **Confidentiality (기밀성 — 역추론 방지)** (단일 주 목적) | "참여자들이 선호 노출이 두려워 위임 자체를 꺼리게 된다 — 프라이버시가 위임의 전제라는 출발점이 무너진다" | 기능 정확성 · 결함 감내 · 분석 용이성 · 확장성-참여자 · 시간 효율성 · 복구 가능성 · 자원 효율성 · 적응성 | 확장성-의제 조합 |
| **34 의제 분해·어젠다 구조** | **Scalability — 의제 조합 (확장성)** (+ Resource Utilization (자원 효율성)) | "조합은 K×L×M×P개가 되어, 전부 만들어 놓고 협상하면 메모리가 터진다(PL 지목 문제)" | 기능 정확성 · 결함 감내 · 분석 용이성 · 시간 효율성 · 복구 가능성 · 기밀성 · 적응성 | 확장성-참여자 수 (31이 지배) |

## 30-1.4 역방향 매핑 — QAW 우선순위 상위 QA는 어느 결정이 좌우하는가

QAW([`22`](22-QAW-QA-우선순위-선정.md))의 우선순위 순서대로, 각 QA를 어느 설계 문제의 결정이 좌우하는지 정리한다.

| QA (QAW 순위) | 주 담당 설계 문제 | 부수 영향 문제 | 해석 |
|---|---|---|---|
| **Functional Correctness (기능 정확성)** (1위) | **32 완결 규칙 실행** (판정 정합) · **36 개입 시점** (의도 반영) · **37 합의 확정** (종결 정합 L4) | 나머지 5개 문제 전부에서 판별 축 | 단일 문서가 없다 — 정확성의 세 측면(판정·의도·종결)이 각각 다른 결정에 걸려 있어, **세 결정의 합**으로만 달성된다 |
| **Confidentiality (기밀성 — 역추론 방지)** (2위) | **33 정보 공개 구조** (사실상 단독 결정) | 31 제안 토폴로지 (누가 제안을 관찰하는 구조인가) · 32 완결 규칙 (판정자가 표를 보는가) · 35 이탈 처리 (대안 C의 선호 이전) | 36·37·38에서는 직교 — **33의 선택이 이 QA의 성패를 사실상 결정**한다 ([`40`](40-설계-단계-레포트.md) §40.4 관찰과 일치) |
| **Scalability — 참여자 수 (확장성)** (3위) | **31 제안 토폴로지** (메시지·시간의 N 증가 구조를 지배) | 32 완결 규칙 (표 교환 방식) · 33 정보 공개 (셔플 홉) · 35 이탈 처리 (감시 신호) · 37 합의 확정 (확정 왕복 수) | 34에서는 직교(의제 축과 분리) — **31이 지배하고 나머지는 악화시키지 않는 것이 과제** |
| **Fault Tolerance (결함 감내)** (4위) | **35 이탈·무응답 처리** (전담) | 31·32·33·34·36·37 전반의 판별 축 | 중앙 집중 계열 대안(Coordinator·중앙 판정·Blind Aggregator)의 공통 약점 축 — 어느 계열을 골라도 35와 함께 집중 검증 필요 |
| **Recoverability (복구 가능성)** (5위) | **전담 설계 문제 없음** | 31 (복구 기준 상태의 소재) · 32 (판정 상태 복원) · 33 (매핑 상태 복원) · 34 (세션 수) · 35 (재참여) · 36 (스냅샷 단위) · 37 (확정 이력) | 전담 문제 없이 부수 축 평가 + 측정 정의([`21`](21-핵심-QA-측정-정의.md))로 관리 — 39번 신설 안 함 (PL 결정, §30-1.5 관찰 4) |
| **Time Behaviour (시간 효율성)** (6위) | 주 담당 없음 — **31 제안 토폴로지**의 영향이 최대 (라운드 왕복 구조) | 32~38 전부에서 판별 축 (각 결정이 시간을 얹는다) | 오버헤드 비율(≤2)의 분자를 모든 결정이 조금씩 키운다 — ADR마다 "이 결정이 라운드에 얹는 시간"을 반복 확인해야 한다 |
| **Analysability (분석 용이성)** (7위) | 주 담당 없음 — 이력이 한 곳에 모이는 구조(중앙 집중·문서 순환 계열)일수록 유리 | 31~38 전부에서 판별 축 | 분산 계열의 공통 약점 축 (N개 로그 상관 분석 필요) |
| **Scalability — 의제 조합 (확장성)** (8위) | **34 의제 분해·어젠다** (단독 결정) | 없음 — 나머지 7개 문제 전부에서 직교 | **34가 이 QA를 단독으로 결정한다** — 기밀성↔33의 관계와 같은 구조 |
| **Resource Utilization (자원 효율성)** (9위) | **34 의제 분해** (옵션 공간 메모리가 지배 요인) | 31·32·33·35·36·37·38에서 판별 축 | 절대 제약(OOM 금지)은 FR로 검증([`21`](21-핵심-QA-측정-정의.md) §21.4)되므로, 여기서는 정도의 문제 |
| **Adaptability (적응성)** (10위) | **38 시나리오 가변성** (전담) + **32 완결 규칙** (규칙의 데이터화) | 31·33·34·35에서 판별 축 | 중앙 집중 계열(변경 지점이 한 곳)이 대체로 유리한 축 |

## 30-1.5 관찰 — 매핑에서 드러나는 구조

1. **단독 결정 축이 둘 있다.** 기밀성은 33 정보 공개 구조가, 확장성-의제 조합은 34 의제 분해 구조가 사실상 단독으로 결정한다 — 이 두 문서의 대안 선택이 곧 해당 QA의 성패다. QAW 2위인 기밀성이 여기 속하므로, **33은 대안 채택 시 가장 신중해야 할 문서**다.
2. **기능 정확성(QAW 1위)은 쪼개져 있다.** 판정 정합은 32, 의도 반영은 36, 종결 정합(L4)은 37 — 세 결정 중 하나만 어긋나도 정확성이 깨진다. 세 문서의 ADR은 정확성 관점에서 묶어서 검토하는 것이 안전하다.
3. **기능 정확성·결함 감내·분석 용이성·자원 효율성은 전 문제의 공통 판별 축이다.** 특정 문서 하나로 확보되는 품질이 아니라 모든 결정에서 조금씩 얻거나 잃는 범용 품질이므로, 문서별 ADR마다 반복 확인이 필요하다.
4. **커버리지 공백 후보: 복구 가능성 (QAW 5위).** "세션의 저장·복원·전 참여자 재동기화 구조"(CFR-I8 그룹 세션 저장·복구) 자체를 다루는 전담 설계 문제가 없다 — 7개 문서에서 부수 축으로만 평가될 뿐, 무엇을 언제 저장하고 어떻게 재동기화하는가의 **대안 비교는 어느 문서에서도 이루어지지 않았다**. 39번 설계 문제 신설 여부를 PL에게 상신했고, **신설하지 않는 것으로 결정되었다** (PL 결정, 2026-08-10) — 복구 가능성은 각 문서의 부수 축 평가와 측정 정의([`21`](21-핵심-QA-측정-정의.md)의 복구 시간 비율 지표 + 재개·상태 일치 FR 조건)로 관리한다.
5. **계열 일관성이 QA로도 설명된다.** [`40`](40-설계-단계-레포트.md) §40.4의 "중앙 집중 계열 vs 문서 순환 계열" 관찰을 QA 축으로 다시 읽으면 — 중앙 집중 계열은 분석 용이성·적응성·시간 효율성에서 얻고 결함 감내에서 잃으며, 분산·순환 계열은 그 반대다. 계열을 엇갈려 고르면 양쪽의 약점을 동시에 안게 되므로, 결정 순서(31 먼저)와 계열 일관성 확인이 중요하다.

## 30-1.6 근거와 검증 방법

- **주 목적 QA**: 각 문서 §1 문제 정의에 명시된 품질 훼손 문구에서 추출했다 (표의 "문제 정의의 근거 문장" 열에 인용).
- **판별 축/직교 축**: 각 문서 §4 QA Trade-off 평가표의 (+)/(0)/(−) 판정을 기계 파싱해 분류했다 — 대안 간 판정이 갈리면 판별 축, 세 대안 모두 (0)이면 직교 축.
- **정합 검산**: 8개 문서 전부에 대해 ① §4 표 기준 대안 간 지배 관계(모든 축에서 같거나 우세) 부재를 기계 검산 — 위반 0건, ② §6 비지배 선언과 §4 표의 일치 확인, ③ [`20`](20-핵심-QA-확정.md)·[`21`](21-핵심-QA-측정-정의.md)의 QA 정의·지표와 어긋나는 표현 검사 — 1건 발견·정정(33의 기능 정확성 판정 근거 중 "승인율" → "정합 판정률").
