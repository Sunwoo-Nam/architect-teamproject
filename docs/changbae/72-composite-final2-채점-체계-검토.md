## 72.4 정본과의 차이와 후속

1. **TB 재앵커(naive=★3)가 유일한 미확정 개정 사안이다.** FC(전체)·RU(14축·P95)는 이미 정본과 일치한다. 재앵커의 근거: ① 본 과제의 목적이 메모리 효율이라 시간은 naive 대비 열세라도 수용 가능(TB는 QA 서열 4위 — 24 §0), ② 현행 "ρ>1 = ★0 결함"은 naive 등가를 낙제로 두는 앵커인데, 목적상 naive 등가는 "보통(★3)"이 적절, ③ 로그 √10 등분은 RU 사다리와 동일 철학(ρ 실측 범위가 0.001~16으로 4자릿수 — 등비 눈금이어야 전 등급에 분산). **채택하려면 24 §4.3 개정 + PL 확정 필요** (RU 사다리 개정이 §2.8에 이력을 남긴 것과 동일 절차).
2. **FC는 14축으로 통일 불가** — 오라클(전수 열거, S ≤ 150,000)이 12축까지만 가능해 14축 FC는 원리적으로 측정 불가(RS는 null 명시). 그래서 FC만 전체(CR 400건) 절단을 유지했다. 14축 인접 프록시가 필요하면 12축 CR 44건(세 방안 ★4 동률)을 병기한다.
3. **naive의 메모리는 실계측이 아니라 환산 추정**이다 — composite-final의 baseline은 lazy k-best로 열거 없이 계산하는 TB 전용 구현이라 RU 계측이 없다. §72.2의 초과 검산은 "전수 물질화 설계라면"의 환산(7.44B/조합)이며, 이 값 자체가 dpca P5 실측에서 유도된 것임을 명시한다.
4. **14축 표본은 20건** — P95가 규약상 최대값과 일치하므로 케이스 1건이 별점을 흔들 수 있다. 수준당 표본 확대(예: 40건)는 후속 측정 사안이다.

## 72.5 추가 검토 — pool2(유효-only 순차 구성)의 동일 체계 채점

### 배경 — 방안 2의 풀 구성은 "축별 독립 선별"이 아니다

사용자 질의(2026-08-20 — "축별 top-k를 독립적으로 뽑으면 축 간에 말이 안 되는 조합이 생기지 않나")로 구현을 확인한 결과:

- **pool** ([`pool.py`](../../poc/total/src/total/adapters/composite/_vendor/strategies/pool.py) `_compress`): 축을 **선언 순서로 순회**하며 앞 축 선택과 **양립(짝 단위 하드 검사)하는 값을 우선** top-k로 뽑고, 부족분은 비양립 값으로 채운다. 이후 **곱(product)으로 kⁿ 물질화** — 이 단계에서 무효 조합이 대량 생기며, 제안 시점의 `feasible()` 필터가 최종 방어한다 (무효 조합은 제안되지 않지만 **풀 메모리는 차지**).
- **pool2** ([`pool2.py`](../../poc/total/src/total/adapters/composite/_vendor/strategies/pool2.py)): 사용자가 상정한 설계와 일치 — 빈 부분조합에서 축을 하나씩 이어붙이는 **조건부 확장**으로, 각 부분조합에 유효한 값만 top-k로 붙여 **후보 전부가 유효(무효 조합 0)**. 단 회복 메커니즘이 다르다: deepening(k↑) 대신 **k 고정 + 충돌 축 top-k 교체(제외)**.
- 순차성의 위치가 세 층위로 다르다: seq2 = **확정**이 순차(경로 의존) / pool = **선별**이 순차(곱은 무효 포함) / pool2 = **후보 구성**이 순차(전부 유효). pool 계열의 협상·확정은 조합 통째 단위라 seq2식 경로 의존은 없다 (hard_path 함정 실측이 증거 — pool 53/53 합의).

### 판정 — 유효성은 메모리 해법이 아니고, FC 열세의 출처는 회복 메커니즘이다

**(1) RU: "유효-only"는 낭비를 없앨 뿐 개수를 묶지 않는다.** 조건부 확장의 후보 수는 여전히 ~kⁿ이다 (pool2.py 자신의 주석 — "k^n 근처까지 커질 수 있다"). 대형 판에선 유효 조합만으로도 지수라, 오히려 무효로 죽던 가지가 살아남아 한도 초과가 26건으로 늘었다. **메모리를 잡는 변수는 유효성이 아니라 개수 상한(P6 예산 ∏k_i ≤ B)** — poolka가 유효성 필터 없이 예산만으로 초과 0건을 만든 것이 실증이다.

**(2) FC: 격차 0.009의 출처는 결렬 8건이 전부다.** 같은 케이스 직접 대결 (pool vs pool2, CR 400건):

| 유형 | pool 합의 | pool2 합의 | pool2 승/무/패 | 달성률 차 평균 |
|---|---|---|---|---|
| plain (302) | 301 | 299 | **38승** / 239무 / 25패 | −0.0015 |
| hard_path (53) | **53** | **47** | 3 / 42 / 8 | **−0.0567** |
| no_deal (45) | 0 (정답) | 0 (정답) | 완전 동일 | 0 |

- **유효-only 풀의 품질 이점은 실재한다** — plain 정면 승부는 pool2가 38승 25패로 우세 (무효 조합 자리에 유효 후보가 들어온 효과).
- 지는 곳은 **결렬 8건**(hard_path 6 + plain 2, 건당 달성률 −0.29~−0.53)이며 이것만으로 전체 격차가 설명된다. 원인은 막혔을 때의 회복: pool은 deepening(**추가** — 기존 값 유지 + 확장)으로 정답 대안을 결국 풀에 들이지만, pool2는 충돌 축 top-k **제외·교체**(버리는 연산)라 정답에 필요한 값을 버리거나 세션 상한 안에 수렴하지 못한다.

**(3) 시사점**: "유효-only 구성"과 "k 고정 + 교체"는 별개 설계 결정인데 pool2가 묶어놓아 전자의 이득이 후자의 손실에 상쇄됐다. **유효-only 확장 + 예산 내 deepening(P6식)** 결합이 이론상 "FC ≥ pool + 메모리 유계"를 동시에 만족할 수 있다 — [`66`](66-composite-보완-택틱-후보-분석.md)의 "유효-only 풀 강화(FC 보조)" × P6 결합 후속 과제와 일치. 검증하려면 FIN2 재실행(`--dataset final2 --plans pool2` 또는 결합 신규 택틱)이 필요하다.
