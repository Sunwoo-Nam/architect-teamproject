## 1. 62 택틱의 이식성 검증

## 2. composite 고유 택틱 카탈로그 — QA별 겨냥

### 2.1 FC 겨냥

**S1. 제약 전파 (포워드 체킹)** — seq2가 축 값을 확정하기 **전에**, 공유 하드 규칙으로 남은 축들의 값 도메인이 얼마나 줄어드는지 로컬 계산한다(CSP의 표준 forward checking). 유인값(0.95)이 뒤 축의 좋은 값(0.90)을 전부 봉쇄한다는 사실은 규칙만 보면 알 수 있는데, 현 구현은 확정 후 뒤 축 세션에서 **협상으로** 발견하고 백트랙한다 — 63 실측으로 함정 판 53건 중 43건이 그 백트랙이 세션 상한 안에 못 끝나 결렬(달성률 0.43-0.59), seq2 함정 라운드 중앙 121. S1은 이 발견을 0 phase로 앞당긴다. **FC와 TB를 한 번에** 겨냥하는 유일한 후보다.
한계를 정직하게: FIN의 함정이 하드 규칙 기반이라 정조준이 되는 것이고, soft 감점 기반 구조(soft_synergy 계열 — 정본 제외)는 포워드 체킹이 못 본다. "데이터셋에 맞춘 택틱" 비판에는 두 가지로 방어한다 — 포워드 체킹은 도메인 일반 기법이고, 하드 의존(상영표·지역 소속·캘린더)은 이 도메인의 본질이다. 그래도 soft 함정 미해결은 §6에 남긴다.

**S2. 축 순서 최적화** — seq2의 협상 순서는 현재 카탈로그 선언 순서다. 경로 의존의 크기는 순서의 함수이므로, 의존 그래프 기준 "가장 제약된 축 먼저"(MRV 계열)로 재배열하면 봉쇄를 당하는 쪽이 아니라 만드는 쪽을 먼저 닫는다. 통신 불변·로컬 재배열. 위험: 축 순서는 UX 요소일 수 있다(약속 잡기에서 날짜부터가 자연스럽다) — 도메인 제약을 명시하고 측정으로만 판단.

**X1. 합의 후 개선 교환 (양 방안 공통)** — 정착 직후, 축당 1회 "한 축만 바꾼 이웃 조합"을 제안하고 **양쪽 효용이 모두 오를 때만** 교체한다(파레토 개선 패스). seq2의 근시(0.917)와 pool의 압축 미스(0.930)가 공통 겨냥 — plain에서 두 방안 모두 ★5 경계(0.95) 미달인 잔여 갭이다. FR 안전: 개선만 수락하므로 바닥선 위가 불변. 비용 ~n phase(라운드 수 대비 소액).

**(pool FC 보조) 유효-only 풀 강화** — 현 압축은 짝 단위 양립 필터 후 부족분을 **비양립 값으로 채운다**(pool.py `_compress` — "풀 필터가 최종 방어"). 채움분은 풀 자리만 차지하는 사석이다. 유효 조합 필터를 풀 구성 시점으로 승격하면 같은 k로 더 좋은 풀이 된다 — vendor의 [`pool2.py`](../../poc/total/src/total/adapters/composite/_vendor/strategies/pool2.py)(유효-only 조건부 확장)가 선행 구현이라 측정 비용이 낮다.

### 2.2 RU 겨냥 (pool의 결함 축 — r P95 48.2% ★1, 한도 초과 11건, 극단 4.7GB)

**P2. 지연 실물화 (lazy pool)** — 풀의 정체성(전 축 한 판 협상)은 유지하고 **저장만 버린다**: kⁿ 조합을 리스트로 실물화하는 대신, 축별 top-k 목록(k·n개 값)만 들고 lazy k-best 힙으로 "다음 제안"을 필요한 만큼 생성한다. **같은 저장소의 naive 기준선([`baseline.py`](../../poc/total/src/total/adapters/composite/baseline.py))이 이미 이 기법을 실증했다** — 전체 공간(최대 6×10^11)을 열거 없이 정확한 효용 내림차순으로 방출한다. 실물화 저장 O(kⁿ) → O(k·n + 방출 접두). 방출 순서 = 정렬 순서이므로 제안 순서·프로토콜 불변 → FC·TB 중립이 설계 목표다(구현 검증 필요 — §6). 기대: 18-20축 실물화 중앙 18-38MB·극단 4.7GB가 kB 규모로 — 63 결론의 "≤16축 조건부"가 걸린 축.

**P1. 선별 심화 + 한도 인지 게이트** — 현 deepening은 **전역 k+1 → 전 축 재압축**이라 한 번 심화할 때마다 풀이 지수적으로 다시 자란다(pool.py L88-94). 두 가지로 다듬는다: ① 심화를 교착 원인 축(마지막 거절들의 충돌 축)에만 적용(per-axis k — pool2의 "충돌 축 교체 재협상"이 유사 발상), ② 심화 전에 예상 ∏k_i를 계산해 예산(한도의 일정 비율)을 넘으면 심화 대신 현 풀로 정착을 시도. 극단값 2건(r 19.7·36.9)의 직접 원인인 "심화 폭주"를 게이트가 자른다. P2가 채택되면 ①만 남고 ②는 자연 소멸(저장이 없으므로) — P2의 보험이다.

**P4. 의제 분할 (보류)** — 의존 그래프의 연결 성분 단위로 축을 블록화해 블록별로 협상. 성분 간에는 하드 규칙이 없으므로 실행가능성 불변, 풀 크기는 k^(최대 블록)으로 감소. 보류 사유: 소프트 시너지가 블록 경계에서 끊겨 FC 위험이 있고, RU 이득은 P2와 중복된다. P2 실패 시 재검토.

### 2.3 TB 겨냥 (seq2의 결함 축 — ρ P95 4.24 ★0, 결함 152건)

**S3/P3. 배치 제안** — §1의 T1/T3 이식. 62 실측에서 nparty P95 0.689→0.368의 주역이었고, composite도 라운드가 시간의 지배 항(63 I절: CR seq2 T 중앙 9.0s ≈ 라운드 62 × 150ms)이라 같은 논리가 선다. seq2 ρ>1의 두 원천 — 함정 백트랙(49/53)과 plain 꼬리(101/302) — 중 **plain 꼬리**를 겨냥한다(함정 쪽은 S1의 몫).

**S4. 반복 생략 + 정체 조기 인지** — §1의 T2 변형. 쌍방 반복 제안 = 정보 증가 없는 정체이므로, K라운드 연속 정체면 축 정착(현 최선 수락) 또는 축 결렬을 조기 선언. no_deal의 상한 소진(60라운드 = 9s)과 plain 꼬리를 함께 줄인다.

주의(측정 정의): TB 택틱은 설계 쪽 T만 줄인다 — **naive 기준선은 측정 정의라 불변**이다(63 A4). 기준선을 같이 줄이는 변형은 ρ의 뜻을 무너뜨리므로 고려 대상이 아니다.

## 4. 우선순위 권고

1. **S1 (seq2 제약 전파)** — 유일하게 FC·TB를 동시에 겨냥하고, seq2의 두 결함(함정 결렬·ρ 꼬리)의 공통 원인을 제거한다. 방안 1이 "품질·시간 다 지는 안"에서 벗어나는지가 걸려 있어 **구도 검증 가치**가 가장 크다.
2. **P2 (pool 지연 실물화)** — 63 종합 결론이 "방안 2, 단 ≤16축 조건부"다. P2가 성공하면 그 조건이 사라진다 — **최종 설계 선택을 바꿀 수 있는 유일한 한 방**. 기법 실증(baseline.py)이 저장소 안에 이미 있어 리스크도 낮은 편.
3. S3/P3+S4 배치·정체 인지 — 등급 1칸 보완, 구현 단순.
4. X1, P1, 유효-only 풀 — 잔여 갭·보험.
5. 보류 P4 / 기각 커밋·결렬 조기 선언 (§1·§2.2).

- **vendor 불변 원칙**: 62 §2와 동일 — 전략 서브클래스·어댑터 계층 변형([`tactics`] 대응물은 composite adapters 아래 신설), 측정 하니스는 `--plans` 확장만.
- **판**: FIN 500건 정본 재사용, 판정 체계·세션 상한(60스텝)·합성 상수 동일. 방안 축: `seq2 / seq2+S1 / seq2+S1+S3S4 / pool / pool+P2 / pool+P2+P3 / (+X1 조합)`.
- **안전성 게이트** (62 §4.3 대응): 합의/결렬 케이스 집합의 변화 보고, no_deal 45/45 유지, FR 위반 0, ρ>1·한도 초과 결함 수, 악화 케이스 수와 사유.
- **함정 실효의 재보고 의무**: S1은 FIN의 함정을 구조적으로 무력화할 수 있다 — 그러면 "함정 판 53건"의 판별력 자체가 변한다. 택틱 적용 후에는 63 F절(함정 실효)을 다시 계산해 공개하고, 필요하면 soft 기반 함정의 재도입을 후속 검토한다(현재 코드 보존 상태 — `plant_pool_trap`).

## 6. 한계

1. **측정 전 제안이다** — 본 문서의 기대는 전부 가설이고, 채택은 §5 측정 후에만 한다.
2. S1의 정조준은 FIN 함정이 하드 규칙 기반인 데서 온다 — soft 감점 구조는 못 보며, 이 비대칭은 데이터셋 재설계(soft 함정) 없이는 검증되지 않는다.
3. P2는 "방출 순서 = 실물화 순서"가 지켜져야 FC·TB 중립이다 — 현 pool 구현의 제안 순서와 힙 방출 순서의 동치는 이론상 성립하나 구현 검증이 필요하다.
4. 배치 제안의 phase 계상(라운드당 1 phase에 k건 — 51 §4·62 §2와 같은 병렬 전송 가정)은 합성 시간 모델의 가정 위에 있다 — ENV-B에서 재검증 대상.
5. X1의 "양쪽 개선만 수락"은 전략적 허위 응답(개선인데 거절)을 막지 못한다 — 2인 협상의 인센티브 문제는 본 PoC 범위 밖으로 명시한다.
