# 30. 설계 문제 총괄 — 채택 목록·의존 관계·공통 평가 방법

> 배경: [`08`](08-핵심-QA-중요도-난이도-평가.md) §8.4의 설계 질문 9가지에 대해 PL이 채택 여부를 결정했다 (2026-08-05).
> 본 문서는 채택된 문제의 목록, 각 문제를 다루는 설계 문서(31~38)의 배정, 문제 사이의 결정 의존 관계,
> 그리고 모든 설계 문서가 공통으로 따르는 평가 방법을 정의한다.

## 30.2 문제 간 결정 의존 관계

어떤 문제의 결정이 다른 문제의 대안 공간을 좁히는지를 명시한다. 작성·결정 순서는 이 의존을 따른다.

```
31 제안 토폴로지 ──→ 33 이탈·무응답 (감지·재구성의 주체가 토폴로지에 의존)
31 제안 토폴로지 ──→ 36 합의 확정   (확정 전파가 제안 채널을 재사용할지가 대안이 됨)
31 제안 토폴로지 ──→ 35 개입 시점   (checkpoint의 경계인 "라운드"의 정의가 토폴로지에 의존)
32 완결 규칙   ──→ 33 이탈·무응답 (참여자가 줄었을 때 완결 규칙 재적용 방법)
32 완결 규칙   ──→ 36 합의 확정   (확정 당사자의 범위를 완결 규칙이 정함)
37 의제 분해   ──→ 38 시나리오 가변성 (어젠다 표현 방식이 프로세스 템플릿의 표현력에 포함되어야 함)
```

- **1차 작성 (의존 없음)**: 31, 32, 34, 37
- **2차 작성 (1차 결정 참조)**: 33, 35, 36, 38
- 34(정보 공개 구조)는 다른 결정과 독립적이나, 도입되는 component가 31의 통신 경로 위에 놓이므로 31의 대안별 영향을 함께 서술한다.

## 30.3 공통 평가 방법 (31~38 전 문서 적용)

1. **평가 축**: [`20`](20-핵심-QA-확정.md)의 확정 QA 10개만 사용한다. 다른 QA는 표에 넣지 않는다 (PL 확인, 2026-08-05).
2. **대안 수**: 2~3개. 각 대안은 **SW component 구성이 서로 다른** 구조여야 한다 — 같은 component 구성에서 파라미터나 정책만 다른 것은 별개 대안이 아니다.
3. **배타성**: 대안들은 서로 결합해서 동작할 수 없어야 한다. 결합 가능하면 그 결합형을 하나의 대안으로 재구성한다. 각 문서에 "왜 결합할 수 없는가"를 명시한다.
4. **비지배(non-dominance)**: 어느 한 대안이 10개 QA 전부에서 다른 대안과 같거나 우수하면 안 된다. 모든 대안은 이기는 QA와 지는 QA를 함께 가져야 한다. 스틸맨(각 대안을 가장 강한 형태로 구성)으로 세워도 지배가 발생하면 그 대안을 버리고 경쟁력 있는 대안으로 교체한다 — 단, 지배 사실을 숨기고 억지 trade-off를 만들지 않는다.
5. **평가 표기**: 대안별로 각 QA에 **유리(+) / 중립(0) / 불리(−)** 를 매기고, 모든 셀에 그렇게 판단한 이유를 문장으로 쓴다. 기호만 있는 표는 금지.
6. **서술 원칙**: 쉬운 표현으로 풀어서 쓴다. 기술 용어는 영어 원문을 쓴다(예: Coordinator, checkpoint, broadcast). 함축적인 어휘 대신 "이 component가 무엇을 받아서 무엇을 하고 무엇을 내보내는가"를 명시적으로 쓴다.
7. **도식**: 모든 대안은 component diagram을 drawio로 작성한다 (프로젝트 규칙 — 도식은 `.drawio`).
   - 저장 위치: [`drawio/`](drawio/) 폴더
   - 파일명 규칙: `<주제번호>-<대안번호>-<대안이름>.drawio` (예: `31-A-Coordinator-집계형.drawio`)
8. **문서 템플릿** (전 문서 동일):
   - §1 문제 정의 — 무엇이 왜 문제이고, 잘못 풀면 무슨 일이 생기는가
   - §2 전제와 제약 — 이 문제에서 바뀌지 않는 것 (NegMAS 기반 알고리즘, 온디바이스 실행, A2A 메시징 등)
   - §3 대안 A/B/(C) — component 목록과 역할, 연결과 데이터 흐름, 정상 시나리오, 오류 시나리오, drawio 링크
   - §4 QA trade-off 평가표 (10개 축 × 대안)
   - §5 배타성 확인 · §6 비지배 확인
   - §7 다른 문제와의 결정 의존
