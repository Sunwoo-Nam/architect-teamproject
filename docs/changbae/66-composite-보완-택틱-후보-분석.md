## 2. composite 고유 택틱 카탈로그 — QA별

63이 규명한 결함의 원인 구조에서 출발한다: ① seq2의 손실은 **"막힘을 협상으로야 발견하고, 원인을 모른 채 시간순으로 되돌아가는"** 백트랙 구조에서, ② pool의 손실은 **"kⁿ을 저장하고, 막히면 전 축 k를 올려 지수 재성장하는"** 실물화 구조에서 나온다. ③ 양 방안 공통으로, 이미 합의될 축까지 협상 라운드를 태운다.

### 2.1 FC 겨냥

**S1. 제약 전파 (포워드 체킹)** — seq2가 축 값을 확정하기 **전에**, 공유 하드 규칙으로 남은 축들의 도메인 축소를 로컬 계산한다(CSP 표준 forward checking — 통신 0 phase). 유인값(0.95)이 뒤 축의 좋은 값(0.90)을 전부 봉쇄한다는 사실은 규칙만 보면 알 수 있는데, 현 구현은 확정 후 뒤 축 **협상에서** 발견한다 — 63 실측: 함정 53건 중 43건 결렬(달성률 0.43-0.59), 함정 라운드 중앙 121. 값 후보의 효용에 "뒤 축 도메인 손실"을 감점으로 반영하면 유인값이 애초에 제안 우선순위에서 밀린다. **FC와 TB를 한 번에** 겨냥하는 후보.

**S5. 충돌 지향 백점프 (conflict-directed backjumping)** — 현 백트랙은 막힌 축의 원인과 무관하게 **무조건 직전 축(i−1)을 금지**한다(sequential.py — `prev = scenario.axes[i-1]`). FIN 함정처럼 원인 축(앞 축 e)과 막힌 축(뒤 축 L)이 떨어져 있으면, 무관한 중간 축들을 차례로 되돌리며 세션을 연쇄로 태운다. 막힌 축의 하드 규칙에서 **원인 축을 식별해 곧장 점프**하면(availability 규칙의 antecedent 축 — 공유 정보라 식별 가능) 회복 비용이 축 거리에 비례하지 않게 된다. S1이 함정을 사전 회피하는 택틱이라면 S5는 **잔여 막힘의 사후 회복 비용**을 줄이는 짝 — S1+S5를 한 패키지로 본다. CSP의 표준 기법이라 도메인 특화 조작이 아니다.

**P5. soft-인지 압축 (pool)** — pool의 압축 순위는 한계효용 w·score만 보고 **soft 감점(조건부 규칙)을 무시**한다(pool.py `_marginal`). seq2는 같은 문제를 이미 `soft_aware=True`(seq→seq2 개선의 T1)로 고쳤고 그것이 정본 방안이다 — **같은 아이디어의 pool 이식**이 비어 있다. 감점 반영 점수로 압축하면 같은 k로 더 좋은 풀이 된다. plain pool FC 0.930(★5 경계 미달)의 잔여 갭 겨냥.

**X1. 합의 후 개선 교환 (양 방안 공통)** — 정착 직후 축당 1회 "한 축만 바꾼 이웃 조합"을 제안하고 **양쪽 효용이 모두 오를 때만** 교체(파레토 개선 패스). seq2의 근시(0.917)와 pool의 압축 미스(0.930)를 공통 보완. FR 안전(개선만 수락 → 바닥선 위 불변), 비용 ~n phase.

**S2. 축 순서 최적화** — 의존 그래프 기준 "봉쇄를 만드는 축 먼저"(MRV 계열) 재배열로 경로 의존 노출 자체를 줄인다. 위험: 축 순서는 UX 요소일 수 있음(약속 잡기는 날짜부터가 자연스럽다) — 도메인 제약 명시 후 측정으로만 판단.

**(pool FC 보조) 유효-only 풀 강화** — 현 압축은 양립 필터 후 부족분을 **비양립 값으로 채운다**(`_compress` — "풀 필터가 최종 방어"). 채움분은 풀 자리만 차지하는 사석. 유효 필터를 풀 구성 시점으로 승격 — [`pool2.py`](../../poc/total/src/total/adapters/composite/_vendor/strategies/pool2.py)의 유효-only 확장이 선행 구현이라 측정 비용이 낮다.

### 2.2 RU 겨냥 (pool의 결함 축 — r 최대 3,692% ★0 · P95 48.2% ★1, 한도 초과 11건, 극단 4.7GB)

**P2. 지연 실물화 (lazy pool)** — 풀의 정체성(전 축 한 판 협상)은 유지하고 **저장만 버린다**: kⁿ 조합 리스트 대신 축별 top-k 목록(k·n개 값)만 들고, lazy k-best 힙으로 "다음 제안"을 필요한 만큼 생성한다. **같은 저장소의 naive 기준선(baseline.py)이 이 기법을 이미 실증** — 전체 공간(최대 6×10^11)을 열거 없이 정확한 효용 내림차순으로 방출한다. 실물화 저장 O(kⁿ) → O(k·n + 방출 접두). 방출 순서 = 정렬 순서이므로 제안 순서·프로토콜 불변 → FC·TB 중립이 설계 목표(§6 구현 검증 항목). 기대: 18-20축 실물화 중앙 18-38MB·극단 4.7GB → kB 규모. **63 결론의 "≤16축 조건부"가 걸린 축이라, 성공하면 최종 설계 선택의 조건 자체가 바뀐다.**

**P6. k 비대칭 배분** — 현 압축은 전 축 동일 k다. 가중치가 낮은 축은 k=1이어도 총효용 손실이 작고, 높은 축은 k를 더 줘야 한다 — 예산 ∏k_i ≤ B 아래에서 가중치 비례로 k를 차등 배분하면 **같은 메모리로 더 좋은 풀**(FC)이거나 **같은 풀 품질을 더 작은 메모리로**(RU) 얻는다. P2와 독립적으로 성립하고 결합도 된다.

**P1. 선별 심화 + 한도 인지 게이트 (P2의 보험)** — 현 deepening은 **전역 k+1 → 전 축 재압축**(pool.py L88-94)이라 심화마다 풀이 지수 재성장한다. ① 심화를 교착 원인 축에만 적용(per-axis k — pool2의 "충돌 축 교체 재협상"이 유사 발상), ② 심화 전 예상 ∏k_i가 예산을 넘으면 심화 대신 현 풀로 정착 시도. 극단값 2건(r 19.7·36.9)의 직접 원인(심화 폭주)을 게이트가 자른다. P2 채택 시 ②는 자연 소멸.

**P4. 의제 분할 (보류)** — 의존 그래프 연결 성분 단위 블록 협상. 성분 간엔 하드 규칙이 없어 실행가능성 불변, 풀 크기 k^(최대 블록). 보류 사유: 소프트 시너지가 블록 경계에서 끊겨 FC 위험 + RU 이득이 P2와 중복. P2 실패 시 재검토.

### 2.3 TB 겨냥 (seq2의 결함 축 — ρ P95 4.24 ★0, 결함 152건 / pool ★2)

**X2. 불일치 우선 협상 (양 방안 공통, 신규)** — 협상 첫 교환에서 서로 "축별 수락 가능 상위 집합"을 공개하고, **겹치는 축은 즉시 잠정 확정, 불일치 축만 협상**한다. 63 실측의 plain 판 다수는 mid 충돌(상관 ≈ 0)이라 상당수 축이 사실상 다툼거리가 아닌데도 라운드를 태운다 — seq2는 그 축들에도 세션을 하나씩 연다. 판정 관점의 비용: composite의 담당 QA에 CF가 없으므로 **선호 공개가 판정상 무비용**이다(nparty였다면 CF를 침식해 성립 불가였을 택틱 — QA 분업이 만든 composite 고유의 여지). 제품 관점의 프라이버시 우려는 남으므로 §6에 명시. 기대: seq2 plain 라운드 중앙 54의 상당 부분 절약 + pool도 불일치 축만으로 풀 축소(RU 부수 이득).

**S3/P3. 배치 제안 (62 이식)** — 라운드당 k개. 62 실측에서 nparty P95 0.689→0.368의 주역이었고, composite도 라운드가 시간의 지배 항이라 같은 논리. seq2 ρ>1의 두 원천(함정 백트랙 49/53, plain 꼬리 101/302) 중 **plain 꼬리** 담당(함정은 S1+S5의 몫).

**S4. 반복 생략 + 정체 조기 인지 (62 변형 이식)** — §1. no_deal의 상한 소진(60라운드 = 9s)과 plain 꼬리를 함께 절약.

**S6. 독립 축 병렬 세션 (seq2, 신규)** — 의존 그래프에서 서로 독립인 축들의 세션을 **같은 라운드에 병렬 진행**(메시지 묶음). 페이즈 계상은 배치 제안과 같은 병렬 전송 가정(51 §4·62 §2)을 따른다. seq2의 T가 "세션 수 × 세션 라운드"라는 구조 비용을 세션 수 → 의존 사슬 길이로 줄인다. 순차 확정의 정체성이 "의존이 있는 곳에서만 순차"로 정련되는 것이라 방안 1의 정의를 해치지 않는다고 보나, 경로 의존 동학이 바뀌므로 FC 영향은 측정으로 확인해야 한다.

**기각 — 기준선 조정 계열**: TB를 "naive를 느리게 잡아" 개선하는 어떤 변형도 고려하지 않는다 — 기준선은 측정 정의다(63 A4). 택틱은 설계 쪽 T만 줄인다.

## 4. 우선순위 권고

1. **S1+S5 패키지 (seq2)** — 유일하게 FC·TB를 동시에 겨냥하며 seq2 두 결함의 공통 원인(막힘의 늦은 발견 + 맹목 백트랙)을 제거한다. 방안 1이 "품질·시간 다 지는 안"에서 벗어나는지 — **구도 검증 가치 최대**.
2. **P2 (pool 지연 실물화)** — 63 종합 결론 "방안 2, 단 ≤16축 조건부"의 조건을 지울 수 있는 **유일한 한 방**. 기법 실증(baseline.py)이 저장소 안에 있어 리스크도 낮은 편.
3. **X2 불일치 우선** — 양 방안 공통 TB 레버, composite의 QA 분업이 만들어 준 고유 여지. 구현 단순.
4. S3/P3+S4 배치·정체 인지, P5, P6, X1.
5. 보류: P4, S2, S6(FC 동학 변화 검증 부담). 기각: 커밋 매칭, 결렬 조기 선언, 기준선 조정.

## 5. 측정 계획 (62 방법론 그대로)

- **vendor 불변 원칙**: 전략 서브클래스·어댑터 계층 변형(62 §2 대응 — composite adapters 아래 `tactics` 신설), 하니스는 `--plans` 확장만.

## 6. 한계

1. **측정 전 제안** — 기대는 전부 가설이며 채택은 §5 측정 후에만.
2. S1의 정조준은 FIN 함정이 하드 규칙 기반인 데서 온다 — soft 감점 구조는 못 보고, 이 비대칭은 soft 함정 데이터셋 없이는 검증 불가. (S5·백점프도 하드 규칙에서만 원인 축을 식별한다.)
