> **다이어그램**: [candidates.drawio](./[초안]DP-추론-컨텍스트-다중화-candidates.drawio) — 페이지 1: 후보 A / 페이지 2: 후보 B

## 0. 용어

이 문서를 읽는 데 필요한 최소 용어. AI 모델 내부 지식은 필요 없다.

| 용어 | 뜻 |
|---|---|
| 토큰 | 모델이 텍스트를 세는 단위. 한글 1자 ≈ 1~2토큰. 4K(4,000) 토큰 ≈ 문서 한 편 + 지시문 |
| 컨텍스트 | 모델에게 준 작업 맥락 전체 — 지시문 + 작업 내용 + 그간의 대화. 토큰열로 표현됨 |
| KV 캐시 | 모델이 컨텍스트를 읽으며 만들어 두는 중간 계산 결과. 이것이 있어야 매 응답마다 처음부터 다시 읽지 않는다. **크기가 컨텍스트 길이에 비례해 자란다** |
| 프리필 | 컨텍스트를 읽어 KV 캐시를 만드는 단계. 길수록 오래 걸린다 (수천 토큰이면 초 단위) |
| 세션 | 플랫폼이 KV 캐시를 유지해 주는 대화 단위. 세션이 살아 있으면 이어서 바로 질문 가능 |
| 상주 (warm) | 세션의 KV를 메모리에 유지해 둔 상태. 응답이 즉시 시작되는 대신 메모리를 점유 |
| 재구축 | 버린 컨텍스트를 원천 데이터(이벤트 로그·문서 상태)에서 텍스트로 다시 만들어 프리필하는 것. 시간이 들지만 메모리는 안 든다 |
| LoRA 어댑터 | 베이스 모델 위에 얹어 특정 기능의 정확도를 높이는 소형 추가 가중치. 본 시스템에서는 **모듈(기능) 단위**로 하나씩 둔다 |
| 양자화 | 숫자의 표현 정밀도를 낮춰(16비트→8→4) 메모리를 줄이는 손실 압축. **모델 가중치와 KV 캐시에 각각 별도로 적용된다** — "모델이 int4"라는 정보는 가중치 얘기이며, KV의 양자화는 별도 확인 사항 |
| K | 동시에 살아 있는 장문 세션의 수 |

## 1. 문제 정의

시스템에 탑재된 4B 모델은 하나이고, 이를 쓰는 소비자는 여럿이다(협상, collaboration, 조회 계획 수립 등). 각 소비자의 컨텍스트는 KV 캐시라는 실물 메모리로 실체화된다. 가중치는 int4로 확정(P7)이나 **KV 캐시의 양자화는 미확인**이므로, 규모는 범위로 산정한다 (4B급 전형 구조 추정, 4K 컨텍스트 한 벌 기준):

```
KV fp16 : 토큰당 ~128KB → 4K 한 벌 ~520MB   ← 한 벌부터 예산(300MB) 초과
KV int8 : 토큰당  ~64KB → 4K 한 벌 ~260MB   ← 한 벌이 예산을 거의 소진
KV int4 : 토큰당  ~32KB → 4K 한 벌 ~131MB   ← 두 벌(K=2)이 경계선
```

**어느 시나리오에서도 컨텍스트를 전부 상주시킬 수는 없다** — KV가 정밀할수록 문제는 더 아파질 뿐이다. 따라서 "무엇을 유지하고 무엇을 버렸다가 다시 만들 것인가"라는 배치 결정이 강제되며, 이것이 본 DP다. KV의 실제 dtype은 후보 B의 생존 가능 K값을 정한다 (fp16이면 K=1도 불가, int4면 K=2 경계).

단, 위 산정은 확인 불가한 모델 내부 구조에 의존한다. 따라서 본 문서는 규모를 사실로 단정하는 대신, **이 결정이 유의미해지는 최소 조건(§2)을 전제로 선언**하고, 조건이 깨질 경우의 답까지 미리 정해 둔다. 조건은 전부 실기기 측정으로 사후 검증 가능하다(§8).

## 2. 적용 조건 — 이 DP가 유의미해지는 최소 전제

아래 조건은 이 DP에 유리한 가정이 아니라, **이 경계 밖에서는 답이 자명해져 비교가 불필요해지는** 최소 조건이다. 조건 밖의 답이 표에 정해져 있으므로, 검증이 어느 쪽으로 나와도 결정은 닫힌다.

| # | 조건 | 근거 | 깨질 경우의 답 | 검증 수단 |
|---|---|---|---|---|
| AC-1 | 동시 활성 장문 세션 K ≥ 2 | 장문 모듈 세션은 수명이 일·주 단위라 복수 동시가 자연스러움 | **A 채택** (경쟁 상황 자체가 없음) | 제품 기획 확정 시 |
| AC-2 | 컨텍스트 한 벌의 KV ≥ 예산의 약 1/3 (≈100MB, 컨텍스트 ~3K 토큰 이상이면 충족) | int4 확정 + 전층 전역 어텐션이 표준 구성 | **B 채택** (전부 상주 가능하므로 고민 불필요) | PoC-1 메모리 곡선 또는 PoC-2 지연 곡선 |
| AC-3 | 재구축 지연이 무시 불가 (1회 수 초 이상) | 모바일 NPU에서 수천 토큰 프리필은 통상 초 단위 | **A 채택** (다시 만드는 게 공짜면 유지할 이유 없음) | PoC-2 |

## 3. 전제

| # | 전제 |
|---|---|
| P1 | 베이스 모델 = 시스템 탑재 4B 고정. 추가 모델 탑재 불가 (메모리 제약) |
| P2 | LoRA 어댑터는 **모듈 단위** (협상 / collaboration / 지식공유). 같은 모듈의 세션들은 같은 어댑터를 공유한다. 모듈 소속이 아닌 공통 추론(조회 계획 수립, MA 의도 해석)은 어댑터 없이 베이스 모델로 수행 |
| P3 | 플랫폼 접근 권한 = 시스템 컴포넌트 계층 (공개 서드파티 API가 아님. 세션 핸들 제공을 전제). 백그라운드 추론 허용 확인됨 |
| P4 | KV 캐시는 (어댑터, 토큰열) 조합에 묶인다. **어댑터가 다르면 같은 텍스트라도 KV를 재사용할 수 없다** |
| P5 | 같은 어댑터 아래에서 컨텍스트의 앞부분(prefix)이 같으면 그 부분의 KV는 재사용 가능. P2에 따라 이 재사용은 모듈 내부로 한정됨 |
| P6 | 모든 컨텍스트는 원천에서 재구축 가능해야 한다. 협상 모듈은 이벤트 로그 100% 기록(NFR-MAF-08)으로 이미 보장됨. **타 모듈은 E1 커널 이벤트 로그 채택 시 자동 보장, 미채택 시 모듈별 개별 검증 필요** (미해결 — 노브 5) |
| P7 | **가중치 양자화 = int4** (확정 — 모델 파일 기준). **KV 캐시 양자화는 미확인** — fp16~int4 범위이며, 토큰당 실효 크기는 PoC-1 메모리 곡선의 기울기로 판정 |
| P8 | 세션 KV의 물리 소재는 **플랫폼 AI 서비스 측**이다 (우리 프로세스가 아님). 따라서 ① 상주는 플랫폼이 회수할 수 있는 **최선 노력(best-effort)** 이며 보장이 아니다 — 재구축 경로는 어느 후보에서도 필수, ② 메모리 상한은 우리 예산과 플랫폼 쿼터 중 작은 쪽이 실효 상한 |

## 4. 사내 확인 대상 (플랫폼 API 스펙)

답변이 오면 후보와 결정 규칙이 자동으로 좁혀진다. 미회신 상태로도 문서는 성립한다.

| # | 질문 | 답이 정하는 것 |
|---|---|---|
| ① | 세션 핸들이 존재하는가. 동시 세션 수 상한은 | 후보 B의 성립 |
| ② | 동시에 로드 가능한 어댑터 수 (활성 모듈 종수만큼 필요, 통상 2~3). 어댑터 1개를 갈아끼우는 지연은 | 모듈 교차 호출 시 숨은 비용 |
| ③ | 세션 KV를 저장했다 복원하는 API가 있는가 | 부록 후보 C의 성립 |
| ④ | 동일 prefix의 KV 재사용을 플랫폼이 지원하는가 | 후보 A의 재구축 비용 |
| ⑤ | 컴포넌트당 세션 수·메모리·추론 쿼터 계약 | 후보 B의 K 상한 (P8-②) |
| ⑥ | **어댑터를 장착한 세션이 유지되는 중에 어댑터 없는(베이스) 추론 요청을 처리하면, 그 세션의 KV는 보존되는가** | 상주라는 개념의 실효성 — 미보존이면 베이스 호출이 낄 때마다 상주 세션이 파괴되어 A·B 모두 전제가 흔들림 |
| ⑦ | KV 캐시의 양자화(dtype) — fp16 / int8 / int4 | §1 산정표의 어느 행이 실제인지, 후보 B의 생존 가능 K값 (미회신 시 PoC-1 실측으로 대체) |

## 5. 공통 설계 (후보와 무관하게 확정)

- **프롬프트 구조 규율**: 바뀌지 않는 부분(시스템·모듈 지시)을 앞에, 바뀌는 부분(작업 내용·경과)을 뒤에 배치한다. P5의 prefix 재사용을 최대화하고, 재구축 시 다시 계산할 범위를 최소화하기 위함.
- **컨텍스트는 캐시이지 진실이 아니다**: 어떤 컨텍스트도 잃으면 끝이어서는 안 된다. 원천에 없는 정보를 컨텍스트에만 쌓는 설계를 금지한다 (P6). 세션 중 결정된 사항은 원천(로그·문서)에 기록하는 책임이 각 모듈에 있다.
- **Context Scheduler — 단일 창구**: 모든 소비자는 플랫폼 세션을 직접 잡지 않고 이 관리자를 경유한다. 이유 셋: (a) 세션 총량·메모리 회계를 한 지점에서 강제할 수 있어야 본 DP의 결정이 집행 가능하다, (b) 소비자 코드가 후보 A/B와 무관해져, 결정이 바뀌어도 관리자 구현체만 교체하면 된다, (c) 모든 추론이 지나는 이 길목이 향후 자원 중재(DP-D1)가 삽입될 자리다 — 지금은 자리만 예약.

## 6. 컨텍스트 수요 (누가 얼마나 쓰나)

컨텍스트의 단위는 (모듈 × 세션)이다 — 같은 모듈이라도 작업(세션)이 다르면 별개 컨텍스트.

| 소비자 | 컨텍스트 성격 | 길이 | 호출 패턴 |
|---|---|---|---|
| 장문 모듈 (유력: collaboration — 미확정) | 작업 대상 내용 자체가 맥락 (문서 등). 세션 수명 일·주 단위 | 길다 (수천 토큰) | 세션 중 산발 반복 — **유일한 상주 후보** |
| 협상 모듈 | 경과의 진실은 결정론 계층의 이벤트 로그가 소유. LLM은 자기 후보 스코어링 시에만 짧게 호출 | 짧다 | 세션 시작·개정 시점에 몰아서 (버스트). 상주 대상 아님 |
| 공통 추론 (조회 계획, 의도 해석) | 과제 단위 일회성 | 짧다 | 수시. 베이스 모델(무어댑터) |

결론: 문제는 "모든 소비자의 공평한 배치"가 아니라 **"장문 세션 K벌을 어떻게 유지하고, 짧은 호출들이 끼어들 때 어떻게 처리하나"** 로 좁혀진다.

## 7. 후보안

**후보의 층위에 대하여**: 두 후보는 서로 다른 아키텍처 스타일이 아니다 — 토폴로지(소비자 → 단일 창구 → 플랫폼)는 양쪽이 동일하며, 이는 후보 교체 가능성을 위해 §5에서 **의도적으로 고정한 상위 결정**이다. 후보 간 차이는 창구 내부의 상태 관리 패턴이다: A는 **cache-aside(단일 슬롯)** — 컨텍스트를 원천의 파생물로 보고 miss 시 재계산, B는 **resource pool + admission control** — 만들기 비싼 자원(프리필된 세션)을 장부(Registry)로 관리하고 상한 게이트로 입장을 통제. §8의 별점은 이 패턴 성질에서 도출된다 (무상태 → 복구 단순·결함 표면 최소 / 풀 상태 → 지연 예측성·장부 정합성 부담). 본 DP의 아키텍처적 무게는 후보 간 차이가 아니라 **단일 창구 강제와 K 상한이 QAS-011의 집행 메커니즘**이라는 점에 있다.

**공통 리스크 — 어댑터 갈아끼우기 비용**: 모듈이 다르면 어댑터가 다르고(P2), 어댑터가 바뀌면 KV를 못 쓴다(P4). 확인 ②가 "동시 로드 1개"로 판명되면 모듈을 오가는 호출마다 어댑터 교체 + 재프리필의 이중 비용이 발생한다. 두 후보 모두에 걸리는 외생 변수이므로 후보 차별점이 아니다.

### 후보 A — 단독 상주 + 재구축 (cache-aside 패턴)

장문 컨텍스트를 **1벌만** 상주시킨다. 짧은 호출(협상 스코어링, 베이스 추론)은 임시 세션을 만들어 쓰고 즉시 버린다. 장문 세션이 2개 이상이면 활성 1개 외에는 버리고, 그 세션의 호출이 돌아올 때 원천에서 재구축한다.

- **강점**: 메모리가 "대형 1벌 + 소형 임시"로 고정 — 예산 회계를 수식으로 쓸 수 있다. 플랫폼 API 요구가 최소(①만 있으면 됨). 재구축 경로가 곧 크래시·플랫폼 회수 시의 복구 경로라 별도 복구 코드가 없다.
- **약점**: K ≥ 2에서 장문 세션을 오갈 때마다 재프리필 지연을 전액 지불 (프리필 속도 × 가변부 길이 — PoC-2). 단 장문 세션은 호출 간격이 길어 전환 빈도 자체가 낮을 수 있다 (PoC-5).

### 후보 B — 활성 세션별 상주 (resource pool 패턴)

활성 장문 세션 K벌을 **각각** 상주시킨다. 같은 모듈의 세션들은 같은 어댑터를 공유한다. 관리자는 세션 목록(Registry)과 상한 게이트를 소유하며, K+1번째 요청은 거절/강등 여부를 도메인(MA)에 넘긴다 (노브 2).

- **강점**: 전환 지연 ~0, 응답 시간이 예측 가능. 모듈 교차 호출에도 (확인 ② 지원 시) 각 세션 KV가 오염되지 않는다.
- **약점**: 메모리 = K × 컨텍스트 크기 — §1 산정대로면 K=2에서 예산 소진이 유력. **성립 조건이 산수 하나다: K_요구 × 실측 크기(PoC-1) ≤ min(예산, 쿼터⑤).** 탈락하면 K+1 처리에 어차피 재구축을 내장하게 되어 A로 수렴한다. P8에 따라 상주가 보장이 아니므로 재구축 경로는 B에서도 병설 필수 (복구용).

*(후보 C — 상주 + KV 저장/복원 스왑: 확인 ③의 존재를 전제하므로 부록으로 분리. ③ 확인 시 재검토.)*

## 8. 품질 속성 비교 (ISO/IEC 25010 축)

† = 측정 전 조건부. 별점 근거는 구조에서 나오는 것만 인정.

| 축 (풀이) | A 단독 상주 | B 세션별 상주 |
|---|---|---|
| 응답 시간 — 장문 세션 전환 (Time behaviour) | ★†~★★ — 재프리필 지불. prefix 재사용(④)과 낮은 전환 빈도(PoC-5)면 ★★ | ★★★ — 항상 warm |
| 응답 시간 — 짧은 호출 끼어들기 | ★★ — 임시 세션 생성 비용 (PoC-4) | ★★★ |
| 메모리 상한과 회계 (Resource utilization) | ★★★ — 1벌 고정, 수식화 가능 | ★† — K에 비례. AC-2가 깨지는(KV가 작은) 모델이면 ★★ 이상 |
| 복구 용이성 (Recoverability) | ★★★ — 재구축 = 복구, 경로 단일 | ★★ — K벌 재구축 필요, 경로는 동일 |
| 결함 표면 (Fault tolerance) | ★★★ — 유지 상태 최소 (포인터 1개) | ★★ — Registry라는 지켜야 할 상태 + 상한 게이트 |
| 플랫폼 API 의존도 (Portability) | ★★★ — ①만 필요 | ★★ — ①+②+⑤ 필요 |
| 모델 업데이트 내성 (Maintainability) | ★★★ — 컨텍스트는 휘발, 원천이 진실 | ★★★ — 동일 |

**읽는 법**: 진짜 승부는 두 칸 — A의 전환 지연† 대 B의 메모리†. 각각 단일 외생 변수에 걸려 있다 (A는 ④+PoC-5, B는 PoC-1). 측정이 오면 표가 자동으로 닫힌다.

## 9. 결정 규칙

```
R1. AC-2 위반 (KV가 작음)                → B 채택, 종결
R2. AC-1 위반 (동시 장문 세션 없음)       → A 채택, 종결
R3. AC-3 위반 (재구축이 충분히 빠름)      → A 채택, 종결
R4. AC 전부 성립 + PoC-1 × K ≤ min(예산, 쿼터⑤)
                                        → B 채택 (재구축 경로 병설 — P8)
R5. R4 탈락                              → A 채택 (④ 지원 시 prefix 재구축 강화)
    (③ 존재 확인 시 부록 C를 R5의 대안으로 승격 재검토)
```

## 부록 — 조건부 후보 C: 소수 상주 + 스왑 (확인 ③ 존재 시 검토)

뜨거운 장문 세션 1~2벌만 상주시키고, 식은 세션의 KV를 저장 API로 내려두었다가 호출이 돌아오면 복원하는 안. 재프리필 대비 복원이 수 배 빠르다는 타 런타임 실측이 근거이나, 해당 API가 내부 플랫폼에 존재하는지 미확인이며(공개 플랫폼 세계에는 사실상 없음), 존재하더라도 ① 저장물에 작업 원문이 녹아 있어 저장 위치·암호화·수명이 프라이버시 검사(DP03) 대상에 편입되고, ② 저장물이 모델 버전에 묶여 시스템 모델 업데이트 시 무효화 처리가 필요하며, ③ 스왑 정책이라는 상태 기계가 추가되어 결함 표면이 가장 크다. R5 상황(B 산수 탈락 + A의 재구축 지연이 실측상 수용 불가)에서만 검토 가치가 있는 3순위.
