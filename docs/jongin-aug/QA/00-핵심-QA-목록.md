# 핵심 QA 목록 — 설계 대안 평가의 축

> 본 문서는 검토 중인 DP 후보들의 대안을 평가하기 위한 품질 축을 정의한다.
> 선정 기준은 **대안 사이에서 실제로 값이 갈리는가**이다. 모든 대안이 공통으로 갖춰야 하는 항목과 위반 0건의 절대 조건은 축으로 쓰지 않는다.
> 평가축은 ISO/IEC 25010:2023(Product quality model)의 품질특성·부특성을 따른다.

---

## 핵심 QA 8개

| # | QA (부특성) | 품질 요구 문장 | 측정 항목 |
|---|---|---|---|
| 1 | **Functional Correctness** | 계획 전체를 하나의 결과로 볼 때, 참여자들의 효용 함수 기준 최적해에 도달한 정도를 최대화해야 한다 | 결합 공간의 파레토 프론티어 기준 근접도와 Nash 근접도. 단계별 최적성 평균과의 격차를 함께 기록 |
| 2 | **Resource Utilization** | 협상 1회가 사용하는 단말 추가 메모리를 정해진 예산 이내로 유지해야 한다 | 세션 구간의 최대 추가 메모리. 조합 전체 생성 여부를 확인하는 보조 지표로 동시 보관 후보 수와 후보 요청 횟수를 기록 |
| 3 | **Adaptability** | 새로운 co-planning 시나리오를 코드 변경 없이 템플릿과 어휘 정의만으로 수용할 수 있어야 한다 | 설계 시 참조하지 않은 시나리오를 템플릿·어휘 등록만으로 정의해 실행. 성공 여부와 코드 변경량 |
| 4 | **Functional Appropriateness** | 협상으로 도달한 합의가 실제 외부 예약까지 완료된 비율을 최대화해야 한다 | 합의 도달 건 대비 예약 성공 건의 비율. 실패 원인을 자원 소진과 그 외로 분리 |
| 5 | **Time Behaviour** | 계획의 실효 기한 안에 계획이 완성된 비율을 최대화해야 한다 | 시나리오마다 실효 기한을 부여하고 기한 내 완성 여부를 판정 |
| 6 | **Fault Tolerance** | 계획이 완성되기 전에 중단되었을 때 확보되는 부분 결과의 비율을 최대화해야 한다 | 임의 시점에 세션을 중단시키고, 유효하게 남는 단계 합의의 비율을 측정 |
| 7 | **Recoverability** | 후행 단계 실패로 선행 단계를 되돌려야 할 때 발생하는 비용을 최소화해야 한다 | 되돌리기 1건당 취소 수수료, 상대 동의 요청 횟수, 되돌릴 수 없어 사용자 결정으로 넘어간 건수 |
| 8 | **Modifiability** | 단계 연결 규칙과 확정 규칙이 바뀔 때 수정·검토해야 하는 지점 수를 최소화해야 한다 | 규칙 변경 시나리오를 미리 정의하고 변경별 수정·검토 지점 수를 계수 |

> **Fault Tolerance와 Recoverability의 구분:** Fault Tolerance는 **협상이 중단되었을 때 이미 도달한 합의가 남는가**를 보며, 협상을 몇 개의 단위로 나누는지가 이 값을 좌우한다. Recoverability는 **이미 확정한 것을 취소해야 할 때 드는 비용**을 보며, 합의를 언제 외부 예약으로 연결하는지가 이 값을 좌우한다. 하나로 합치면 두 선택이 서로 다른 품질을 건드린다는 점이 보이지 않는다.
