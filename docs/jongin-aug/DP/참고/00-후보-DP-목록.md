## 후보 DP1 — 의존 단계의 협상 단위

### 문제

co-planning은 선행 협상의 결과가 후행 협상의 의제를 결정하는 구조다. 영화 협상 결과가 식사 협상의 시간과 지역을 제한하고, 오전 일정 협상 결과가 오후 일정의 출발 지점을 제한한다.

이때 의존 관계로 연결된 단계들을 **하나씩 순서대로 협상할 것인가, 하나의 협상으로 묶을 것인가**를 정해야 한다.

순차로 협상하면 선행 단계를 먼저 정하게 되고, 그 결정이 후행 단계의 선택지를 줄인다. 선행 단계에서 양측 효용이 가장 높은 합의를 골라도, 그 조건에서 후행 단계의 합의 품질이 낮으면 계획 전체로는 더 나은 조합을 놓친다.

묶어서 협상하면 계획 전체를 대상으로 최적을 찾을 수 있으나, 의제에 포함되는 쟁점 수가 단계 수만큼 늘고 단계 간 의존 관계가 쟁점 사이의 제약으로 바뀐다.

### 대안 A — 순차 협상

의존 관계 순서대로 단계를 하나씩 협상한다. 각 단계의 합의는 계획 전체가 완성될 때까지 잠정 상태로 두고, 상위 합의 결과를 하위 단계의 의제 제한 조건으로 전달한다. 후행 단계에서 만족 가능한 조합이 없으면 실패한 조합을 기록하고 선행 단계로 되돌아가 다시 협상한다.

한 협상의 쟁점은 그 단계의 쟁점뿐이며, 단계 간 의존 관계는 협상 밖에서 값 목록을 줄이는 방식으로 처리된다.

### 대안 B — 의존 단계 결합 협상

의존 관계로 연결된 단계들의 쟁점을 하나의 협상 의제에 넣는다. 의존 관계는 쟁점 사이의 제약 조건으로 표현한다.

의제가 커져도 가능한 값 조합 전체를 만들지는 않는다. 쟁점별로 값을 선호 기여도 순으로 정렬해 두고, 상위 조합부터 하나씩 꺼내는 방식으로 후보를 공급한다. 단계별 최소 만족 수준을 조건으로 두어, 한 단계가 그 수준에 미달하는 것이 확정되는 시점에 해당 탐색 분기를 중단한다.

의존 관계 중 값 범위 축소로 바꿀 수 있는 것(예: 앞선 일정의 종료 시각 이후만 유효)은 협상 시작 전에 값 목록에서 제거한다.

### 갈리는 품질 특성

| 품질특성 → 부특성 | 측정 지표 | 대안 A | 대안 B |
|---|---|---|---|
| Functional suitability → Functional correctness | 계획 전체 기준 최적해와의 거리 | 선행 확정이 후행을 제한해 최적을 놓친다. 되돌리기로 일부만 회복한다 | 계획 전체를 대상으로 탐색한다 |
| Performance efficiency → Time behaviour | 계획 완성까지의 총 소요 | 단계 수만큼 누적된다. 되돌리기가 발생하면 더 늘어난다 | 한 번의 협상으로 끝난다 |
| Performance efficiency → Resource utilization | 협상 중 최대 추가 메모리 | 한 협상의 쟁점 수가 적어 탐색 상태가 작다 | 쟁점 수가 많아 탐색 상태 항목이 크고 상계 계산이 추가된다 |
| Reliability → Fault tolerance | 시간 제한 도달 시 확보되는 결과 | 앞선 단계의 합의는 남는다 | 전체가 미완성으로 끝난다 |
| Maintainability → Modifiability | 처리해야 할 제약 형태의 종류 | 쟁점별 값 필터만 다룬다 | 쟁점 사이 제약과 분기 중단 판단을 구현하고 유지해야 한다 |

### 핵심 긴장

> **"계획 전체의 합의 품질과 총 소요를 얻을 것인가(대안 B), 부분 결과 확보와 구현 단순성을 지킬 것인가(대안 A)"**

### 이 과제에서만 발생하는 이유

단발 협상에서는 이 선택이 존재하지 않는다. 의제가 하나이므로 나눌 대상이 없다. 여러 단계를 한 사람의 하루 계획으로 묶어야 하고, 그 계획이 모바일 단말의 백그라운드에서 수행된다는 두 조건이 동시에 있을 때만 발생한다.

## 후보 DP2 — 단계 합의의 외부 확정 시점

### 문제

협상 결과는 외부 서비스의 예약으로 이어진다. 영화 좌석과 식당 자리는 수량이 한정되어 있고, 협상이 진행되는 동안 다른 사람이 가져갈 수 있다.

협상 안에서의 합의는 되돌릴 수 있으나 외부 예약은 되돌릴 수 없거나 비용이 든다. 이 비대칭 때문에 **단계 합의를 언제 외부 예약으로 연결할 것인가**를 정해야 한다.

늦게 확정하면 되돌리기가 자유로운 대신, 협상이 끝났을 때 예약 대상이 남아 있지 않을 수 있다. 일찍 확정하면 자원을 먼저 확보하는 대신, 후행 단계가 실패해도 되돌릴 수 없다.

### 대안 A — 계획 완성 후 일괄 확정

모든 단계가 합의에 도달하고 사용자 승인을 받은 뒤에만 외부 예약을 실행한다. 그 전까지 모든 단계는 잠정 상태이며, 어느 단계든 비용 없이 되돌릴 수 있다.

되돌리기가 자유로우므로 후행 단계 실패 시 선행 단계 재협상에 제약이 없다. 계획 전체가 확정되기 전에는 외부 세계에 어떤 변화도 만들지 않는다.

### 대안 B — 자원 경합 단계의 조기 확정

단계마다 자원 경합 정도를 속성으로 두고, 경합이 큰 단계는 합의 직후 외부 예약을 실행한다. 나머지 단계는 계획 완성 후에 확정한다.

조기 확정한 단계는 이후 되돌리기 대상에서 제외되며, 후행 단계는 그 결과를 고정 조건으로 받는다. 되돌려야 하는 상황이 발생하면 취소 절차와 그에 따르는 비용을 사용자에게 제시하고 결정을 받는다.

### 갈리는 품질 특성

| 품질특성 → 부특성 | 측정 지표 | 대안 A | 대안 B |
|---|---|---|---|
| Functional suitability → Functional appropriateness | 계획이 실제 예약까지 완료된 비율 | 협상 종료 시점에 예약 대상이 소진되어 실패할 수 있다 | 경합이 큰 자원을 먼저 확보한다 |
| Reliability → Recoverability | 후행 실패 시 복구 가능성 | 모든 단계를 비용 없이 되돌린다 | 조기 확정한 단계는 되돌릴 수 없거나 비용이 든다 |
| Functional suitability → Functional correctness | 계획 전체 기준 합의 품질 | 되돌리기가 자유로워 더 나은 조합을 탐색할 수 있다 | 조기 확정이 이후 탐색 범위를 고정한다 |
| Security → Non-repudiation | 사용자 승인 없이 발생한 외부 거래 건수 | 승인 이후에만 외부 거래가 발생한다 | 승인 이전에 외부 거래가 발생하므로 별도 위임 범위 정의가 필요하다 |

### 핵심 긴장

> **"되돌릴 수 있는 상태를 끝까지 유지할 것인가(대안 A), 사라지는 자원을 먼저 확보할 것인가(대안 B)"**

### 이 과제에서만 발생하는 이유

협상 프레임워크는 합의까지만 다루며 합의 이후의 외부 실행은 범위 밖이다. 본 플랫폼은 협상 결과를 예약과 결제로 직접 연결하므로, 협상 내부의 상태와 외부 세계의 상태가 어긋나는 구간이 생긴다. 단발 협상에서는 합의 즉시 실행하면 되므로 이 구간이 없고, 여러 단계를 순서대로 협상할 때만 발생한다.

## 검토 후 제외한 DP 후보

| DP 후보 | 제외 이유 |
|---|---|
| 제약 힌트의 공개 시점 (즉시 전량 vs 점진) | 힌트는 값이 실제로 변경 불가할 때만 붙는다. 변경 가능한 값에 고정 표시를 붙이는 것은 설계 대안이 아니라 잘못된 선언이다. 따라서 공개 시점은 양보 일정에 따라 결정되며 선택 대상이 아니다 |
| 계획 단계의 출처 (사전 정의 vs 생성형 모델) | 별도 검토에서 제외하기로 결정함 |
| 되돌리기 발동 조건 (만족 불가 시 vs 효용 미달 포함) | 만족 불가 시로 확정됨 |
| 잠정 합의의 양측 상태 일치 방식 | 양측 동의 후 확정으로 확정됨 |
| 후보 열거 방식 (정확한 순서 vs 표본 추출) | 일반적인 탐색 기법 선택에 가깝고 본 과제 고유의 특성이 약하다 |
