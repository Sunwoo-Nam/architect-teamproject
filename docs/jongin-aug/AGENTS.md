# AGENTS.md

## 목적

- 이 프로젝트의 목표는 "S/W Architect 인증" 심사에서 설계 역량을 설득력 있게 증명하는 것이다.

## 기본 원칙

- 문서와 대화 응답은 한글을 기반으로 작성한다.
- 추상적/비유적으로 표현하지 않고, 분명하고 구체적으로 말한다.
- 대화 중 제안 사항에는 항상 항목별로 알파벳-숫자 조합의 ID를 붙인다.
- 문서 내부 항목에는 ID를 부여하지 않으며, 다른 문서나 세부 항목의 ID를 지칭하지 않는다. (ID는 사용자와 대화시에만 사용)
- 한 번에 진행하는 작업 범위는 사람이 읽고 판단할 수 있는 분량으로 제한한다.
- 사용자 피드백 중 반복 적용 필요한 작업 원칙은 간략히 지침화하여 `docs/jongin-aug/AGENTS.md` 반영을 제안한다.

## 파일 관리

- `docs/jongin-aug/참고자료/` 폴더는 아이디어, 현황 정리, 소스자료를 보관하는 참고용 공간이다.
- `docs/jongin-aug/DP/` 안의 파일은 임의로 수정하지 않는다. 수정안을 먼저 제안하고, 확인을 받은 뒤 반영한다.
  `참고자료/`는 이 절차 없이 갱신해도 된다.
- `__cold_storage__/` 폴더는, 사용자의 별도 지시가 없으면 내부를 열람하지 않는다.

## Decision Point(DP) 작성 기준

- DP 문서를 작성하거나 수정할 때는 `docs/jongin-aug/DP/README.md`의 작성 가이드를 따른다.
- DP는 이 프로젝트의 핵심 평가 요소로, 해당 DP가 해결하고자 하는 문제가 중요하면서도 어려워야한다.
- 일반적인 솔루션이 아니라, 이 과제만의 도메인 특성에 의해 발생하는 고유한 내용을 포함하는 솔루션이어야 한다.
- 하나의 DP의 설계안은 2가지로, 모두 실무적으로 선택 가능한 합리적 대안이어야 하며, QA간의 trade-off 때문에 선택이 쉽지 않아야 한다.
- DP 문서는 자기완결적으로 작성한다. 다른 DP를 이름·번호로 참조하지 않는다.
    
## 설계 방법론과 본 프로젝트의 진행 방법

- 설계 방법론은 크게 "ADD(Attribute Driven Development) 3.0"을 따른다.
- 다만 실질적으로는 중요한 후보 DP의 목록을 우선 확보하고, 그중 핵심 DP를 선정한 다음,
  이후에 핵심 DP를 중심으로 나머지 내용의 논리적 정합성을 맞춰가며 진행하도록 한다.
